需求来源：[v0.5 与增量需求](../../PRD_V0.5.md)；执行规则：[安全执行计划](../../GOAL_EXECUTION_PLAN.md)。

## 前置与范围

- 前置：GW-02契约稳定。
- 修改范围：QQ官方平台adapter。源码根为 aika-crossplatform；优先复用现有端口，不为文档目录迁移源码。
- 非目标：本份范围外功能、发布、公网部署、真实账号操作。前置自动契约通过可开发；需要真实安全属性的集成不可由 fake 放行。

## 行为与接口

核实官方支持的账号/会话形态与权限，不假定能读取个人QQ全部私聊；不使用账号逆向协议补齐能力。

所有新增公共字段需在 CONTRACTS 登记版本、兼容 adapter 与消费者；持久化使用临时数据库验证升级与失败回退，不触碰用户库。

## 验证与交付

先读当前生产实现与既有测试，列出定向命令；测试必须走本模块生产实现，fake 只替代外部依赖。记录命令、退出码、逐 AC 证据、影响消费者、未执行的真实/人工项。逻辑测试不证明 UI 可用、真机或真实服务通过。
报告路径：../reports/GW-06_ACCEPTANCE.md。仅所有可自动 AC 通过才能写 AUTO_PASS / 待人工验收；FAIL 不可改为 NOT RUN 来推进依赖。完整验收维持待人工；不自动提交或推送。


## 全文审阅：先验证平台可行性

第一内部步骤只做官方能力表和支持矩阵，明确QQ开放平台应用类型、bot/群/私聊ID与审核条件；若申请条件或私聊能力不满足，整项保留条件阻塞，不擅自用其他账号形态替代“个人QQ私聊”。本地adapter可先实现确定支持的文本scope，必须精确命名该范围；账号审核/凭证申请不自动执行。
