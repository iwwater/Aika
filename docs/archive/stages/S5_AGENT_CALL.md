## 范围与运行契约

- 固定路径：本地 ContextAssembler → 一次流式 Agent 请求 → ReplyEnvelope → 分句播放。情绪、回复、记忆候选同轮输出，不增加意图分类、query rewrite 或情绪判断模型调用。
- S2 Schema 约束在此接入完整运行链；正文先流出，记忆候选等附加字段在完整校验后使用。迟到 emotion 不修改已经播放的音频。
- 使用 S1 turnId/取消语义。记忆候选仅来自成功轮及有来源的用户表达，不能将角色虚构经历当用户事实。
- 替换每轮额外抽取模式：每 8 个成功轮或会话正常结束后启动一次后台合并任务；持久化待处理队列、批次 ID 和进度。退出未完成可下次恢复；相同来源与批次重复执行不产生重复记录。用户关闭抽取后不创建新任务、不继续提交待处理写入。
- 后台摘要与合并可调用模型，但不在当前回复等待链中，单独计数/计费并限并发 1；实时请求优先。
- 普通回合 `toolCalls=[]`。若后续确有工具，必须白名单、参数校验、调用预算与结果来源；需要二次模型调用时记为工具回合，不谎报“一次”。本阶段不新增外部动作工具。
- 不支持流式的 Provider 可在未产生正文时回退一次；已输出正文后断流标记失败，不整轮重放。每次尝试及回退单独记录。

交付 Provider 请求计数、流式适配、候选队列及后台幂等处理；涉及 `useCompanionSession`、`providerClient`、`services/memory/extractor.ts`。
