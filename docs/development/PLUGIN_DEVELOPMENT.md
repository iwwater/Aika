# 合作者模块开发规范

日期：2026-09-21。适用于负责 STT、TTS、情感陪伴等模块的合作者。每个人交付自己的模块及必要接线，不要求负责整个桌宠。参考 DSH 的公开接口、依赖声明和生命周期做法；不要求开发 DSH 市场插件。

## 1. 分工与边界

| 负责人 | 负责 | 不负责 |
| --- | --- | --- |
| 主线维护者 / 主线 AI | 内核、SDK、加载器、来源管理、基础桌宠、LLM 接线、最终组合与回归 | 替各模块复制一套功能实现 |
| STT 合作者 | 音频到 partial/final 文本、流式与批处理 adapter、取消和输入资源释放 | 决定何时提交全局轮次、调用 LLM 或直接写记忆 |
| TTS 合作者 | 文本到音频、音色/来源能力声明、流式与批处理 adapter、取消与音频资源释放 | 生成对话内容、另建轮次状态机或控制其他模块 |
| 情感陪伴合作者 | 情感观察/状态/建议及声明的 Context 或表现输出 | 绕过宿主直接改 Prompt、长期记忆、角色配置或自行触发外部动作 |

STT/TTS/情感陪伴的新功能与引擎开发由对应合作者承担。0.65 主线 AI 仍负责迁移已有 STT/TTS 实现为独立包、公共契约、接线与回归；不能因分工而跳过 K65-05/06，也不提前代做情感陪伴新业务。

## 2. 开始前约定五件事

在任务或模块 README 写清：模块名称与路径、使用的 SDK 版本、输入输出/错误/取消契约、必需与可选依赖、验收命令。先看 [0.65 契约](../next/0.65/CONTRACTS.md)、[多源规范](../next/0.65/PROVIDERS.md) 和自己的 SPEC，不必阅读整个代码库。

情感模块尚无可用接口时，先提交最小接口提案和样例，由主线接入公共 SDK 后再实现接线；不能自行发明宿主 API 并宣称已集成。已稳定的接口不需要每次重复审批。

## 3. 统一开发约定

- 只通过公开 SDK、事件、能力接口通信；不能引用其他包私有路径。接口需要改动时列出直接消费者，同步做最小适配与契约测试。
- 一个功能可有多个云端/本地 adapter；地址、凭据、模型、音色放在来源配置中，不写死。沿用 Capability → Adapter → SourceInstance → ModelProfile → Binding，不另建全局注册中心。
- 声明支持的 streaming/batch/取消等能力；不支持的参数明确报错，不静默切换厂商或把本地数据发送到云端。
- 只有加载并选中模块后才初始化资源；普通桌宠不装 STT/TTS/情感包也能文字聊天。不在 import 时启动进程、下载模型或申请麦克风。
- 输入输出携带宿主要求的会话、轮次和取消信息。切换会话或停用后，晚到文字、音频、情感结果不得污染新轮次。
- 自己创建的连接、订阅、定时器与进程自己登记释放；用户自部署服务只断开连接，不关闭进程。部分初始化失败也必须清理。
- 配置有运行时校验与默认值；日志不包含密钥、私人音频或完整敏感对话。模型、素材和依赖标明来源/许可。

## 4. 合作者交付清单

具体测试范围与主线集成责任见[架构改造测试计划](../next/0.65/TEST_PLAN.md)。模块测试随开发交付，主线负责组合回归；不等用户最终验收才补自动测试。

1. 模块代码与可独立构建/打包的产物；目录和入口符合已交付 SDK，不强装其他可选模块。
2. 简短 README：安装/配置示例、支持来源与版本、输入输出、限制、资源释放、测试命令。
3. 自己模块的测试：正常路径、错误、取消、停用、缺可选依赖；多源 adapter 验证参数/分片/来源隔离。
4. 一条实际生产接入链；外部模型/网络可用 fixture，被测模块和接线本身必须是真实代码。
5. 交接说明：改了哪些公共接口、直接影响谁、测试结果、真实服务验证结果与未完成项。

模块内部改动只测自身及直接消费者；共享契约变化再扩大回归。fixture、真实服务、人工体验分列，未运行写 NOT RUN，缺必要资源写 BLOCKED。模块测试通过不等于全产品验收。主线维护者负责最终组合验证，合作者负责修复由自己改动引起的回归。

多人不要同时改同一个共享契约/锁文件；先约定一个修改者。不要覆盖他人工作树、顺手重构无关模块或提交密钥/模型权重。具体工作区约束见 [AGENTS.md](../../AGENTS.md)。
