# MVP-12 · 双向交互条件规格（未纳入）

依据：[RPD](../../RPD_MVP_0.6.md) MVP-R12、[统一规则](../SPEC_MVP_0.6.md)。这是决策占位，**不可直接派发实施**；AC 全部 NOT RUN。

待用户选择：不纳入 / 点击交互 / 文件输入 / 两者。选择后先补齐事件种类、触发产品行为、授权与数据流、文件限制、失败反馈和确切文件清单，再冻结可执行版本。不预定 WebSocket，不默认点击生成一轮对话或拖入文件即上传。

前置：MVP-08/09；依赖 Live2D hit area 时另需 MVP-11。范围限定 shell 输入适配与 Aiki 明确的接收端口，不将 Agent 搬入 shell。

| AC | 冻结后必须满足的条件 |
| --- | --- |
| A | 仅启用用户选定的输入种类；使用明确的 loopback 反向契约、实例身份验证与作用域，协议版本及消费者可追溯 |
| B | 事件 ID、去重窗口、背压、断连/重连和错误响应明确；不自动重放旧点击或旧文件操作 |
| C | 若选点击：区分点击/拖动/双击，定义 hit area 与触发动作，按选定语义保证不重复派发业务轮 |
| D | 若选文件：只处理明确选入文件；冻结格式/大小/数量、路径验证、接收确认及是否进入模型。失败有反馈，不将文件自动执行或当系统指令 |
| E | 禁用/退出/换实例撤销迟到输入；fixture 与真实 UI 操作分列，关闭该能力不影响四端点输出 |

未选分支在范围冻结时注明不适用及决定依据，不写 PASS 或擅自 DEFERRED。报告仅实施后创建：`docs/integration/reports/MVP-12_ACCEPTANCE.md`。
