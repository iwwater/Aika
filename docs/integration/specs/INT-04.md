## 前置与范围

- 前置：RT-01～04、GW-02/GW-04、AGT-05。
- 修改范围：联调 harness、临时仓库、报告。源码根为 aika-crossplatform；优先复用现有端口，不为文档目录迁移源码。
- 非目标：本份范围外功能、发布、公网部署、真实账号操作。前置自动契约通过可开发；需要真实安全属性的集成不可由 fake 放行。

## 行为与接口

分轨验收fixture链路与真实Telegram/移动端→唯一Runtime→ACP→临时仓库→批准→修改测试→原渠道结果。两个外部Agent分别记录；桌宠回顾不阻塞核心链路但仍NOT RUN。

所有新增公共字段需在 CONTRACTS 登记版本、兼容 adapter 与消费者；持久化使用临时数据库验证升级与失败回退，不触碰用户库。

## 验证与交付

先读当前生产实现与既有测试，列出定向命令；测试必须走本模块生产实现，fake 只替代外部依赖。记录命令、退出码、逐 AC 证据、影响消费者、未执行的真实/人工项。逻辑测试不证明 UI 可用、真机或真实服务通过。
报告路径：../reports/INT-04_ACCEPTANCE.md。仅所有可自动 AC 通过才能写 AUTO_PASS / 待人工验收；FAIL 不可改为 NOT RUN 来推进依赖。完整验收维持待人工；不自动提交或推送。


## 全文审阅：入口和完成矩阵

前置明确为RT-01～04、AGT-05、至少一个已实现渠道分支；最终核心里程碑须覆盖Telegram与Device两个入口、Codex与Claude两个适配器；列出入口×适配器矩阵，至少每个入口和适配器各有一条完整成功链路，不要求额外跑满四种组合；未跑组合如实记录。

fixture链路必须从生产用户命令入口开始，不能测试里直接new manager绕过parser/认证/路由；PC任务视图消费同runId。真实链路先验证拒绝/取消，再批准临时仓库内可控修复，保留diff与测试命令退出码；缺许可只准备harness，整份实际里程碑不写AUTO_PASS。副作用边界以受限宿主及canary证据说明，不仅凭最终git diff断言机器其他位置从未写入。
