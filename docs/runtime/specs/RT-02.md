## 行为与接口

账户键=(platform,botAccount,tenant,sender)，conversation scope 另含 chat/thread；仅可信本地界面发起一次性短期绑定，外部声明 userId 无效。共享角色不等于共享所有聊天内容；同 Runtime 不支持并行会话时显式有界串行排队。

所有新增公共字段需在 CONTRACTS 登记版本、兼容 adapter 与消费者；持久化使用临时数据库验证升级与失败回退，不触碰用户库。

## 全文审阅：隔离必须覆盖存储和运行中状态

生产RuntimeStorage只有全局listMessages/latestSummary且submit新轮取消旧轮。仅在Gateway排队或输出过滤不能防止混用历史。范围明确包含Runtime/Storage/Context最小scope扩展：每轮固定principal+conversation，history/summary/mode按conversation，User Soul/relationship/Memory按授权principal；Trace/任务/缓存亦带scope；去重与排序不能跨tenant混键。

保持一个Runtime实例，内部按conversation保存活动turn/revision；同conversation保留旧“新提交取消旧轮”语义，跨conversation排入有界队列不取消别人的轮次。若使用单worker串行，settled与存储提交完全完成才换scope，不能用全局变量让在途I/O看到新scope。cancel校验turn归属。

旧数据仅映射本地legacy conversation并可回退，不自动共享到群；SQLite迁移和localStorage版本化升级需临时库验证。增加AC-E：真实生产Runtime+两主体scope存储测试，不仅fake router；summary/画像/关系/检索/取消/旧记录及并发均0串线。
