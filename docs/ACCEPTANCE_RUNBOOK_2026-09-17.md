## 三、站 2 · A1 命令下行真实进程复测（10 分钟，**本轮最高优先级**）

**为什么**：这是 0.5 唯一「本地证据只到 HTTP 202」的断点——没有真实进程级证据证明命令真的流到了桌面 Runtime。**不需要手机**，Rust 只绑 loopback，本机浏览器打开的就是同一个"手机页"。

**怎么做**

1. 应用 → 设置 / 远程 → 打开「手机远程」开关（默认端口 **8765**），记下界面显示的地址与 token。
2. 本机浏览器打开 `http://127.0.0.1:8765/`，按页面提示填 token。
3. 发一条可判定的消息：`请只回复四个字：收到命令`。
4. 再**原样重发一次同一条**（同一个 messageId）。

**预期**

- 桌面聊天区出现这条用户消息，并产生回复 → 说明命令真到了 `Runtime.submit`。
- 浏览器页面数秒内收到回帧（长轮询上限 25s）。
- 第二次重发不重复执行（重放去重生效）。

**证据**：浏览器 F12 网络面板（`commands` 响应码 + 回帧 payload）+ 桌面截图。

**若出问题**：只回 202 桌面无反应 → 查 emit / `outbound://command` 监听是否注册；桌面执行了但手机无回帧 → 查 `registerTarget` 会话键。**把现象和截图给我，我来定位。**

## 五、站 4 · 真实语音全链路（20 分钟，本轮最关键的一站）

**为什么**：这是全项目唯一从未被证明过的东西——`STT-03` / `TTS-05` / `INT-02` 三项全是 NOT RUN。**一次真人回合都没跑通过。**

**怎么做**

1. **安静环境识别（STT-03）**：念一组固定短句，建议中文 5 句 + 日文 5 句 + 英文 3 句，长短句各半。每句念完记「我说的」和「她识别成的」。
2. **同轮观察（INT-02）**：随便挑其中一轮，全程盯这五段是否**对齐同一个 turnId**：
   你说 → 识别文本正确 → 回复出现 → 出声 → 字幕逐句高亮 → 桌宠气泡/动作
3. **打断测试**：她正在说话时，你插一句话。看是「抢话」（她的句子被截断/混音）还是「正确等待」。
4. **噪声环境**：开一段视频当背景噪声，再念 3 句，看准确率与断句是否明显恶化。
5. **朗读质量（TTS-05）**：让她读一段固定长文本，听自然度；中途打断一次，确认能停。
6. **可选 · 云 TTS**：设置里切到云端输出链路并填配置。**云 TTS 至今没有一次真实试听，此前证据全部走假 `HttpFetch`**——如果配置不全，界面必须按错误显示降级（`note/degraded` 要一路送到界面），不能静默假装成功。这一步需要当前有效的服务凭证。

**判定**：一次完整真人回合 = 五段全有。**任一段断，这一轮记现象，不要重试掩盖**——丢字、抢话、字幕不同步，这些正是 TODO-01 最需要的输入。

**证据**：识别文本 vs 你实际说的话；延迟手感（粗计秒数即可，不用精确）；打断前后的行为；云 TTS 若降级，截降级提示。

### TOFIX-01 · 手机远程访问「不能用」（现象待补，服务端已排除）

**我实测的服务端侧（全部正常）**：

| 探测 | 结果 |
| --- | --- |
| `127.0.0.1:8765` 监听 | **LISTENING**，Owner = 宿主 PID 36428 |
| `GET http://127.0.0.1:8765/` | **HTTP 200**，返回完整手机页（12,025 B，`Server: tiny-http (Rust)`） |
| 未带 token `POST /api/v1/commands` | `{"error":"token 不对"}`（鉴权生效，非 500、非无响应） |

因此**服务端与鉴权链路均健康**，问题不在 Rust 侧。

**用户复现（本机浏览器，非真机）**：打开 `http://127.0.0.1:8765/` → 页面提示「**这个链接少了 token。在电脑上的设置页重新复制一次手机地址。**」输入框可用，发送即失败。

**根因（已读代码确认，非推测）**：

- `src-tauri/src/remote.rs`：鉴权取 `header_token(request).or_else(|| query_token(&url))`，凭据只认 `Authorization: Bearer <token>` 或 URL `?token=`，**没有来源例外**——loopback 访问与远端一视同仁，一律要 token。
- `src/App.tsx`：设置页只提供「复制地址」按钮（`handleCopyRemoteUrl`），生成的是**带 token 的完整地址**；没有「直接打开手机页」入口，也没有「本机免配」路径。页面提示语本身是准确的。

**判定**：功能未损坏，属**入口体验缺陷**——本机用户（与宿主同机）被当成远端设备对待。用户「本机不该再配一次」的直觉是对的产品直觉。

**修复方向（待选，需立 SPEC）**：

1. 设置页加「打开手机页」按钮，用系统浏览器带 token 直接打开（最小改动、零安全影响）；
2. 对 `127.0.0.1` 来源请求免凭据——**不建议**：本机任意进程都能借此发命令，等于把 loopback 当信任边界；
3. 真机跨设备仍需 `lanEnabled`（见 `ACCEPTANCE_PLAN.md` §八），属未授权新功能。

**站 2 / A1 判定（2026-09-17 用户决定）**：**NOT RUN，本轮不再尝试**。用户已明确放弃本项。A1 维持 `ACCEPTANCE_PLAN.md` 的 NOT RUN 状态——**服务端健康不代表命令真的流到了 `Runtime.submit`**，该断点仍然悬着，不代偿判定。
