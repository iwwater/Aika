# SPEC SER-01 — 语音情感识别（副语言）研究立项

> 状态：研究提案（DRAFT，待用户确认选题方向后细化）
> 日期：2026-09-20
> 关联：`docs/archive/research/AFFECT_RESEARCH_ROADMAP.md`（文本侧情感，互补不冲突）

---

## 0. 一句话定位

**研究「怎么说」里的情绪**：不依赖词语内容，仅从语音的副语言特征（韵律 prosody + 音色 voice quality）判断说话人的情绪状态。

> 用户原话：「我今天很伤心，就是它不通过词语，仅通过语气等方面判断出我的心情。」—— 这正是 Speech Emotion Recognition（SER）领域里最核心、也最难的一支：**纯语音（acoustic-only）副语言情绪识别**。

---

## 1. 背景与动机

### 1.1 语音里有两条信息通道

说话时，语音同时携带两套信息：

| 通道 | 内容 | 学术名 | 用户要研究的 |
|---|---|---|---|
| 说什么 | 词语、语义 | linguistic（语言学） | ✗ 排除 |
| 怎么说 | 音高、能量、语速、音色、停顿 | paralinguistic（副语言） | ✓ 核心 |

用户在 TTS 侧已独立发现「情绪由参考音频（韵律）决定，而非采样参数/词义」——这条**生成侧**的结论，正好是**识别侧**的镜像：如果情绪确实编码在韵律里，那么就应该能从韵律反推情绪。**生成 ↔ 识别对称，是一个完整的研究故事。**

### 1.2 为什么值得做（学术空白）

- SER 是成熟领域，但**日语场景相对缺乏探索**——文献明确：「Japanese SER lacks exploration compared to English, Chinese, and European languages.」
- 现有 benchmark 多是**朗读/表演语料**（字正腔圆、情绪刻意夸张），**真实口语/情绪化语音**（ASMR、日常陪伴语境）研究少。
- 用户手上有**授权 ASMR 情感切片素材 + 7 mood 情绪体系 + GPT-SoVITS 情绪迁移能力**，恰好能填补「真实情绪化日语语音」这个缺口。

### 1.3 与旧路线（文本侧情感）的边界

| | 旧路线（09-05，已归档） | 本 SPEC（新方向） |
|---|---|---|
| 研究对象 | LLM 对话中的情绪状态管理（人格/记忆/事件） | 语音信号中的情绪感知（韵律/音色） |
| 输入 | 文本 + 结构化状态 | 音频波形 |
| 核心问题 | 情绪的事实依据被澄清后能否修正 | 情绪能否仅靠语气判断 |
| 关系 | 理解「说了什么」 | 理解「怎么说」 |

两者互补，最终可融合成多模态情感（语音 + 文本），但**各自是独立、可单独答辩的研究问题**。本 SPEC 只做语音侧。

### 1.5 后端技术栈事实（2026-09-20 查证，决定「接入姿势」）

**主工程后端 = Rust（Tauri 2），是一个「桌面壳」，零模型推理。** 已核 `src-tauri/Cargo.toml` + 11 个 `.rs` 源文件：

- Rust 侧只做：窗口/托盘/通知（tauri 2）、密钥存储（`secret_store.rs`，Windows DPAPI）、本地 SQLite（tauri-plugin-sql）、桌宠进程管理、截图（windows-capture）、手机远程终端（tiny_http 本地 HTTP 服务）。
- **Rust 依赖里没有任何 torch/onnx/tensorflow/whisper/tts 相关 crate**；`src-tauri/src/` 全仓 grep `whisper|tts|emotion|onnx|torch|inference` 仅命中一个无关的测试断言 `PetEndpoint::parse("emotion").is_none()`。
- **所有「智能」都是进程外服务，语言异构是既定架构**：LLM 走 DeepSeek（前端 HTTP 直连），STT 走 whisper-server（C++ 进程，8080），TTS 走 GPT-SoVITS sidecar（Python 进程，9880）。

**对 SER 的结论（这就是「不岔劈」的关键）**：

1. SER 模型属于 Python 生态（openSMILE / HuBERT / emotion2vec / torch），**沿用既有「进程外 Python 服务」模式**：包成一个独立 HTTP 服务（与 whisper-server / TTS sidecar 同款），前端或 Rust 后端经 HTTP 调用即可。
2. **红线：绝不要在 Rust 里重写 SER 模型推理**——Python 生态在 Rust 无等价物，硬搬是大费周章且必翻车的岔劈根源。
3. 语言异构本身不是问题（项目里 C++ whisper + Python TTS 早已并存）；要协调的只是**接口契约**（SER 服务端口 + JSON 返回结构），那是「接入产品」阶段才需要与合作者约定的，研究阶段完全不涉及。

## 2. 研究问题（Research Questions）

**总 RQ**：语音的副语言特征在多大程度上编码说话人情绪？能否实现不依赖词义、跨说话人的日语语音情绪识别？

拆解为四个可验证的子问题：

- **RQ1（可解释性）**：哪些声学特征（F0 音高、能量、语速、jitter/shimmer、频谱斜率等）能可靠区分情绪？—— 回答「为什么能判断」。
- **RQ2（副语言贡献量化）**：纯语音模型 vs 含文本模型，情绪识别准确率差距多大？—— 量化「语气单独能提供多少信息」。
- **RQ3（词义隔离）**：当词义与语气冲突（如「我太开心了」用悲伤语气说），模型跟语气还是跟词义？—— 验证「真的是在听语气」。
- **RQ4（现代方法）**：自监督预训练表征（wav2vec2 / HuBERT / emotion2vec）能否在不显式提取特征的情况下捕获情绪？

**面试可讲点**：这四个问题层层递进，从「能不能」到「为什么」到「怎么验证它没作弊（偷看词义）」，体现完整的研究设计能力。

## 3. 相关研究（文献综述）

### 3.1 方法演进三阶段

1. **传统特征工程**（2000s–2010s）：`openSMILE` 提取标准声学特征集 ——
   - `eGeMAPS`（88 维，精简通用）、`ComParE`（6373 维）、`emo_large`（6552 维）
   - 特征分三类：**prosodic**（F0、能量、语速、停顿）+ **spectral**（MFCC、频谱质心）+ **voice quality**（jitter、shimmer、声门）
   - 分类器：SVM / HMM / MLP
2. **深度学习**（2010s–）：CNN/RNN 直接从频谱图/波形学特征
3. **自监督预训练**（2020s–，当前 SOTA）：`wav2vec 2.0` / `HuBERT` / `WavLM` / `data2vec` / `emotion2vec` 预训练表征 + 下游 SER 分类头

### 3.2 关键基准数据（IEMOCAP，英语）

| 方法 | 准确率（4 情绪，UAR） | 来源 |
|---|---|---|
| HuBERT-base | 78.26% | arXiv:2501.10408 |
| WavLM（attentive pooling） | 75.60% | arXiv:2211.01756 |
| wav2vec 2.0 | ~63–72% | 同上 |
| emotion2vec（情感专训） | 71.79%（WA, linear） | arXiv:2503.22687 |

**emotion2vec** 值得关注：专门用 262h 情感数据预训练，比通用 ASR 预训练（wav2vec2）在 IEMOCAP 上高约 8 个百分点——说明「针对情感任务预训练」有实打实收益。

### 3.3 学术界已确认的「语气 ↔ 情绪」对应关系

系统综述（PLOS ONE 2025）确认的稳定声学相关：

| 情绪/状态 | 声学特征 |
|---|---|
| 愤怒 anger | F0 升高 + 能量增大 + 语速加快 |
| 压力 stress | F0 + 强度升高 + 时长缩短 |
| 认知负荷 | F0 + 强度升高（较模糊） |
| 恐惧/焦虑 | **无一致声学模式**（难点） |

**关键结论**：prosodic（韵律）特征在负性情绪/压力检测中**准确率最高**——这直接支持了用户「仅靠语气判断心情」的可行性，同时也点明「恐惧/焦虑」是硬骨头。

### 3.4 日语数据集：JTES（本 SPEC 的主战场）

- **JTES**（Japanese Twitter-based Emotional Speech corpus）：20,000 段，100 说话人（50 男/50 女），4 情绪（joy/anger/sad/neutral），每情绪 50 句（来自 Twitter，音素+韵律平衡），48kHz→16kHz。
- **人类主观评估基线：75.5%**（4 情绪）——这是「机器要追上人类」的参照线。
- 评估惯例：**speaker-independent**（留出说话人交叉验证），更严的是 **speaker + text-independent**（说话人和句子都不重叠）。

### 3.5 文献引用的诚实边界

上述准确率数字来自不同论文、不同划分协议（LOSO / 5-fold / STI），**不可直接横向比较**；只作方向性参考，复现时统一协议。

## 4. 市场方案调研（业界怎么做）

| 方案 | 定位 | 关键能力 | 对我们的启示 |
|---|---|---|---|
| **Hume AI** | 最相关 | Expression Measurement API：**Prosody API**（实时，亚秒延迟）+ **Tagger API**（离线批处理）；48+ 情绪、600+ voice descriptors、50+ 语言 | 维度情绪理论（Alan Cowen）+ 实时流式 + 大规模；但**闭源黑盒** |
| audEERING | openSMILE 商业版 | 副语言情绪分析 API | 传统特征路线商业化 |
| Nemesysco | 情绪/压力/认知 | Layered Voice Analysis（LVA） | 声纹层析，偏侦查/呼叫中心 |

**关键洞察（面试可讲）**：
- 商业方案走的是**维度情绪模型**（valence/arousal 连续谱，48+ 细粒度情绪），而非离散 6 情绪——因为真实情绪是连续的、混合的。
- 它们普遍**闭源、黑盒、英语/多语通用但不对日语情感专门优化**。
- **我们的差异化**：①日语专攻（商业方案不深挖）②真实情绪化语音（非朗读）③可解释（研究「哪个声学特征对应哪个情绪」，而不是黑盒打分）。

## 5. 技术路线（分阶段，结合已有能力）

### 阶段 0：数据盘点 + 可解释基线（最快出结果）

- 数据：JTES（公开）+ 用户自建 ASMR 情感切片（7 mood，真实情绪化日语）。
- 方法：`openSMILE eGeMAPS` 提取 88 维标准特征 → SVM/MLP 分类。
- 产出：可解释的基线（哪些特征区分哪些情绪）——**这一步和用户已有的 `prosody_metrics.py`（f0_cv / 半音跨度 / 能量动态）一脉相承**，是强项。

### 阶段 1：可解释性研究（RQ1）—— 用户的独特贡献点

- 系统分析每个声学特征的区分度、消融（去掉某类特征看准确率掉多少）。
- 回答「为什么能判断」，产出**特征-情绪对应表**（面试的可视化亮点）。

### 阶段 2：现代方法（RQ4）

- 用 `wav2vec2 / HuBERT / emotion2vec`（Hugging Face 直接可调）做特征提取 + 下游分类头。
- 与阶段 0 的传统特征基线对比，量化「自监督表征 vs 手工特征」的收益。

### 阶段 3：词义隔离实验（RQ2 + RQ3）—— 面试的高光时刻

用 GPT-SoVITS（用户已有能力）生成**同一句台词 × 6 情绪**的对照集，做三个实验：

1. **词义中性句**：「今日は雨だね」用开心/伤心/生气各说一遍，模型能否分对 → 分对=靠语气。
2. **内容-语气冲突**：「すごく嬉しい（我超开心）」用悲伤语气说 → 模型跟语气还是跟词义？
3. **无意义刺激**：哼唱/中性元音（去掉语义、保留韵律）→ 模型还能否判断情绪？

**这一组实验直接证明「模型判断情绪靠的是语气而非词语」，是把 RQ 从「能不能」推进到「凭什么」的关键。**

### 阶段 4（可选）：跨语言泛化（RQ3 延伸）

- 日语训练的模型 → 测试中文情绪语音。若副语言线索通用，应能跨语言泛化；这是「语气是情绪的通用载体」的强证据。

## 6. 数据集与评估

### 数据集（不申请路线，2026-09-20 定）

**核心现实**：日语情绪语音数据全线需申请（JTES/OGVC/Keio-ESD/STUDIES 均无公开直链），用户明确不申请。故改走零申请路线：

| 数据/工具 | 语言 | 情绪 | 获取 | 角色 |
|---|---|---|---|---|
| **emotion2vec+**（预训练模型） | 多语言含日语 | 9 类 | HF 直接下 | 主力：zero-shot + baseline |
| RAVDESS / CREMA-D / TESS | 英语 | 7~8 | HF 直接下 | 训练自己的模型，迁移日语 |
| 自建 ASMR | 日语 | 7 mood | 已有 | 真实日语评测集 + few-shot 微调 |
| demo A/C 组合成 | 日语 | 6 | 已有 | RQ3 词义隔离实验（非训练） |

**合成语音红线（不变）**：GPT-SoVITS 合成情绪**不能当训练数据**（否则学到合成器情绪指纹，对真人分布偏移崩塌），只用于 RQ3 词义隔离 + 落地闭环。

### 评估指标与协议

- **UAR**（unweighted average recall）—— 处理类别不平衡的标准指标。
- **speaker-independent 交叉验证**—— 关键：避免模型「记住说话人」而非「学会情绪」。
- **与人类基线 75.5% 对比**（JTES 人类主观评估）。

### 诚实边界

- 样本量、划分协议必须统一后才能谈「准确率」；n 小时做探索性，不宣称统计显著。

## 8. 与面试叙事的关联（为什么这个方向好投）

1. **与已有工作闭环**：生成侧发现「情绪在韵律里」→ 识别侧验证「能从韵律读出情绪」，生成↔识别对称，是完整故事。
2. **有明确学术空白**：日语 + 真实情绪化语音 + 可解释，三个差异化点。
3. **方法可落地**：openSMILE/HuBERT/emotion2vec 都有现成开源，JTES 公开，起步门槛低、能快速出结果。
4. **科研设计能力**：词义隔离实验、speaker-independent 协议、UAR 指标——体现「严谨实验设计」而非「调包侠」。

## 9. 风险与诚实边界

- **SER 是成熟领域**：不是「没做过」的新题，贡献点必须落在「日语 + 真实情绪化语音 + 可解释 + 词义隔离」的交叉处，而非「做个情绪识别」本身。
- **恐惧/焦虑无稳定声学模式**：负性情绪里最难的子类，诚实标注。
- **数据授权**：自建 ASMR 素材需授权清晰；JTES 需确认使用许可。
- **样本量**：探索阶段不作因果/显著断言。
