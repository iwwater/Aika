## 3b. FIX61-11 token 缺陷：修复、RED→GREEN 证据与 0.61 基线冻结

**缺陷**：`desktop/electron/main.mjs` 的 `open_management` 用 `new URL(value.path, url)` 拼接，而 `url` 是后端发布的 `http://127.0.0.1:<port>/#token=<64hex>`。WHATWG URL 构造器会**整体替换 fragment**，故 `new URL('/#page=skins', 'http://127.0.0.1:51234/#token=ABC').href` → `http://127.0.0.1:51234/#page=skins`，**token 丢失**。后果：功能面板「外观 / 换肤」打开正确页面但处于**未授权锁定态**。

**修复（2 个生产文件，最小改动）**：

| 文件 | before → after |
| --- | --- |
| `tools/management-url.mjs` | 新增导出 `managementTarget(session, route)`：先做**同源校验**（异构 origin 直接抛错，绝不把 token 交给外部主机），再把 session fragment 与 route fragment 合并（`sessionFragment + '&' + routeFragment`），session 在前 |
| `desktop/electron/main.mjs` | `.then(url => shell.openExternal(value.path && value.path !== '/' ? new URL(value.path, url).href : url))` → `.then(url => shell.openExternal(managementTarget(url, value.path)))`；同时 import 增加 `managementTarget`，`value.path` 正则加 `(?!\/)` 拒绝协议相对路由（`//evil.com/x`），路由守卫由 `managementTarget` 的同源检查双保险 |

**fragment 顺序依据**：读 `management/ui/app.mjs:25` 与 `:32-36` 确认——token 取自 `new URLSearchParams(location.hash.slice(1)).get('token')`，`page`/`section` 取自同一 hash 的 `get('page')`/`get('section')`；`URLSearchParams.get` 返回**第一个**同名值，故把 session fragment 放在最前，使路由自带的 `token=…` 无法覆盖真实会话。`/#page=skins` → `#token=<64hex>&page=skins`，两者同时到达。

**覆盖的四种情形**（单元测试断言）：route+token（两者都保留）、token-only（`/` 与 `undefined`/`''` 均返回**逐字节相同**的 session URL）、route-without-token（保留 route，控制台选页后要求授权）、neither（原样）。
