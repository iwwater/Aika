## 4. 真实 native 接入

- **落点**：`desktop/collection/collection-helper.cpp` → `dist/collection/aika-collection-helper.exe`，由 `build:windows` 纳入。契约 §7 的首选落点已验证**可行**：helper 可在当前交互会话内启动并收到 Raw Input，因此**不需要**修订契约为 renderer 键盘监听。
- **键盘来源**：`RegisterRawInputDevices` + `RIDEV_INPUTSINK` + 归属消息窗口，`RAWINPUT.header.dwType == RIM_TYPEKEYBOARD` 才计数。鼠标（`RIM_TYPEMOUSE`）被显式排除，因此鼠标-only 时段不产生 keyboard 证据。
- **消息泵**：helper 主线程阻塞在 stdin，故 Raw Input / 剪贴板窗口由**独立消息泵线程**创建并 `GetMessage` 循环。这是本步发现的关键缺陷（见 §6）。
- **前台应用**：仅取 `QueryFullProcessImageNameA` 的进程映像名；**窗口标题从不读取**。
- **无正文保证**：键码/扫描码/字符在 `onRawKeyInput` 内即被丢弃，只累加 `activityCount`；该函数不接受任何键身份参数。

## 5. 资源释放证据

`stopKeyboard` 会先 flush 当前桶，再 `RIDEV_REMOVE` 注销设备并 `CloseHandle` 定时器，然后清空 grant/revision/前台应用状态。`close()`（协议 `op:'close'`）额外 `RemoveClipboardFormatListener`、`DestroyWindow`、清 staging 并置 `g_running=false` 结束消息泵。客户端 `close()` 等待进程退出（2 s 上限后强杀）并 `clearStaging()`；重复 `close()` 不再产生动作，测试验证了两次调用后 `running===false` 且无残留进程。

锁屏/睡眠/会话切换的真实 hook 由 N081-06 接入 `suspendAll`；本步提供的是被该入口调用的 `stopKeyboard`/`stopClipboard` 与 lease 释放。

## 6. 本步发现并修复的三个真实缺陷

1. **`RegisterRawInputDevices` 失败（`hwndTarget=nullptr`）** → 首轮实机探测返回 `keyboard_unavailable`。`RIDEV_INPUTSINK` 必须指向真实窗口；已改为消息窗口句柄。
2. **注册成功但零事件（无人泵消息）** → 加入按键注入后 `ACTIVITY_BUCKETS=0`。主线程阻塞在 `fgetc(stdin)`，`WM_INPUT` 永不投递；已新增专用消息泵线程。
3. **时间戳偏移 369 年** → 桶时间显示 `2395-09-25T…`。FILETIME 以 1601 起算的 100 ns 为单位，直接格式化未减去 Unix 偏移；已减去 `116444736000000000` 并统一走 `isoFromUnixMillis`。

同时发现测试自身的假通过：`import.meta.dirname` 在 `dist/tests/next081` 下 `../..` 解析到 `dist/` 而非包根，导致产物判空后静默 return。已改为 `../../..`，并把"产物缺失"从静默 `return` 改为带诊断的断言失败，避免 NOT_RUN 被当作 PASS。
