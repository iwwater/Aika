## 4. 边界与稳定性判定

- **realpath 双重校验**：读取元数据**前**与**后**各做一次 `realpath` 并比对结果，两次都必须落在 `grant.directoryRoot` 内（`relative()` 不以 `..` 开头且非绝对路径）。前缀字符串比较被显式排除，因为它无法识别重解析点与 `..` 逃逸。
- **稳定判定**：`policy.fileStableIntervalMs`（normal/smoke 同为 1 s）分隔两次 `stat`；`size` 与 `mtime` 任一变化即拒绝。因此"半写文件被误收为有效样本"在结构上不可能。
- **尺寸上限**：`maxImageBytes = 20 MiB`、`maxImagePixels = 40 MP` 两档相同，配置放宽被 `validateCollectionPolicy` 拒绝。
- **不导入历史**：`start()` 时对目录做一次列举作为基线，只有**该次列举之后**出现的条目（或同名覆盖产生的新版本）才成为候选；`#boundedRescan` 额外用 `mtime >= enabledAt` 排除启用前文件。
- **有界补扫**：`rescanIntervalMs` 为可选；补扫只覆盖同一有效授权期且只针对 `mtime` 晚于启用时刻的文件，因此 watcher 丢事件时不会回补历史，也不会在暂停期间写入。

## 5. 源身份与跨源关联

事件身份 `idempotencyKey = grantId|grantRevision|fileVersion`；`fileVersion = <相对路径>|<size>:<mtime>`。

**本步修正的设计缺陷**：初版 `fileVersion` 只用 `<size>:<mtime>`，导致两个不同文件（相同字节、相同大小、同一毫秒写入）碰撞成同一事件、第二个被误判 `duplicate`。已在测试 `AC-08104-5` 暴露并修复为包含**相对文件身份**。`correlationDigest()`（内容 SHA-256）只供 N081-05 做双通道关联提示，**不参与**事件身份。
