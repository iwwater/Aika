## 4. 表结构与计数算法

- `collection_samples.idempotency_key` 与 `UNIQUE(user_id, character_id, character_instance_id, source_kind, idempotency_key)` 共同构成事件身份。**内容 hash 不参与**。`N081-03～05` 各自提供 key：键盘 = `grantRevision + 桶起点 + policyVersion`；目录 = 文件身份/版本；剪贴板 = sequence。
- `collection_assets.asset_id = sha256(pairing 三字段)[0:16] + '-' + sha256(bytes)`，路径 `<assets>/<pairDigest前2位>/<pairDigest>/<contentHash>.<ext>`。**跨配对绝不复用文件**；同配对相同字节共享文件并靠 `ref_count` 计数。
- 容量：`managedBytes() = SUM(collection_assets.bytes)`，包含副本（含未来缩略图派生）。超限时按 `received_at ASC, id ASC` 逐条驱逐并写 `reason='capacity'` tombstone，直到满足上限。
- `collection_counters` 按配对×来源记录 `accepted/duplicates/rejected/dropped` 与 `last_accepted_at`/`last_error_code`。**零计数不得显示为来源健康**：`sourceStatus()` 在无授权时返回 `state:'disabled'`，`lastAcceptedAt` 为 `null` 而不是伪造时间。

## 5. 崩溃可恢复的一致性

写入顺序固定为：`staging/<uuid>.part`（`flag:'wx'`）→ 校验签名/MIME/像素 → `rename` 到 `<target>.promoting` → `rename` 到最终路径 → 行可见。因此崩溃只会留下 staging 孤儿或 `.promoting` 残片，不会留下指向缺失字节的可见行。`open()` 先清 `staging/` 再校验 `collection_assets.path` 是否存在，缺失则把引用它的活动样本标 `invalidated` 并删资产行。

样本行与资产引用数在同一 SQLite 事务（`.immediate()`）内提交；`appendImage` 在事务抛错时回退引用数并计入 `rejected/write_failed`。
