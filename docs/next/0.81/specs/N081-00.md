# N081-00 · 基线、契约与测试策略

状态：**AUTO_PASS（契约/配置层）**；原生 helper 与实机采集 NOT_RUN。验收报告 [reports/N081-00.md](../reports/N081-00.md)。关联 [RPD](../RPD.md)、[SPEC 索引](../SPEC.md)、[共用契约](../CONTRACTS.md)、[双配置](../TEST_PROFILES.md)。前置：核对 0.65 宿主/0.8 正式进程的实际可复用入口；不等待 0.8 全版验收。

## 目标与修改范围

冻结 Windows 正式启动链、可选能力包/资源释放点、管理鉴权、现有三域 Timeline 和单帧感知边界。形成 `CollectionGrant`、`CollectionSourceRecord`、受管资产、聚合活动、collection 查询投影的**逻辑契约**和迁移/兼容方案，再在工程中落为最小公共类型与直接消费者适配。类型名称为规格称呼，不宣称现有导出已存在。改动候选为 `contracts/`、`core/`、`management/`、`memory/` 及相应测试；先由实际源码核实 owner，不预设新表名或 native 库。

契约须写明：用户/角色/实例配对、来源类型与目录实路径、授权用途/目的地/修订/到期、occurred/received/context 时间、图片来源可信度、稳定 ID、去重与重复事件的区别、TTL/容量、删除 tombstone、投影有效性。Collection 与 0.8 `CaptureGrant`/`Observation` 并存；旧三域查询默认语义不变化，只有显式请求 collection 才返回新域。不能把 keyboard 逐键数据装入公共 Event envelope。

定义可注入 clock、文件/剪贴板/键盘 adapter 边界，以及 [normal/smoke](../TEST_PROFILES.md) 的装载、校验和隔离策略。**在实现性能测试前**登记参考机器、系统/磁盘、基线应用修订，冻结 CPU、私有内存、磁盘增长、队列时延、聊天文字轮次延迟的测量窗口和合格阈值；阈值与测量脚本同报告提交，之后不得为通过而改线。正常与 smoke 的默认值按配置表，不把测量阈值混成采集阈值。

## 接口设计与责任范围

本步负责拟新增 `contracts/collection.ts`：导出 `CollectionSourceKind`、`CollectionPolicy`、`CollectionGrant`、`CollectionSample`、`CollectionQuery/Page` 及运行时校验；复用既有 `PairingScope`，不再定义同名三字段结构。`CollectionPolicy` 带 `schemaVersion=1`、profile、policyVersion 和 [双配置](../TEST_PROFILES.md)各项数值；配置加载器暴露 `loadCollectionPolicy(profile,dataRoot)` 并拒绝未知档、非法值或 smoke 与 normal 共用根。由 N081-01/02/03～06 分别消费，不在契约层执行文件监听、数据库读写或模型推理。

按 [进程契约](../CONTRACTS.md#7-配置与进程边界)验证首选 `trial-backend` 管理受控 Windows helper：冻结 NDJSON `schemaVersion/instanceId/requestId/grantId/grantRevision/kind/op`、聚合输出白名单、图片 staging 一次性引用、最大消息长度与异常关闭。目录 watcher 留后端；helper 只负责 Raw Input 和剪贴板。交付可运行的最小 helper 启停/资源探测原型及构建/清理入口；Windows 构建须包含该可选 helper，缺失时来源报 unavailable 而不破坏基础对话。未能接入当前会话则记 BLOCKED 并调整契约，不用 renderer `keydown` 冒充全局输入。

测试启动接口同时冻结：在 `package.json`/`tools/` 增加 `test:next081` 和 `dev:next081:smoke`（后者拟由 `tools/run-next081-smoke.mjs` 创建独立临时数据根并启动正式产品）。脚本默认不授权任何来源，不从正式 userData 继承 grant；normal 产品入口不接受残留 smoke 数据根。N081-00 可先交脚本骨架/配置校验，自动用例在后续步骤补入；不能把不存在的脚本写成已运行。

兼容改动范围是 `contracts/perception.ts` 的 `EventDomain` 显式扩 `collection`，`core/companion-event-hub.ts` 的验证/订阅域，以及 `memory/unified-timeline.ts` 和管理端对默认三域的兼容约束；实际新域投影由 N081-06 实施。本步给 `collection.sample.created/invalidated` 规定只含 sampleId/sourceKind/grantRevision 的无正文 envelope，`turnId` 可缺省。合同提交前核对 [现有 Event Hub](../../../../windows/code/desktop-pet/core/companion-event-hub.ts)中通用 `publish()` 会生成 `host-user`，不能拿它发 collection 来源。N081-00 不接触原生监听、不创建真实授权，也不宣称 G1～G5 通过。
