# N081-06 · 正式接线、控制台与实机放行

状态：**AUTO_PASS（管理 API + 正式组合根 + 控制台页面）；G1/G2/G3 键盘路径已实机 PASS，G4/G5 其余项 NOT_RUN**。验收报告 [reports/N081-06.md](../reports/N081-06.md)。前置 [N081-01～05](../SPEC.md)；接口基线 [Collection 契约](../CONTRACTS.md)。可先核验已就绪来源，但完整 G5 必须包括 keyboard、目录与剪贴板图片。关联 RPD G1～G5、81-A～F。

## 实施

把 Windows listener、包生命周期、Collection owner 与鉴权管理服务装到真实 `app/trial-backend.ts` 启动链；关闭包或未授权时不注册监听。管理 API 提供来源列表/状态、授权启停/暂停/撤销、按日分页回看、单条/时段/清空删除、来源健康/采集/丢弃/去重/错误/磁盘统计。来源控制需带配对及配置修订，错误不能伪装“已开启”。不让浏览器页面直接监听系统键盘或任意读取用户路径。

Settings/隐私与采集显示三来源独立开关、目录实际目标、本地留存/预算、`normal` 或显式 `smoke` 标记、暂停/停止/删除和失效原因。普通界面可回看最近 keyboard 片段与图片候选、标记有用/无用/错配/漏采；Dashboard 只展示真实聚合状态，详细 Timeline/Companion 放 Developer。若 UI 重构仍在修复，以可操作的最小 Settings 和回看入口达成 G4，不等待其他页面造型；权限控制不能只放 Developer。

为 Collection 加独立显式查询域/投影，保持 canon/companion/work 默认请求结果不变；数据源被撤销或删除后旧投影不可读。Timeline 持续时间从片段来源读取，不伪造对话 `turnId`。Management/IPC 暴露只含聚合数据和受管资产访问，不泄漏任意文件路径或原始键盘通知。

## 接口设计与责任范围

本步新增 `management/collection-routes.ts`，向 `management/server.ts` 装入 `CollectionManagementPort`，在 `management/bootstrap.ts` 和 `app/trial-backend.ts` 正式传入同一 `CollectionServicePort`。路由必须实现 [API v1 表](../CONTRACTS.md#4-管理-api-v1)：status，来源 activate/pause/resume/stop/revoke，样本时间范围分页/资产读取/feedback/无样本漏采标注/单条删除/区间删除/清空。浏览器不得自报 pairing；服务端从当前 runtime 固定作用域，写操作按契约校验 operationId 与各自 revision；漏采标注没有旧样本 revision，只按当前配对与 operationId 幂等。原图 bytes 只由受管资产 ID 的鉴权路由返回。

`memory/unified-timeline.ts` 的新增查询域 `collection` 从 N081-02 owner 读有效片段/图片引用；`GET /api/unified-timeline` 默认仍只有旧三域，显式请求 `domains=collection` 才包含本版数据。`core/companion-event-hub.ts` 只转发无正文 collection envelope，不能使用会合成 `host-user` 的旧通用 publish。Settings/隐私与采集页面消费 status 和写端口，Dashboard 消费轻量统计，Developer 消费 collection 投影；UI 不直接操作 SQLite/native。`smoke` 标记必须来自后端有效 policy，不允许前端自称测试档。范围不含 UI 全量重构、OCR、VLM、主动发言或 Wiki 晋升。
