# N081-07 · 正常配置试运行与版本收口

状态：**工具就绪；试运行 NOT_RUN**（前置 N081-06 G1～G5 未完成，用户尚未在产品中启用来源）。验收报告 [reports/N081-07.md](../reports/N081-07.md)。前置 [N081-06](N081-06.md) G1～G5 全部通过，且用户在产品中实际启用所需来源。接口基线 [Collection 契约](../CONTRACTS.md)。关联 RPD 81-G 和 §8 完成定义。

## 试运行

只用 `normal` 配置开展至少 **3 个使用日、累计 8 小时开启时段** 的自然使用，覆盖一次应用重启与睡眠/唤醒。记录应用修订、Windows/硬件、截图工具、所选目录、来源开关、授权期限、normal 策略版本、预算和 N081-00 预冻性能线。每次状态变化、断档、队列溢出、目录无效、磁盘压力单独计数；不要把未采到的区间填为零活动。smoke 与 fixture 仅作受控测试证据，不计入自然使用时长。

人工标注至少 **20 个图片事件、10 个 keyboard 活动片段**：采到/漏采、重复未合并/误合并、时间/来源错配、认为有用/无用。受控核心场景与自然样本分表；价值比例只帮助决定后续 OCR/VLM/连接器优先级，不用数量硬凑长期记忆。不给图片或 keyboard 活动凭空生成语义。按日输出授权范围、事件数、拒绝原因、总受管字节、CPU/内存/时延、聊天可用性及用户手动删除结果；私人图片正文不放报告。

## 接口使用与范围

本步不新增采集写接口或第二数据 owner。试运行脚本只通过 N081-06 的鉴权 `GET /api/collection/status` 与时间范围分页查询读取计数，已采样本的人工标签走 `POST /api/collection/samples/:id/feedback`，漏采走独立 `POST /api/collection/feedback/missing`，不造一个假样本 ID；成本与健康从 `CollectionStatus` 导出，不能直接扫用户截图目录或解析 SQLite 绕过授权。日报/总结只引用聚合计数、脱敏 sampleId 和来源状态，不附用户图片或键盘正文。任何发现的契约缺口回到负责的 N081-01～06 修复并重验，不在报告脚本里私造兼容接口。

## 版本验收

- 复跑受影响的定向自动回归、`npm run check`、`npm run build`、目标桌面构建；核对 G1～G5 在试运行中仍成立。记录失败和未运行，不以 3 日试运行覆盖测试缺口。
- 执行单条删除、时段删除、清空、来源撤销后重启复查；受管副本/缩略图/投影失效，用户原图保留。验证停包或不安装包时基础文字链仍可用。
- 对照 N081-00 性能阈值和 81-A～G，分别写 PASS/BLOCKED/NOT_RUN、真实设备/fixture、已知漏采范围及修复/延期出口。安全硬门槛任一失败不得放行。
- 报告 `reports/N081-07.md` 结论最多记 AUTO_PASS 或 READY_FOR_ACCEPTANCE；仅用户明确确认实际体验后才记 ACCEPTED。未过的 0.79/0.8 独立门槛保持原状态。
