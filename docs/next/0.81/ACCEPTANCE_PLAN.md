## 0. 先决判据与当前待核对项

Agent 在执行测试前先冻结本次待验源码、native helper、正式运行包、配置档与数据根，记录 Git HEAD、未提交改动摘要、产物哈希、Windows 版本、测试机器、截图工具和策略版本。`check:next081:pin` 只证明配置列出的文件摘要匹配；还须证明运行的正式产物确实包含本次修复。不得为获得绿色结果绕过 `verifyTrialRuntime`、重新指向旧产物，或混用 `smoke` 与 `normal` 数据根。

当前代码预检发现三项必须在 Agent 阶段给出结论：

1. [N081-01](specs/N081-01.md) 与 RPD §4 写明**解锁、重启后需主动恢复**；当前 `trial-backend.ts` 会在重启时自动启动持久 `active` 来源，且忽略启动失败。按现行规格，这项判 **FAIL**，应先使持久状态、实际监听和用户可见操作一致。若产品决定改成自动续采，应先明确修改授权语义与 RPD/SPEC，再验该新规则，不能由测试报告暗中代改。
2. 锁屏事件目前由 native helper 上报；只启用截图目录时，目录 watcher 可以启动而 helper 未必启动。Agent 必须证明**目录单独启用**时仍有可靠的 Windows 会话事件通路；仅测 keyboard 与 clipboard 同时启用不算覆盖 G2。
3. `perf-thresholds.template.json` 的五个绝对阈值仍为 `null`。按 N081-00 要求，在本轮性能判定前确定并记录参考机器和通过线；未冻结则资源项记 **NOT_RUN**，不能因一次测量数值好看而补填通过线。

任一安全硬门槛失败，停止放行；其余缺环境的项目记 `BLOCKED` 或 `NOT_RUN`，不得以自动用例或附件的汇总数字代替真实证据。

| 编号 | Agent 执行内容 | 通过判据与证据 |
| --- | --- | --- |
| A0 基线与构建 | 核对上述规格冲突、pin 覆盖范围和产物来源；运行 `npm run check`、`npm run build`、`npm run build:collection`、目标桌面构建及 `npm run check:next081:pin`。构建后重新确认运行包与源码同版。 | 命令退出码均为 0，pin 可启动，helper manifest/哈希与实际产物一致；无未解释的旧包或未纳入 pin 的关键修复。 |
| A1 定向回归 | 运行 `npm run test:next081`；逐一核对六个原 P1 的直接回归用例。额外覆盖三来源分别处于“仅该来源启用”和“两/三来源并存”的状态矩阵。 | 全套测试退出码 0，无意外 skip/挂起；暂停、停止、撤销某来源时，其他来源状态、租约和后续样本均不变；失败断言后 helper 也退出。通过数随新增测试如实记录，不把旧 `53/53` 写成固定门槛。 |
| A2 生命周期与权限 | 经正式管理 API 验证默认关闭、确认与 revision、过期、暂停→继续、撤销→重新授权、不同目录/配对、迟到回调；用可控系统事件测试锁屏/挂起分发，特别验证目录单独启用。检查重启后真实 lease 与 UI 状态，并注入来源启动失败。 | 无越权、旧代次不写入；锁屏/挂起后所有活跃来源停止且待提交不落库；解锁/重启按现行规格需用户主动恢复；不能出现显示 `active` 却无监听或启动失败被吞掉。真实 Win+L 留到人工阶段再验。 |

## 2. 人工验收：仅在 `READY_FOR_HUMAN` 后开始

Agent 先准备正式产品、隔离 `smoke` 根、空测试目录、几张无私人内容的测试图片、可定位的状态/计数页与脱敏记录表。用户亲自进行实际操作；Agent 旁观记录状态、时间、计数、进程和失败现象。用户无需提供键入正文或私人截图。每个场景同时检查“页面显示什么”和“实际新增了什么”，不能只看 HTTP 200。

| 顺序 | 用户操作 | 人工通过判据 / 对应门槛 |
| --- | --- | --- |
| H1 启动与入口 | 打开正式桌宠和 Settings/隐私与采集，进行一次基础文字对话；查看三个来源、目录、留存期限、预算及最近样本入口。 | 未授权时零采集；文字链可用；普通界面可完成操作，无需 Developer 页。对应 G1、G4。 |
| H2 键盘与独立控制 | 只启用 keyboard，在普通编辑器输入无敏感测试内容，等待活动桶；暂停后继续输入，再手动继续。随后启用目录来源，仅暂停或撤销其中一个。 | 只出现活动区间、计数和可信前台信息，不出现文字/键码；暂停期间不补写；其他来源继续采集。对应 G2、G3、G5。 |
| H3 真实截图通道 | 用至少一种实际截图工具生成**新文件**，再做一次只进入剪贴板的截图，以及一次在关联窗口内同时保存文件和复制剪贴板；复制一张普通图片作对照。 | 新文件与仅剪贴板图都可回看；启用前旧文件不入库；双通道同次捕获仅一张体验卡，普通复制不被强标为截图，用户原文件不变。对应 G3、G5。 |
| H4 锁屏、睡眠与重启 | **先只启用目录来源**，由 Agent 准备延时写入的无害测试图，用户执行 Win+L 并解锁；再在多来源开启时重复，覆盖一次睡眠/唤醒和一次应用退出/重启。 | 锁屏/挂起立即暂停、迟到文件不入库；解锁与重启不自动续采，用户明确继续后才产生新样本；未到期旧样本重启可查。对应 G2、G3、G5。 |
| H5 删除与恢复 | 在 UI 中删除单条、按时段删除、清空；撤销一个来源并尝试重新授权。每次检查卡片/资产，再重启复查。 | 已删样本和资产不可读、不会因重放/重启复活；其他来源证据仍在；原始截图文件保留；重新授权只接收新事件。对应 G3～G5。 |
| H6 体验与成本 | 采集开启时再次文字对话，观察界面是否卡顿、采集状态是否可信；Agent 同时读取已冻结的资源测量。 | 基础交互仍可用，实际成本不超过预设线；异常有可理解的错误状态。对应 G1、G4 与 81-F。 |

H1～H6 任一必需项失败，记录复现条件与 `BLOCKED`，修复后由 Agent 先复验受影响链路，再回到相应人工场景。全部通过后，N081-06 的 G1～G5 才可记录为通过，并允许用户在产品中主动启用 `normal` 配置开始试运行；这时 **0.81 仍未完成**。

## 3. 正常试运行与最终签收

按 [N081-07](specs/N081-07.md) 使用 `normal` 独立数据根，至少 **3 个使用日、累计 8 小时启用时段**，跨应用重启和睡眠/唤醒。每日由 Agent 生成只含聚合计数与脱敏 ID 的报告，分列漏采、重复未合并、误合并、来源/时间错配、拒绝与资源成本；`smoke`/fixture 不计入自然覆盖率。用户至少标注 **20 个图片事件、10 个 keyboard 活动片段**，并实际复核删除、暂停、撤销及聊天可用性。Agent 复跑受影响的自动回归并给出 `READY_FOR_ACCEPTANCE` 或 `BLOCKED`；只有用户确认实际体验后，版本状态才可写 `ACCEPTED`。
