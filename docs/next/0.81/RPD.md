## 1. 目标与插入时机

UI 衔接（2026-09-25）：先执行 [六入口 UI 重构](../ui-rework/RPD.md)。本版日常采集授权、状态、暂停、回看/删除接 Settings/隐私与采集，摘要接 Dashboard，完整 Timeline/Companion 诊断接 Developer；普通数据控制不要求开启 Developer。沿用该专项已授权的自主 UI 设计，不以旧逐页参考审批阻塞；采集本身的 G1～G5 与用户启用授权不变。

在基础功能具备采集前置后，尽早开始积累真实日常样本，优先 **keyboard 活动 + 用户主动截图**。先回答“有没有采到、时间和来源是否可信、能否回看和删掉、运行是否稳定”，再迭代事件理解、主动陪伴与长期知识。

安排为 **0.8 → 0.81 → 0.85 → 0.9**。0.81 是紧接 0.8 的有界增量，不是等待所有感知、Work、高级语音或插件生态完成后的大版本。版本号表示能力阶段，不承诺某个日历发布日期。

- **允许开始独立开发**：0.65 宿主生命周期和 0.8 事件/管理入口的直接依赖可复用，并核对本版新增授权、存储和撤销缺口。
- **允许开始用户实机采集**：第 7 节 G1～G5 的最小闭环有真实证据，且用户在产品中启用该采集范围；不等待 0.8 全版发布、真实 ACP/MCP、云 VLM、本地 OCR、Wiki 编纂或长时观察结论。
- **允许宣布 0.81 完成**：本版必需需求与第 8 节验收满足；开始收集样本不等于版本已验收。旧版本未过门槛继续保留。

选择 0.81 而不是继续扩大 0.8：0.8 已有执行规格，主线覆盖单次感知、邀请、Work 和 UI；后台采集的授权与跨日留存是新增产品语义，需要单独定义。选择 0.81 而不是 0.85 以后：收集本身无需等到长期记忆质量成熟，真实样本反而能帮助后续设计。

## 2. 对原始 IDEA 的消歧

| 讨论中的表述 | 本 RPD 的解释与修正 |
| --- | --- |
| keyboard / 输入法信息 | 首版定义为键盘活动区间、聚合次数和停顿，不记录键码、字符、IME composition 或提交正文。这是基于讨论的首版范围解释，不冒充用户已逐项确认；若实际要文本语义，应另立限定应用的文本来源需求，不由本版暗中开启 |
| AFK 可以代表键盘活动 | AFK 是综合输入闲置，不能冒充 keyboard。键盘来源不可用时显示 unavailable，不能用鼠标移动生成“正在打字” |
| 用户截图一定是好事件 | 截图是较强的主动行为线索，不保证重要性或图中事实属于用户；保存战绩图不能直接推断获胜，保存论文图不能直接断言读完论文 |
| 剪贴板图片就是截图 | 可能是复制网页图片、旧图或第三方内容。保留 image origin 为 unknown/clipboard，只有足够来源证据才标 screenshot；普通图片也可作为已授权候选样本 |
| 截图都保存在默认目录 | 由用户选择实际输出目录；支持文件与剪贴板图片两个独立来源，不承诺覆盖所有截图工具；首版不扫描整盘或历史图片库 |
| 事件发生时的前台窗口就是截图来源 | 区分图片发生时间、文件到达时间与上下文观测时间；延迟写盘、切应用和旧图复制会导致错配，不确定时只保留关联候选 |
| 事件 → OCR → VLM → Memory | 每一步独立按需；没有 OCR 仍可收图和活动。存储样本、理解图片、注入对话、主动说话、长期晋升分别受控 |
| 不保存 Raw Event，但想先攒情报 | 高频原始输入不落盘；有界持久保存聚合活动、去重后的图片副本与来源，作为试运行样本，不建设永久 Raw Event 仓库 |
| Timeline 下挂 Soul / Wiki | Timeline 只是查询投影，Soul/Wiki 属于既有连续性与 Memory 生命周期；不在感知包内重建 Memory |
| 高频 pHash/SSIM 成本很低 | 仍需要获取画面并付出采集成本；首版不常驻截屏做差异检测，避免把“读取已有截图”变成另一个屏幕录制器 |
| 正则过滤能保证剪贴板没有密码 | 不能保证，因此普通文本剪贴板不进入首版；未来文本来源需独立范围与排除策略 |

## 4. 用户流程与数据生命周期

### 4.1 开始一次采集试运行

1. 用户打开采集设置，选择 keyboard 活动、实际截图目录和是否接收剪贴板图片，看到当前角色配对、本地存储范围及留存上限。
2. 开始前预览一条键盘聚合示例和一张测试图片的归类结果；确认后进入“采集中”。这是对所选来源与期限的持续授权，不要求每次键盘活动或截图重复确认。
3. 活动与图片在后台进入本地样本库；桌宠不主动说话、不调用模型；控制台显示来源健康与最近采集时间。
4. 用户在当日列表查看活动片段、缩略图、来源可信度和未解析状态，标记有用/无用/错配/漏采；按需删除。
5. 暂停立即停止新采集并使在途提交失效；恢复必须仍在有效授权范围。停止后既有样本按保留期保存，清空另有明确入口；撤销授权则清理其未晋升的样本及派生投影。

首次启用只接收启用后的新事件，不回填目录旧文件或当时已存在的剪贴板图片。监听中断后的补扫只覆盖同一有效授权的活动时段与指定目录；暂停/撤销期间的数据不得补采。发现断档显示缺口，不虚构完整连续记录。

### 4.2 首版试运行默认值

以下是本 RPD 的建议产品默认值，非已实测结果；正式实施时用参考机器验证。调小预算可保持功能，扩大授权或保留范围必须在设置中明确生效。

| 对象 | 默认策略 |
| --- | --- |
| 原始键盘通知 | 在采集 adapter 内立即聚合；不向 IPC、事件总线、日志或磁盘传输键码/字符/逐键序列 |
| 聚合窗口 | 10 秒活动桶，连续片段合并；键盘静默 5 秒结束一个活跃段，综合无输入 5 分钟标 AFK；均记录策略版本 |
| 上下文 ring buffer | 最多 3 分钟且最多 1,000 条轻量元数据，先触及的上限生效；暂停、锁屏、撤销、配对切换时清空 |
| 图片与采集元数据 | 用户启用试运行即授权本地保留 7 天，总量上限 1 GiB，先到者触发清理；启动时先清理到期内容再开放查询 |
| 图片接入 | 单图最多 20 MiB 且最多 40 MP；解析队列最多 32 项/64 MiB；超限拒绝并计数，不复制到无限重试队列 |
| 去重关联 | 内容摘要定位资产，同一配对/来源授权范围内 5 秒关联文件与剪贴板到达；不同时间的重复使用保留独立事件及 repeated 标记，不重复复制资产 |
| 前台上下文 | 以采集当时上下文为关联线索；有时间差或来源冲突时标 uncertain，不回填确切来源应用 |
| 锁屏 / 睡眠 / 会话切换 | 立即暂停并中止待提交；首版解锁、重启、角色切换后需主动恢复，不自动跨用户或跨角色续采 |
| 处理目的地 | 本地；无模型仍采集；云端请求为零 |

目录中的用户原图保持原位，Aika 只管理其授权复制的样本；删除样本、到期清理不删除用户原图。持久留存采用受管副本，不能以指向用户文件的裸路径假装拥有可靠可回放的来源。副本、缩略图、索引和后续解析派生物均关联同一来源 ID 与过期/撤销状态。

后台样本 TTL 与 0.8 临时 Observation TTL 是不同生命周期：本版新增持久采集来源，不能把 2 分钟临时 Observation 改成 7 天来绕过其契约。未来明确保存的来源按既有受控维护契约处理；若它仍依赖样本，样本删除须传播失效，不能在到期前自动复制为永久记忆。

### 4.3 失败与恢复

- 截图文件需确认写入稳定且解码有效；路径授权按规范化后的实际目标核验，不跟随重解析点越出授权目录。目录搬移/失效显示 source unavailable，不扩大扫描范围。
- 剪贴板占用可有界重试；内容版本已变则放弃旧次读取。不能把下一张图片当成上一条通知的内容。
- 内容摘要去重需结合归一化像素处理容器差异；不同编码或压缩只能标可能重复，不能仅凭 pHash 接近删除不同证据。
- 暂停、角色切换、授权撤销后，在写库和投影提交前再次校验代次；迟到回调不得补写。
- 磁盘不足、解码超限或队列已满时丢弃受影响项并记录无正文原因；键盘活动与其他正常来源可继续，不能拖死聊天/语音。
- 崩溃恢复清理孤立临时文件，恢复已提交记录；事务/幂等机制避免半写或双写。删除标记阻止旧任务及自动补扫恢复已遗忘记录。

### 5.2 责任与数据流

```text
Windows 键盘活动 / 指定目录图片 / 已授权剪贴板图片
  → 可选采集能力包：权限校验、聚合、稳定读取、去重、有界缓冲
  → 本地 Collection 来源存储：受管图片 + 聚合活动 + 有效性/保留期
  → 既有事件通道中的来源引用 → 既有管理 API / Timeline 的 collection 投影
                                  └ 后续显式处理 → 临时 Observation
                                  └ 后续明确保存 → 既有 Memory / 0.85 候选维护
```

Collection 是采集来源权威，不是第二套 Memory；Timeline 只投影，不能独立保存一份不受来源删除控制的正文。活动 Session 只是片段分组，不创建 Dialogue session/turn；没有对话时 turnId 缺省，不伪造一轮助手对话。

包负责平台 adapter 和数据处理；宿主继续负责包/资源生命周期、Scope 和取消；管理端经鉴权接口读写配置/查询，不从浏览器 DOM 监听全局键盘，不直接读任意用户路径。后台事件不启动 `TurnPort`；未来用户明确提问或接受邀请才进入原有轮次。

## 6. 平台可行性核验与限制

- Windows 的 [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo) 只提供调用会话的最近输入时间，可支持闲置判断；不能据此区分键盘与鼠标，更不能得到输入正文。
- Windows [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input) 可按设备类型注册并通过 WM_INPUT 接收，支持相应后台注册。这证明键盘活动来源有实现路径，不证明 Electron 当前已实现。具体 native adapter 后续确定，原始字段必须在 adapter 内丢弃，仅输出聚合结果。
- [AddClipboardFormatListener](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener) 可通知剪贴板变化；它不证明内容是截图或属于当前前台应用。需独立做格式、版本及来源判断。

以上官方资料于 2026-09-25 核验。IME 全局 composition 读取、游戏事件、第三方截图覆盖率均不作为本版已核实能力；首版只支持实际验证的 Windows 用户会话和截图来源。具体原生库、进程部署、数据库表和 API 路径留到后续规格，不在 RPD 中提前承诺。

## 9. 风险与延期出口

| 风险 | 处理/出口 |
| --- | --- |
| keyboard 期望其实是输入正文 | 当前活动定义明确显示；正文需求另行澄清来源/目的/范围，不能用偷偷收字符弥补活动数据语义不足 |
| 新的持久样本绕过旧 Observation 限制 | 建立显式来源留存语义与删除链；0.8 临时观察保持原生命周期 |
| 接入工作拖到插件生态重构 | 复用现有公开包/资源/事件入口，只补直接缺口；不等待 VFS、通用 Hook 或市场 |
| 每张截图都触发理解导致成本高 | 首版零模型调用，后续根据真实样本评估按需 OCR/VLM；记录与发言分离 |
| 无法确认截图来源或发生时间 | 保留 unknown/uncertain 及原始接收时间，不生成“确定经历” |
| 实机权限/原生依赖不可用 | 标记对应来源 BLOCKED，继续已通过来源；核心双源不足不代签整版 |
| 数据越攒越多但没法评估 | 从首版即提供回看、标注、留存与运行计数；不以文件数量替代采集价值 |

执行入口见 [0.81 SPEC](SPEC.md)、[Collection 接口契约](CONTRACTS.md) 与 [双配置](TEST_PROFILES.md)。先冻结直接契约和实机预算，再按 G1～G5 放行真实采集；本次只拆规格，未执行采集。
