# 0.65 架构改造测试计划

日期：2026-09-21；状态：计划已编写，新增测试项未在本次执行。测试证据以各 K65 报告为准；本文补充 [TESTING](TESTING.md) 的实施清单，不另建验收状态体系。

## 1. 要新增测试，但不重写所有旧测试

采用“保留业务回归 + 迁移接线测试 + 新增架构测试”。测试跟随每步改造一起完成，不等全部拆包后再补。0.61 自动通过后继续 0.65，人工体验仍集中到 K65-11。

| 旧测试类型 | 处理方式 |
| --- | --- |
| 文本、语音、取消、记忆、知识库、配置等外部行为 | 保留原输入和行为断言，改接新公开入口；不能为了通过改掉兼容要求 |
| 绑定旧构造器、私有字段、固定目录的测试 | 迁移 setup/fixture 与调用入口，保留真正的行为保障；不维持已废弃内部结构 |
| 重复覆盖同一行为的测试 | 先建立旧用例→新用例映射和通过证据，再合并；不能只因文件失效直接删除 |
| 插件生命周期、独立安装、多源等新行为 | 新增契约、集成与产物测试，旧业务测试不能证明这些能力 |

当前工作树已有 `test:next65`，以及 `baselineBehavior.test.ts`、`baselineSurface.test.ts`、`rendererArtifact.test.mjs` 和 SDK fixture。先复核并扩展，不重复创建 runner，也不把这些文件存在视为整个新架构已通过。K65-00 当前状态由索引/报告管理，本计划不将其重置。

每行绑定已有 SPEC，不新增一条与开发脱节的测试工期。新行为先写可解释的失败用例，再实现；纯迁移复用原特征测试。

| 步骤 | 测试工作 | 关键通过条件 | 负责人 |
| --- | --- | --- | --- |
| K65-00 基线 | 复用基线报告，补齐旧套件→行为→新归属映射 | 原语音/文字/取消/记忆/配置保障可追溯；遗漏与既有故障可见 | 主线 |
| K65-01 SDK/manifest | 合法/非法 manifest、版本不兼容、必需/可选依赖；独立 SDK 消费者编译与运行 | 错误可定位；仅公共 SDK 即可编写插件；私有入口不能作为合法依赖 | 主线 |
| K65-02 加载器 | 真实包发现、依赖解析、按需加载、重复 ID、初始化失败和部分资源清理 | 发现不启动引擎；依赖缺失不破坏其他包；失败无残留 | 主线 |

情感陪伴新业务不增加为 0.65 阻塞项。对应合作者实施时应补：观察输入与输出 schema、会话/角色隔离、状态更新幂等、过期结果丢弃、停用清理、Context/表现建议的公开接线。不以主观“感觉有感情”的断言替代契约测试；情感效果用固定样例与末尾人工评估。已在基线承诺的情感行为按 K65-00 归属保留回归。

## 3. 有限且必要的集成矩阵

| 组合 | 必测行为 |
| --- | --- |
| 只有宿主 | 可发现包、明确缺普通包；不初始化模型/设备 |
| 宿主+普通包 | 文字→LLM→回复；可选包及依赖真正缺席 |
| 普通包+TTS | 文字回复与合成/取消；STT 不在安装中 |
| 普通包+STT | 语音→文字→回复；TTS 不在安装中 |
| 普通包+STT+TTS | 完整语音链、打断、重复/晚到结果隔离 |
| 兼容升级组合 | 0.61 数据升级、原功能回归、撤销和回退 |
| 公开 SDK 第三插件 | 独立构建并导入；不改宿主/普通包产物 hash 即可启用 |

来源维度单独测试，不穷举所有厂商×所有包组合。必须包含云端不依赖本地引擎、本地无云端 Key、两个来源配置隔离、不同阶段绑定不同来源、已输出后故障不换源。真实云/本地 LLM、TTS 和本地 streaming ASR 门槛仍按 TESTING，不因本表简化而删减。

## 4. 测试方式与存放

- 契约/模块测试调用真实实现；用受控 HTTP 服务、音频 fixture、测试 worker 替代外部服务。被测 loader、registry、adapter、IPC 接线不能自己 mock 掉。
- 并发与取消用可控屏障/事件序列复现，覆盖停止发生在初始化、首个结果前、输出中三个时点；避免靠任意 sleep 撞概率。
- 不断言 LLM 的完整随机回复；断言实际目的地、协议结构、完成/取消、无重复和无串线。STT 固定语料及指标按基线，TTS 验证格式/采样率/可解码及非空音频；听感后置。
- 独立产物在临时干净目录启动，只带声明的包与运行依赖，不借用开发树 node_modules。验证真实解析路径及资源计数；不只检查源码未出现某个 import。
- 优先沿用 `tests/next65` 的架构接入测试；功能逻辑测试留在模块已有测试位置。拆包后可迁入包自己的测试目录，由根 runner 汇总；不强制新建重复测试框架。
- 当前 next65 runner 收集目录顶层 `.test.ts` 编译产物与 `.test.mjs`；新建嵌套测试目录时必须同时补显式发现并验证该用例确实运行。缺目录、零用例、必需套件漏收集不能当成功。

## 5. 运行节奏与证据

| 时机 | 执行范围 |
| --- | --- |
| 日常模块修改 | 当前模块、公共契约、直接消费者；优先定向运行，必要共享类型检查 |
| 一个 K65 步骤结束 | 当前新增架构用例、受影响旧回归及本步要求的真实接线/回放 |
| 修改轮次/取消/数据/来源核心 | 扩展到受影响的文字、语音、后台及恢复路径 |
| K65-10 | 显式套件清单、独立产物/组合矩阵、必需真实验证、Windows UI 冒烟 |

当前可用入口包括 `npm run check`、`npm run test:next65`、`npm run test:next61`、`npm run test:next`、`npm run test:windows`、`npm run build:windows` 和 `npm run test:windows:ui`，工作目录为 `windows/code/desktop-pet`。命令存在不表示已经通过，也不表示自动覆盖所有套件；`npm test` 当前仅覆盖默认 memory/providers 组。实施时以实际 package.json、runner 与发现清单核对，不重复跑没有新增风险的已通过检查。

K65-00 基线或后续相应报告维护一份映射即可：`旧用例/行为 → 新入口/用例 → 对应 AC → 定向命令 → 真实或 fixture → 结果/修订`。必需 AC 不得空映射；合并旧用例须指向替代证据。K65-10 汇总遗漏，不按测试数量增长或行覆盖率达标代替行为验收。

测试报告沿用 `reports/K65-xx.md`，新失败补回归后最小修复，不删断言/skip/放宽指标换通过。缺真实资源记 BLOCKED，已有确定性测试结果保留；续跑修复受影响项，不把整版无差别重跑。最终交付自动证据、实际产物和合并人工清单，等用户醒后统一验收。
