## 6. 决策记录

**D1 — SDK 模块范围**：**扩展** `SDK_MODULES`（5 个 `plugins/*.ts` + 4 个 contracts + runtime），**不缩减**冻结的 `PLUGIN_SDK_SURFACE`（**31** 项，`sdk:next65` 实测 `31/31 declared`）。产物树保留 `contracts/` + `plugins/` 布局，唯一的改写是 `./esm-graph.mjs` → `../runtime/esm-graph.mjs`（因为 runtime 单独落到 `runtime/`）。新增 `plugins/esm-graph.d.mts`，宿主不再依赖 ambient `declare module '*.mjs'` hack。

**D2 — `contracts/index.ts` 是否再导出四个新模块**：**决定 —— 不新增再导出，保留直接导入**。理由：(a) 碰撞检查实测唯一重名是 `ValidationResult`，且它同时出现在 `contracts/plugin.ts` 的 interface 与 `validationResult` 的类型位置，属同文件自身，**跨模块零碰撞**（gap 分析结论一致）；但 (b) 四个新模块是**插件作者面**，`contracts/index.ts` 是**宿主运行时面**（`CONTRACT_VERSION`/`TurnScope`/`TurnInput`…），把 31 项插件面（含 `validatePackageManifest`/`buildPackage`/`emitSdkArtifact`）并入宿主 barrel 会让宿主的每个消费者都挂上打包器与发射器；(c) 插件作者的权威入口是 `dist/next65-sdk/index.ts`，它已 `export *` 了全部四个模块，无需宿主 barrel 中转；(d) 因此"不合并"不损失任何可达性，且把冻结面切成两个互不污染的面。先例（`export type * from './self-setup.js'`、`'./emotion-state.js'`）成立但仅用于同面内的类型模块，不构成反例。**若后续审计要求合并，须重跑 `npm run check` 并确认 0。**

**D3 — Flow Profile 范围**：`contracts/flow-profile.ts` 是 K65-00 §4-D1 / §7 点名的 01 必需交付。**01 只冻结 schema v1 + 结构化校验**：`validateFlowProfile` 校验 `schemaVersion`、重复 `nodeId`、capability 节点必带 `capabilityId`、规则操作数为非空声明路径、非 `exists`/`not_exists` 必带比较值、依赖边指向已知节点、自依赖、**环检测**、`joinOrder` 节点存在、`retrySideEffects === false`（副作用阶段禁止自动重试）。**Profile 执行、诊断、Context 组合属 07**（SPEC §3），本步不实现。

**D4 — `knownCapabilityIds`**：**供给则强制、不供给则开放**（开放命名空间，K65-00 D4）。现双向均有测试。

**D5 — D3 `SecretStore`**：真实 adapter `plugins/secret-store.ts`（约 60 行）建于既有 `credentialRegistry()` 之上，**不新建凭据存储**；**故意不放进 `SDK_MODULES`**，使管理侧依赖树不随 SDK 泄漏到产物；`resolve()` 只返回 `{ref, provider}`（无路径、无密钥材料）。

## 10. SlotBinding 冲突裁决（BASELINE.md §8 登记议题，K65-01 契约层冻结）

**议题**：`providers/slot-registry.ts:54` 强制 `credentialRef`、`:87` TTS 强制 `characterMicros > 0`，与 02A「无 Key 本地来源、费用 unknown」冲突。

**裁决：分层共存，schema 层放行，协议层不动。**

1. **0.65 多源 schema 层（新增面）**：`contracts/provider-source.ts` 的 `AuthDeclaration`（`none`/`credentialRef`）+ `CostDeclaration`（`known`/`unknown`/`local_unmetered`，**可选字段**）+ `validateSourceInstance`：本地来源 `auth.kind:'none'` 合法、无费率字段合法（甚至整个 `cost` 缺席也合法）、`cost:{basis:'unknown'}` 是**显式声明的未知状态而非错误**；remote-api 仍强制 `credentialRef` + endpoint（`auth_required_missing`）。云必填字段不套本地引擎。
2. **0.61 旧协议层（不动）**：`matchSlotBinding` 的 `credentialRef` 强制与 TTS `characterMicros > 0` 原样保留——旧层按云优先构造，本地来源不是它的输入；本地旧协议路径的真实放行属 0.61 既有缺陷清单（transport https 硬拒等，RUN §4），不在 K65-01 修。
3. **桥（唯一映射点）**：`plugins/legacy-slot.ts`——capability→slot 映射读自 `management/settings.ts` 权威导出（只读不重建），`legacySlotVocabularyDrift()` 保证 SDK 副本与宿主词表零漂移；无槽对应的新能力（`audio.playback`/`presentation.render`/`background.lifecycle`）显式登记为"无旧槽"，不发明映射。
4. **兼容规则（冻结）**：新包写 0.65 schema（Binding 可声明 `legacySlot` 名，但无第二设置权威）；旧 0.61 七槽配置继续走 slot-registry，两词表仅经 legacy-slot.ts 单向对应；02A 只消费 0.65 schema，不得把本地来源塞进 `matchSlotBinding`。
5. **证据**：`tests/next65/legacySlot.test.ts` 7 例（本地无 Key 无费率过 schema、unknown 费率合法声明、云端仍强制鉴权、旧协议两断言保持拒绝、桥完整性/零漂移/只读性）；`tests/providers/slot-registry.test.ts` 9/9 与 `tests/next61/fix61-01.openConfig.test.ts` 8/8 复跑无回退（旧协议断言未删未松）。
