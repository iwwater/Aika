## 1. 安排位置与目标

建议路线：0.61 可用性与输入基础 → **0.65 插件化与包体化内核** → 0.7 Soul & Continuity → 0.8 感知与主动陪伴 → 0.9 高级语音与表现。

用户希望自定义从输入、感知、记忆、Context、模型调用到输出的完整流程。当前 Provider 可替换，但流程策略仍集中在 DialoguePipeline；0.7 将增加多个 Context 来源，0.8 再增加感知和工作路由，因此建议在这些能力扩张前建立最小编排边界。

0.61 先完成自动收口并固定可复现基线，然后直接实施本版；0.61 人工验收后置到 K65-11，与本版集中进行。不降低两版自动门槛，见[连续计划](../EXECUTION_061_065.md)。0.7 的产品范围保持不变，实施时接入本版实际交付的扩展入口。若近期优先体验角色连续性，也可把本版移至 0.75，但须接受对 0.7 接线再次迁移的成本。用户已在本次讨论确认采用 0.65，先内核化再实施 0.7；0.75 仅保留为取舍说明，不是当前路线。

首要目标是“按需加载的内核 + 能力包”：只安装内核和普通包（桌宠 + LLM + 文字交互）即可使用，TTS、STT、OCR/VLM 陪伴等按需导入。能力包决定安装和加载什么，Flow Profile 决定已启用能力如何组合。未加载包不得启动模型、后台任务或占用设备。

产品结构：

```text
内核：加载 / 依赖 / 生命周期 / 编排
  └─ 普通包：桌宠 + LLM + 文字交互（最小可用）
       ├─ 可选 TTS：文字输入 → 语音回复
       ├─ 可选 STT：语音输入 → 文字回复
       ├─ 可选 STT + TTS：语音双向
       ├─ 可选 OCR / VLM 陪伴（后续版本）
       └─ 可选连续性 / Wiki / 关系等（后续版本）
```

上图表达用户组合，不规定物理目录或要求所有可选包都依赖桌宠渲染器。实际包依赖必须显式声明，内核不能反向依赖业务包。

新安装默认使用最小普通包；从 0.61 升级的用户通过显式兼容组合保留已有功能与数据。能力兼容不等于要求所有新安装用户加载全部功能。

## 4. 用户流程与可定制边界

默认使用：内核 + 普通包 → 配置 LLM → 桌宠文字聊天。扩展：导入所需包 → 校验依赖与资源 → 启用 → 选择流程 → 使用时加载。TTS 和 STT 可以各自单独安装；OCR/VLM 陪伴按后续业务版本提供可选包。

自定义：复制默认 Profile → 修改阶段/绑定/输出策略 → 校验并预览实际执行关系 → 激活 → 从下一轮使用 → 查看阶段结果 → 必要时回退。校验和预览不调用模型、不执行外部动作；实际试运行走正常权限、调用成本和数据语义。

| 示例 | 本版预期 |
| --- | --- |
| 语音输入但只显示文字 | 输入沿用现有语音能力，输出选择文字；不调用 TTS/播放 |
| 增加一个只读 Context 来源 | 注册适配器并声明输入、输出、预算和依赖，通过配置加入组合，无需修改中央流程 |
| 两个独立只读来源并行 | 汇合时按稳定规则合并；可选来源失败显示降级，不按完成先后随机覆盖结果 |
| 调整 Emotion 与检索顺序 | 仅在实际数据依赖允许时接受；依赖回复结果的阶段不能移到回复前 |
| 增加尚未交付的 VLM 或多轮推理 | 明确显示能力不可用；留待对应版本，不静默跳过后声称成功 |

“全流程可定制”覆盖各段的能力选择和受约束编排，不意味着用户可以关闭角色隔离、撤销检查、权限校验或取消保障。

## 5. 职责边界

以下为逻辑职责，不冻结 TypeScript 类型、包目录或文件协议。

| 概念 | 职责 |
| --- | --- |
| Kernel | 包发现与受控加载、依赖校验、作用域/取消、编排及必要诊断；复用现有轮次权威，不依赖具体模型/设备实现 |
| 能力包 | 独立安装与加载单元，声明提供的能力、依赖、版本、资源及生命周期；提供 Stage/Provider/界面或后台入口 |
| 普通包 | 桌宠、LLM、文字交互与必要近期上下文；不依赖可选语音/视觉/长期维护服务 |
| Flow Profile | 描述使用哪些阶段、依赖与分支、Provider 绑定及受支持策略；带版本，不存密钥 |
| Stage | 声明需要什么、产出什么、是否有副作用以及失败方式；不自行创建第二套轮次或数据库 |
| Provider | 完成模型/设备能力；沿用既有配置、凭据引用和协议适配 |
| Context 组合 | 接受来源片段并执行预算、隔离、去重及修订校验；业务内容由对应版本提供 |
| 输入与输出适配 | 管理输入会话、partial/final、音频及播放资源；与轮内流程衔接，不为每个音频 chunk 重跑整轮 |
| 后台维护 | 沿用现有 Memory 生命周期和队列；有独立寿命、来源与撤销检查，不被每轮重复启动 |

能力包与 Flow Profile、Character Pack、模型配置、外观皮肤分别管理；配置导入不等于安装包，安装包不等于启用或采集。切换流程不等于切换角色，不自动重置记忆，也不复制凭据。流程可引用已有配置版本，适配其实际语义。

可称为 Kernel 的部分应从现有 Runtime/Pipeline 渐进提取，不迁入旧 Aika 全套 Plugin Kernel。轮次权威、存储权威与后台任务所有者各保持唯一。

## 6. 执行、切换与失败要求

- 每轮固定 Profile 版本及相关配置快照；普通修改从下一轮生效。在途流程不混合新旧节点。角色切换、遗忘和来源撤销仍即时使相关旧结果失效，不能等到下一轮。
- 实时 ASR 沿用输入会话的 partial/final 规则，final 仅提交一次；已有 transcript 不重复调用批量 STT。输入设备资源、轮内任务和后台维护分别取消/清理，具体规则继承基线。
- 依赖必须显式；只允许无共享写入冲突的只读阶段并行。汇合需定义必需结果、可选结果、预算和稳定顺序，缺失数据不可伪造为空成功。
- 必需阶段失败终止依赖路径并报告；可选阶段仅在明确降级策略下继续。超时与重试有上限；阈值由实施前基线测量及 SPEC 冻结。
- 对写入、播放和外部动作不能默认重试整轮。已交付回复、已写入消息不因后续 TTS 故障重复产生；沿用幂等标识并报告实际完成状态。
- 取消后过滤迟到输出；终态与资源释放维持既有保证。流式扩展不能绕过发送前的撤销检查或播放停止语义。
- 保障项是不可绕过的执行约束；无效 Profile 不替换当前有效配置。Profile 回退不回退用户事实、恢复已遗忘数据或撤销已发生的外部动作。
- 首版注册受信任的内置/本地开发适配器。配置导入不执行代码；外部动作权限与确认沿用产品规则，不由图中的连线授予权限。

| K65-R | LLM 与 TTS 分别完成至少一条云端和本地真实路径，STT 保留既有 batch/streaming 边界；无 Key 本地不强求云端凭据或费率 |
| K65-S | 只选中来源初始化，配置切换固定轮次快照；外部本地服务不被误停，managed 资源释放；本地失败不触发云端请求 |
| K65-T | 新增另一种本地 adapter 可独立打包接入同能力，宿主不新增厂商分支；只用云端不安装本地专用依赖 |

实现时复用特征测试，新行为先 RED 再实现；先定向测试，版本收尾全量相关回归、Windows 构建与自动链路。真实模型回放与 fixture 分列，缺环境记 BLOCKED，未运行记 NOT RUN。实际自动门槛与性能预算在 SPEC 冻结，不在本 RPD 虚构指标。

版本最后由用户集中体验：默认聊天、修改流程、切换回退、失败诊断与语音打断。未确认之前只能记“开发完成，待人工验收”。

## 10. 多源能力补充

LLM/TTS/STT 等功能可有多个云端 API、本地服务或本地引擎选型。统一分为能力、adapter 插件、来源实例、模型/音色配置、阶段绑定；功能包不等于唯一模型来源。普通包与 TTS/STT 可为轻量组合包，专用本地引擎独立安装。每轮按明确绑定使用，不要求全部引擎同时加载，也不自动失败切云。

详细语义与首版真实交付门槛见 [PROVIDERS](PROVIDERS.md)；实施在 02 与 03 之间新增 [K65-02A](specs/K65-02A.md)，其余步骤同步接入与验收。具体已有资源由 00 核对，协议可配置不代表支持任意服务产品。
