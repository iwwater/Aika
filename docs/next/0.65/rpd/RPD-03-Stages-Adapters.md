# 0.65 RPD-03 · 能力接入与 Context 组合

日期：2026-09-21；状态：需求草案，已拆执行 SPEC，开发与测试 NOT RUN。本文受[总 RPD](../RPD.md)范围约束；编号用于需求追踪，不是 worker 执行任务。

## 定位与用户价值

开发者将 Stage/Provider 等适配器封装为独立能力包；用户先导入并启用所需包，再在 Profile 中选择组合。静态注册本身不能替代按需加载。新增合规能力不要求中央调度器增加专属业务分支。

需求归属：K65-R04、K65-R05（能力入口）、K65-R09（既有能力复用）。依赖：RPD-01；与 RPD-02 共同定义可配置能力边界。

## 产品需求

| 编号 | 必须满足的结果 |
| --- | --- |
| SA-01 | Stage 声明需要的数据、产出、依赖、副作用属性和失败方式；不自行拥有第二套轮次或数据库 |
| SA-02 | Provider 复用已有模型槽位、配置及凭据引用；Profile 不复制密钥或另建一份当前模型状态 |
| SA-03 | 输入适配保留实时 ASR 会话、partial/final 和单次提交规则；已有 transcript 不重复批量识别 |
| SA-04 | Context 来源声明预算、隔离、去重和修订要求；组合后仍受整体预算约束 |
| SA-05 | 来源区分稳定前缀与动态后缀，声明失效条件；流程配置不能暗中改写冻结前缀规则 |
| SA-06 | Memory、Timeline、知识库及后台维护复用现有权威与生命周期，不通过新增 Stage 重复启动维护 |
| SA-07 | 输出可选择已有文字或语音能力；清理、撤销校验与播放停止保障不由用户关闭 |
| SA-08 | 未交付或不兼容的能力明确不可用；配置中的节点名称不能冒充实际能力 |

Flow Profile、Character Pack、皮肤与模型配置独立管理。切流程不自动切角色、重置记忆或改变访问权限。注册范围限受信任的内置/本地开发能力包，只有实际加载时才初始化实现；第三方市场及沙箱后置。

## 能力包交付约束

[RPD-06](RPD-06-Capability-Packages.md) 定义安装与加载边界，本文件定义加载后的能力接入。新增 SA-09：具体 Stage/Provider 只在所属包需要加载时初始化，内核与普通包不传递导入可选模块的专用依赖。

0.65 必须将现有 TTS 与 STT 做成可分别导入、启用的包。基本角色设定和近期会话上下文归普通包；长期 Memory、Timeline、知识库及后台维护作为可选兼容能力接入，默认基础路径不要求其服务启动。0.7/0.8/0.9 按包机制继续扩展，OCR/VLM 业务实现仍后置。

## 插件化与包体化主目标

新增 SA-10：建立最小版本化公开插件契约，内置及新增插件通过同一入口发现、注册、使用和释放。独立插件只能使用公开宿主能力与已声明依赖，不依赖宿主私有路径。K65-O 以新插件独立打包导入验证，中央内核和普通包无需修改或重建。

相关入口：[总 RPD 与依赖关系](../RPD.md)。

实施入口：[0.65 SPEC 索引](../SPEC.md)。产品中的待定项按对应步骤冻结，不要求 worker 自行扩大范围。

## 多来源部署补充

需求补充 K65-R16～R19。新增 SA-11：Capability→Adapter→SourceInstance→ModelProfile→Binding 五层分离，同一 adapter 多端点、不同本地引擎 adapter 和同源多模型都合法。来源匹配使用实际能力声明，LLM/TTS/STT 参数分别校验；本地无 Key 不受云端必填项限制。新增 SA-12：多个 adapter 可提供同能力，独立 adapter 包扩展不要求宿主修改厂商分支；K65-Q～T 作为验收。

具体契约：[多源 Provider](../PROVIDERS.md)；实施入口：[K65-02A](../specs/K65-02A.md)。
