# 0.65 RPD-01 · 内核与生命周期

日期：2026-09-21；状态：需求草案，已拆执行 SPEC，开发与测试 NOT RUN。本文受[总 RPD](../RPD.md)范围约束；编号用于需求追踪，不是 worker 执行任务。

## 定位与用户价值

让流程可以改变，同时保持聊天、打断和数据隔离的既有体验。Kernel 从现有 Runtime/Pipeline 渐进提取；继续使用唯一轮次权威，不迁入旧 Aika Kernel。

需求归属：K65-R01、K65-R05、K65-R08。依赖：0.61 实际交付基线。向其他子 RPD 提供不可绕过的生命周期约束。

## 产品需求

| 编号 | 必须满足的结果 |
| --- | --- |
| KL-01 | 最小普通包无需用户配置流程即可文字聊天；升级兼容组合在对应能力包可用时保留已有语音等行为 |
| KL-02 | 输入会话、单轮执行、后台维护和输出资源各有唯一所有者，阶段不能自行再创建一套轮次体系 |
| KL-03 | 每轮固定流程及相关配置版本；普通配置变化下一轮生效，角色切换、遗忘和撤销立即使相关旧结果失效 |
| KL-04 | 取消、超时及失败后，迟到结果不能交付或污染新轮；终态与资源释放沿用既有保证 |
| KL-05 | 必需阶段失败终止依赖路径；可选阶段仅按声明策略降级，不能把缺失结果标成成功 |
| KL-06 | 写入、播放和外部动作不因整轮重跑重复发生；重试有边界并保留实际完成状态 |

升级兼容流程须涵盖基线实际存在的输入处理、路由、记忆操作、Context、回复交付、输出和清理。阶段粒度由后续源码核对决定，不机械地把每个函数拆成节点。

后台 Memory 维护继续使用现有生命周期与队列。前台轮次结束不等于后台任务任意中止，后台也不能绕过来源撤销或写回约束；具体继承行为在实施前核对。

## 关键场景与验收

| 场景 | 预期结果 | 总 AC |
| --- | --- | --- |
| 升级后首次启动 | 默认流程可用，文字、语音、Memory 与 Timeline 行为可回归 | K65-A |
| 回复过程中修改流程 | 本轮版本不变，下一轮采用新版本 | K65-F |
| 取消后模型返回 | 迟到结果被丢弃，不发送、不写入新轮 | K65-F |
| 回复已交付但 TTS 失败 | 报告输出失败，不重新生成或重复存储回复 | K65-G |
| 遗忘与后台写回交错 | 撤销后的来源不能被重新写回 | K65-F、K65-I |

## 边界与待定

不新增分布式 Runtime、第二套存储或通用后台调度平台。生命周期接口、超时上限、重试分类和兼容切换方式留到 SPEC；本稿不指定类名或代码路径。

## 能力包生命周期约束

按 [RPD-06](RPD-06-Capability-Packages.md) 管理包加载与资源释放。Kernel 不直接依赖具体桌宠、LLM、音频或视觉实现；长期 Memory 生命周期只在相应包启用并被使用时存在，普通文字路径不要求启动它。

停用包须阻止新调用，处理在途轮次和依赖者，再释放资源；撤销设备权限立即停止采集。首版可明确要求重启完成代码卸载，不要求运行中热替换，但不能把仍驻留状态报告为已卸载。

## 插件化与包体化主目标

内核宿主不得直接导入业务插件实现；内置插件和导入插件使用同一生命周期。无普通包时可启动宿主管理能力，但不声称提供聊天产品。插件是业务扩展单元，资源和轮次权威仍由宿主统一约束。

相关入口：[总 RPD 与依赖关系](../RPD.md)。

实施入口：[0.65 SPEC 索引](../SPEC.md)。产品中的待定项按对应步骤冻结，不要求 worker 自行扩大范围。

## 多来源部署补充

来源实例生命周期由共享 Provider 管理层维护，业务包不各建全局当前模型。外部 local-service 只关闭本应用连接；managed-local 的进程/模型按租约回收。宿主可加载 adapter 代码而不初始化该 adapter 的所有实例。多来源修订在轮内固定，新增 K65-S 验收。

具体契约：[多源 Provider](../PROVIDERS.md)；实施入口：[K65-02A](../specs/K65-02A.md)。
