# 0.65 RPD-06 · 能力包与按需加载

日期：2026-09-21；状态：需求草案，已拆执行 SPEC，开发与测试 NOT RUN。本文受[总 RPD](../RPD.md)约束，落实用户“内核 + 普通包，其他功能按需导入”的目标。

## 1. 产品形态

用户可只安装内核与普通包，获得桌宠和 LLM 文字交互。其他能力可以完全不存在于安装目录和运行进程中，不能仅用禁用按钮模拟模块化。

需求归属：K65-R10～R15；共同涉及 R01、R04、R05、R06、R08、R09。包生命周期依赖 RPD-01 的轮次与资源保证；包能力供 RPD-02/03 使用，管理体验见 RPD-04，整版验收见 RPD-05。

| 层/包 | 必须承担 | 不应强制携带 |
| --- | --- | --- |
| 内核 | 包发现与受控加载、依赖/兼容校验、生命周期、作用域/取消、编排与必要诊断基础 | 桌宠渲染器、具体 LLM 实现、音频/视觉模型与设备后台、长期记忆业务 |
| 普通包（基础包） | 桌宠展示、文字输入与回复、至少一条已支持 LLM Provider 路径、必要设置及近期会话上下文 | TTS、STT、OCR、VLM、长期 Wiki/关系引擎 |
| TTS 包 | 已支持的语音合成与播放，资源生命周期及输出接入 | STT、麦克风输入、视觉能力 |
| STT 包 | 已支持的语音识别与输入接入，麦克风资源生命周期 | TTS、OCR/VLM |
| OCR / VLM 陪伴包 | 后续版本的视觉能力、必要采集入口与陪伴策略，依赖显式声明 | 不相关语音包；VLM 不默认必须依赖 OCR |
| 连续性等其他包 | 按后续需求提供长期记忆、Wiki、Soul、关系、工作能力等 | 不得成为普通文字交互的隐式必装项 |

“普通包”可以是一个产品安装单元或声明依赖的组合包；内部物理拆分留到 SPEC。复用现有桌宠最低可用表现，不把新的高级 Live2D 移植提前到 0.65。近期会话和基本角色设定可由普通包持有，不要求加载长期沉淀服务。

## 2. 插件化与包体化的交付边界

- 插件是运行时扩展单元，遵守版本化公开契约，声明能力并受宿主生命周期管理。包是可安装交付单元，携带插件代码、必要资产、元数据及依赖声明。一个包可包含多个相关插件，但不能以组合包为由强制夹带无关可选功能。
- 普通包是用户选择的基础产品组合：桌宠 + LLM + 文字交互。它与可选包同样通过插件契约接入，不能在宿主中保留一套专供内置功能使用的私有接线。
- 内核只保留宿主机制：加载、兼容校验、生命周期、作用域、权限边界、编排与基础诊断。模型调用、桌宠表现、设备采集、长期维护属于插件业务。内核可以运行并列出包而没有普通包，但此时不提供完整聊天产品。
- 交付应能分别识别内核、普通包、TTS、STT 的产物及依赖；不要求拆成多个 Git 仓库、npm 发布或在线商店。独立产物可在同一仓库构建。
- 插件通过公开能力/事件边界协作，不直接引用另一包的内部文件或宿主私有对象。具体 API 和格式在 SPEC 冻结，版本不兼容须拒绝加载并说明原因。

新增 CP-11：内置插件与一个新增测试插件走同一发现/注册/调用/释放路径，新增插件不需修改内核分支。

新增 CP-12：支持单个兼容插件包独立打包和更新；普通包与内核无需重新构建。更新不兼容时保留最后可用版本与配置。代码热替换仍后置，允许明确重启。

## 3. 首版必须交付

| 编号 | 产品要求 |
| --- | --- |
| CP-01 | 有独立可交付的最小安装形态：内核 + 普通包；机器上没有任何可选包/其专用运行依赖时仍可启动并完成文字聊天 |
| CP-02 | TTS 与 STT 是可分别导入的能力包；新增这些已支持能力无需重建或重新安装整个应用 |
| CP-03 | 包声明稳定身份、版本、内核兼容范围、必需/可选依赖、提供能力、运行资源/模型要求和权限需求；具体 manifest 格式后定 |
| CP-04 | 区分未安装、已安装未启用、已启用待加载、已加载、不可用/失败及停用待生效；安装不等于初始化或授权采集 |
| CP-05 | 仅加载已启用且当前入口/流程需要的包及必要依赖；未加载包不执行初始化、不启动后台/模型进程、不占设备或发起网络调用 |
| CP-06 | 缺依赖、不兼容、重复身份冲突或损坏包在启用前提示；失败不破坏普通包和最后有效配置，不静默联网下载依赖 |
| CP-07 | 支持停止使用、释放资源和卸载；受在途轮次、活动设备和其他包依赖约束，不能让卸载留下可执行的陈旧回调 |
| CP-08 | 包启用/停用与 Profile 激活协调；引用未启用/缺失能力的流程不能成为可运行活动流程，提供修复或显式切回基础流程的入口 |
| CP-09 | 卸载能力默认保留其用户数据，明确提示保留内容；清除数据是独立操作，重新安装仍遵守撤销与遗忘状态 |
| CP-10 | 记录包及版本的加载/失败/释放结果，能验证未加载能力确实未运行；包版本与每轮使用的配置可关联 |

内核不硬依赖可选包实现。普通包及其必要依赖不能传递导入音频/视觉包来满足启动；也不能用全套依赖预装、启动时立即加载全部包的方式通过最小安装验收。共享轻量基础设施可复用，但可选模型、原生依赖和工作进程不得强制随基础安装提供。

包所需资源与能力代码分别表达：用户可以显式选择配置服务、导入模型或安装所需依赖；安装状态不能冒充就绪。未就绪能力不阻止基础文字聊天。首版支持受信任的本地能力包导入，不要求插件市场、任意第三方代码沙箱或运行中热替换代码。

## 4. 加载与停用体验

默认：安装内核 + 普通包 → 配置 LLM → 桌宠文字聊天。

扩展：导入能力包 → 查看兼容性/依赖/资源与权限 → 启用并选择相应流程 → 在该入口使用时加载。常驻陪伴能力只有在用户明确启用相应功能后才启动后台；安装、发现包或预览流程不会自动开始屏幕/麦克风采集。

停用：展示受影响流程与依赖者 → 停止新调用 → 等待相关轮次结束或显式取消并释放资源 → 停用/卸载 → 使用有效流程。首版可以要求重启完成代码卸载或版本更新，但必须显示“待重启”，重启后确认没有自动加载；不能把重启前仍驻留的模块标为“已释放”。无需修改源码或重装全应用。

撤销采集权限或点击停止须立即停止相应采集与交付，不受“下一轮生效”或“等待重启”的延迟规则影响。包版本在一轮内固定，更新不得混用实现；共享资源在最后使用者退出后释放。

## 5. 版本范围

0.65 交付包机制、最小普通包、现有 TTS/STT 能力拆包及独立组合验证。既有 Memory/Timeline/知识库等保留兼容接入，可形成可选兼容包；具体包合并边界后定，但必须能在完全不加载长期维护能力的情况下运行普通包。

0.7 的连续性、0.8 的 OCR/VLM 陪伴及后续高级表现按同一包机制交付；其业务功能不提前到 0.65。框架允许这些能力独立扩展，不把示例包或接口视作功能已实现。

## 6. 组合与就绪状态

| 用户选择 | 可获得的体验 | 不能成为隐式依赖 |
| --- | --- | --- |
| 内核 + 普通包 | 桌宠、文字问答、近期上下文 | 麦克风、声卡播放、音频模型、屏幕采集、长期记忆引擎 |
| 普通包 + TTS（均运行于内核） | 文字提问，显示并朗读回复 | STT 和麦克风 |
| 普通包 + STT | 语音提问，文字回复 | TTS 与播放引擎 |
| 普通包 + STT + TTS | 语音提问与语音回复，文字展示保留 | OCR/VLM |
| 普通包 + OCR/VLM 陪伴 | 后续可加入视觉上下文，依赖实际包声明 | 不默认要求 TTS/STT；OCR 与 VLM 不相互强制绑定 |

最小普通包仍需用户配置有效 LLM 服务或模型，不声称无需任何模型即可聊天。缺 LLM 配置时桌宠与设置可启动，明确引导配置；可选包缺模型、依赖或权限只使该能力未就绪。

包可声明功能依赖而非捆绑重复资源；例如两个视觉包共享采集能力时，由明确所有者统一管理资源，不能各自后台偷偷采集。具体依赖解析与冲突规则由 SPEC 冻结。包声明读取阶段为元数据读取，不执行可选实现入口；发现已安装包不会触发模型初始化。

## 7. 验收

| 总 AC | 可观察结果 |
| --- | --- |
| K65-J | 干净环境只有内核 + 普通包，无可选包代码/专用依赖，桌宠文字聊天可用；无音频/视觉初始化、工作进程、采集请求或长期维护任务 |
| K65-K | 分别验证基础、基础+TTS、基础+STT、基础+TTS+STT：文字、文字输入语音回复、语音输入文字回复、语音双向均符合所选组合；不依赖未选包 |
| K65-L | 安装但未启用、启用但未触发、实际触发三个状态可区分；前两者不初始化可选实现，触发仅加载所需依赖；后台功能按显式启用策略启动 |
| K65-M | 缺依赖/不兼容/损坏包无法启用；加载失败保持基础可用；依赖者存在或在途调用时的停用有明确结果，停止后无迟到交付和残留采集 |
| K65-N | 无需重建整应用即可导入/更新/移除能力包；需要重启时准确提示；重新安装保留数据且不恢复已撤销事实 |
| K65-O | 公开契约接入的新插件可独立打包导入，不修改/重建内核及普通包，完成注册、配置、调用、释放 |
| K65-P | 内核、普通包、TTS、STT 有独立产物和依赖清单；单独兼容更新 TTS，其他产物不变，不夹带 STT |

以上均 NOT RUN。真实模型与设备验证、依赖隔离证据和量化资源预算在 SPEC 按环境冻结，不能只靠隐藏菜单、mock 包加载器或空 Provider 宣称按需加载通过。

## 8. 延后决定

包目录/归档格式、manifest、入口 API、模块/进程隔离方式、依赖解析和共享资源引用机制在实施前确定。首版允许明确的重启边界；市场、自动升级分发、代码签名体系和通用不可信代码沙箱后置。按需加载及最小安装本身是本版必需目标，不得以后置这些高级能力为理由取消。

实施入口：[0.65 SPEC 索引](../SPEC.md)。产品中的待定项按对应步骤冻结，不要求 worker 自行扩大范围。

## 多来源部署补充

新增 CP-13：功能包可由公共接线包与所选 adapter 包组成。TTS 不强制携带所有本地合成引擎，普通包不强制携带所有本地 LLM 环境。一个 adapter 包可配置多个来源实例，无需复制代码包；多个 adapter 通过公开契约提供同能力，实例身份与包身份分离。新增 K65-T 验证第二种本地 adapter 独立接入，K65-R 验证实际云/本地路径。

具体契约：[多源 Provider](../PROVIDERS.md)；实施入口：[K65-02A](../specs/K65-02A.md)。
