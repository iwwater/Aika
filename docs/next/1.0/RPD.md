# Aika Next 1.0 RPD · 稳定交付与长期维护

版本：0.1；日期：2026-09-22；状态：产品需求草案已补齐，尚未拆执行 SPEC 或发布。目标是可安装、可升级、可恢复、可诊断的 Windows 产品；不以补齐所有远期功能作为 1.0 定义。

## 1. 目标与用户路径

新用户下载选定 Windows 产物 → 完成基础配置 → 成功文字聊天 → 按需添加语音/连续性等包。已有用户升级前看到变更、兼容性和备份 → 升级成功或恢复旧版 → 原有设置和授权边界保持可解释。

用户可导出允许导出的个人数据、查看来源、清除数据、定位失败原因。卸载程序默认保留用户数据，清除必须是独立明确操作。没有云服务凭据时可配置已有本地来源，不静默借用内置 Key。

## 2. 工程基线与进入条件

已有包 manifest/import、PackageLifecycleManager、release-next65 和 release-doctor，以及多个 SQLite/JSON 存储。它们是起点；文件 hash 清单不等于签名信任，代码回滚不等于数据恢复，单包测试不等于全应用安装成功。

开始 1.0 实施时冻结实际发布候选提交、工作树状态、SDK/API、数据库 schema、包/模型/运行库版本和构建环境。不沿用 package.json 当前版本号直接判断产品版本；建立产品版本、SDK 版本、各包版本和数据模式的显式映射。

0.65 的 32 项人工验收及后续新增项在发布前逐项给 PASS/FAIL/BLOCKED 或用户明确接受的范围排除。相关 P1 故障须闭环；不能通过改写状态、删测试或把真实必测项移到人工清单规避自动门槛。独立模块可提前稳定化，不要求开发期间等待全部人工项目。

## 4. 安装、启动与包分发

### 4.1 产物和首次运行

实施 SPEC 在现有 Windows 构建能力基础上固定一种主要发布形态（安装器或便携包），记录架构和最低系统/运行库要求。是否附带 Node/Electron/native 运行库由产物决定；不能让终端用户借用开发树 node_modules 或现场编译整仓库。

基础包必须可以完成配置、文字输入、回复和错误恢复。功能包列明大小、依赖、权限、资源及兼容版本；模型权重默认不混入程序包。来源/许可核实后才能分发相应模型或素材，开发机器上可加载不等于允许再分发。

首次启动展示缺失资源和配置检查，不在扫描期间启动全部引擎。慢启动显示进度和取消/重试；凭据缺失不伪报服务已连接。离线情况下仍能打开配置、诊断和使用已配置的本地能力。

### 4.2 更新和完整性

更新按检查、下载/导入暂存、校验、影响预览、备份、重启切换、启动验证分阶段处理。当前在途轮次固定旧版本，暂存不影响正在运行的注册表。依赖不兼容拒绝切换并解释影响；不自动升级其他用户包到任意版本。

hash 检测内容变更，来源可信性另由已选分发渠道和发布验证机制保证。签名/发布渠道在执行 SPEC 明确；未具备签名时如实标明，不宣传可信签名分发。不执行任意包 install 脚本。

程序退出、磁盘满、文件占用、校验失败或启动验证失败后恢复最后有效代码/配置；若数据模式已变化，必须恢复对应数据快照。包卸载保留数据，显式清除时列出影响范围。

## 5. 数据迁移、备份与恢复

备份清单至少覆盖聊天/Memory、知识库、Character Pack/来源、User Soul/Wiki/关系、撤销代次/墓碑、活动实例、Provider 引用和包配置；不同存储不能独立恢复成互相不匹配的修订。秘密值的备份和导出有单独策略，不作为普通可读配置导出。

| 场景 | 必须保证 |
| --- | --- |
| 旧版本升级 | 明确源/目标 schema；先验证备份可读，再迁移；重复运行不重复创建数据 |
| 迁移中断 | 通过事务/阶段日志恢复到可解释状态；不留下新旧 schema 混用 |
| 回退 | 代码与对应数据一起恢复；旧程序不直接打开不兼容新库 |
| 多库备份 | 协调写入或一致快照，记录所有相关修订和校验；处理 SQLite WAL |
| 恢复旧备份 | 合并仍有效的撤销记录；备份不能成为恢复已遗忘内容的旁路 |
| 用户完整清除 | 明确涉及正文、索引、缓存及本地备份；不能承诺删除用户另存或第三方持有副本 |

导出默认包括用户可见条目和必要来源引用，区分用户数据、第三方原文与不能导出的资产。恢复先预检模式/完整性/空间，失败不覆盖现有数据；提供恢复摘要而不在普通日志写私人正文。

迁移矩阵至少覆盖实际可支持的 0.6/0.61 数据到当前 Next 数据、0.65 包配置到发布配置、0.7 连续性数据升级，以及发布版内上一兼容版本回退。若历史格式没有真实 fixture，标待补证据，不伪造兼容范围。

## 6. 诊断与维护

日志默认记录错误类别、模块、关联 ID、配置修订、耗时和资源状态。导出诊断包先脱敏并显示内容范围；不得包含 Key、会话 token、私人录音、完整 Prompt/资料正文或未经授权的屏幕图像。

健康状态区分未安装、未配置、待加载、已加载、已验证和失败；有凭据不等于真实调用成功。允许针对单个来源执行用户触发的探针并明确可能的网络/费用，不在每次打开设置时自动推理。

完整 wire Trace、本地模型一键安装器和只配 Key 的极简入口仍遵守现有 TODO 排期；1.0 必需的是足够诊断与首次配置，不借稳定化把全部候选优化升级为门槛。

维护交付包含包/API 兼容表、依赖与许可清单、已知限制、备份恢复说明、问题复现模板和数据清除说明。长期支持期限、升级渠道、性能上限及参考设备在首个执行 SPEC 冻结，不能没有测量就宣称长期稳定或给出保证期限。

## 7. 验收矩阵

| AC | 必需证据 |
| --- | --- |
| 10-A | 固定提交与锁文件、构建工具版本、完整文件/依赖/许可清单；两次清洁构建比较可解释差异；无密钥/私人数据 |
| 10-B | 开发树不可访问的干净 Windows 环境安装/启动/配置/文字回复；非 ASCII 路径、离线和无可选包 |
| 10-C | 更新暂存不影响当前轮；依赖冲突拒绝；校验/重启失败恢复；包停用立即停止设备 |
| 10-D | 各承诺源 schema 真实 fixture、幂等迁移、断电/磁盘满故障注入及备份恢复校验 |
| 10-E | 代码与数据配套回退；关系/来源/知识库 ID 和撤销状态不丢失；并发写入备份一致 |
| 10-F | 导出范围正确；遗忘传播到派生项/索引/缓存；旧备份/旧包不复活撤销事实；清除操作范围明确 |
| 10-G | 启动、离线、认证、设备错误均可恢复；诊断包脱敏；不假绿、不静默云端 fallback |
| 10-H | 参考机器长时运行、多轮取消、换肤/切源/停用压力及资源曲线；时长和阈值实施前固定 |
| 10-I | 相关自动门槛全部完成；32 项旧人工及各版新增项有结论；安装/升级/恢复真实操作；用户明确验收发布候选 |

自动、真实服务、设备、人工证据分别登记。旧用例失效须记录等价覆盖和理由，不删除断言换通过。不同平台和模型组合采用明确支持矩阵，不承诺所有厂商笛卡尔积。

## 8. 执行和发布

建议拆分：发布基线/支持矩阵 → 清洁产物/安装 → 联合迁移/恢复 → 更新事务 → 隐私/诊断 → 稳定性/兼容回归 → 集中人工 → 发布交接。

开发完成、人工验收完成、公开发布是三个状态。发布包、推送、签名和上传渠道各依实际授权执行，本 PRD 不自动触发外部发布。仍有必需阻塞时交付候选和缺口清单，不能将版本号改成 1.0 就宣布验收完成。
