## 已验证的正式运行子链（2026-09-24）

- 在隔离的正式 `trial-backend` 进程测试中预置一条已展示的持久化语音邀请；桌面桥命令 `click_invitation` 经过 `BackendSession` 消费该记录，并由唯一 `DesktopRuntime` 创建语音 `TurnScope`、发出 `capture_start`。发送 `cancel` 后桥接发出 `capture_stop`。

- 桌面“稍后再说”发送 `ignore_invitation`：只有仍为 `shown` 且来源有效的邀请可被忽略；持久化状态为 `ignored`，同一来源当天被抑制；不会创建对话 TurnScope 或开启采集，并以 `companion.invitation.dismissed` 独立活动投影到 Timeline。
- Electron 页面已加入“稍后再说”控件，并把邀请卡加入 click-through 的交互区域枚举；`npm run build:desktop` 通过。由于本机 Electron renderer 启动仍受 GPU 子进程错误阻断，本轮没有验证真实窗口中的鼠标命中、排版或点击体验。

- 点击状态重启后仍为 `clicked`；接受和忽略活动均在后续正式 backend 进程中可查询，忽略状态也持久化；另有未处理邀请从持久化状态恢复。固定 fixture 证明的是“预置候选的恢复/接受/忽略→轮次授权或不创建轮次→审计投影”，没有证明生产候选生成、首次展示仲裁或真实录音。

## 仲裁模块安全复核（2026-09-24）

- 候选必须带 observation、continuity_fact 或 schedule 的来源 ID 与正整数版本，且时间窗有效；缺失来源或时间窗无效时拒绝注册。
- 来源有效性回调缺失、返回无效或抛错时，仲裁失败关闭；来源被撤销、过期或在展示后失效，均不能接受。
- 只有已展示且仍有效的候选可接受/忽略；重复注册不重置状态，终态候选不能二次接受；相同来源类型、ID、版本的日内重放会失效清理。
- 审计事件使用真实来源 ID/版本，而不是邀请自身 ID。
- 本节早期记录的模块测试结论仍有效；候选生产、首次仲裁及偏好授权现由本报告开头的 2026-09-25 收口记录补充，并由正式管理进程集成与 UI policy 测试覆盖。Observation/Schedule 与 Electron 实机展示仍未接通/验收。
