## 一、 缺陷修复与环境加固总结

### 1. Chromium 本机测试环境缓存权限隔离
- **根因分析**：
  在 Windows 运行环境中，Electron 在未指定 `userData` 路径时，默认共享 `%APPDATA%\desktop-pet` 或 `%APPDATA%\Electron`。由于多进程并发执行或此前权限限制，Chromium 的 `net\disk_cache` 与 `gpu_disk_cache` 在初始化与重命名移动缓存目录时触发 Windows `0x5 (拒绝访问)` 错误：
  ```
  [ERROR:net\disk_cache\cache_util_win.cc:25] Unable to move the cache: 拒绝访问。 (0x5)
  [ERROR:net\disk_cache\disk_cache.cc:290] Unable to create cache
  [ERROR:gpu\ipc\host\gpu_disk_cache.cc:737] Gpu Cache Creation failed: -2
  ```
- **修复方案**：
  对所有 Electron 测试场景执行严格的独立环境沙箱化加固：
  1. 使用 `mkdtempSync(join(tmpdir(), 'electron-...-'))` 为每个测试进程创建绝对独立的临时 `userData` 目录，通过 `app.setPath('userData', tempUserData)` 绑定；
  2. 显式追加 `--disable-http-cache` 与 `--disable-gpu-shader-disk-cache` 开关，避免测试过程产生磁盘网络/着色器脏缓存；
  3. 在 `finally` 和顶层 `catch` 中执行 `rmSync(tempUserData, { recursive: true, force: true })` 保证进程退出后零残留；
  4. 覆盖文件：
     - `tests/management/trace-content-electron.mjs`
     - `tests/management/strict-forget-electron.mjs`
     - `tests/next079/click-through-region-electron.mjs`
     - `tests/next079/local-greeting-preview-electron.mjs`
     - `tests/management/presentation-preview-electron.mjs`
     - `tests/management/emotion-ui-electron.mjs`
     - `tests/management/console-audit-electron.mjs`
     - `tests/next61/fix61-02.ui-electron.mjs`
     - `tests/next61/fix61-03.ui-electron.mjs`
     - `tests/next61/fix61-11.deeplink.ui-electron.mjs`
     - `tests/next61/fix61-11.ui-electron.mjs`
     - `tools/verify-memory-forget-electron.mjs`
     - `tools/verify-trace-electron.mjs`

### 2. `strict-forget-integration.test.ts` 错误断言与句柄释放修复
- **根因分析**：
  `P0 RV-02` 测试用例中断言 `assert.equal(body.error, 'unavailable')`，而管理端 HTTP 服务器对 `ManagementError` 的统一响应格式为 `{ error: { code: 'unavailable', message: '...' } }`，直接断言字符串抛出 `AssertionError`。由于用例内部先注册了 `fixture(t)` 清理钩子，且未在 `try ... finally` 中释放 `forget`、`server`、`store` 句柄，导致测试失败时直接触发 `rm(tempProjectRoot)`，因 SQLite 句柄与 HTTP 监听端口仍未关闭而在 Windows 下发生 `EBUSY`（Node 内部 10 秒重试后退出并挂起）。
- **修复方案**：
  1. 将断言修正为支持对象结构：
     ```typescript
     const errorCode = typeof body.error === 'object' && body.error ? body.error.code : body.error;
     assert.equal(errorCode, 'unavailable');
     ```
  2. 移除与 `fixture(t)` 注册时序相冲突的个别 `t.after`，使用标准的 `try { ... } finally { await forget.drain(); forget.close(); await server.close(); store.close(); }` 保证异常发生时绝对优先安全释放文件与端口句柄。
