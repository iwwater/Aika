## 1. 目标与用户流程

本版主线是“授权观察 → 可追溯事件 → 本轮理解或受控长期沉淀 → 适时邀请 → 气泡/展开聊天反馈”。OCR 是其中一个输入。用户能知道桌宠看到了什么、为什么开口、记住了什么，并能停止和遗忘。控制台负责管理与追溯，桌宠负责轻量交流；显式 Work 请求继续按原计划接入。屏幕观察、陪伴建议和工作执行具有不同授权范围，不相互隐式升级。

四条最小路径：

1. 选择窗口/区域 → 查看采集预览与处理目的地 → 单次读取 → OCR/视觉理解 → 对当前画面提问 → 清除观察。
2. 开启主动陪伴 → 设置时间段、来源和配额 → 符合条件时出现邀请 → 接受进入正常轮次，忽略则冷却。
3. 明确工作请求 → 显示目标项目、执行器与工作卡 → 按动作权限确认 → 发送一次 → 跟踪回执 → 展示结果或未知状态。
4. 气泡读到回复或邀请 → 按需展开聊天并继续同一轮上下文 → 在控制台查看对应事件、来源和沉淀状态 → 纠正/遗忘后所有派生视图同步失效。

仅安装基础包时继续文字聊天；不安装感知、主动陪伴或工作包不影响基础功能。没有 0.7 连续性时仍可做本轮画面问答；涉及长期偏好的主动邀请明确显示缺少连续性依赖。

## 4. 屏幕感知

### 4.1 采集和授权

默认关闭。第一次采集明确窗口/区域、单次或会话时长、OCR/VLM 来源及本地/云端目的地。授权引用绑定采集目标、用途和修订；改为另一窗口或从本地切云端时重新核对范围。持续观察只在用户主动开启后发生，显示持续可见状态和停止入口。

锁屏、目标关闭、授权撤销或包停用时停止新采集并取消在途处理。目标失效不改抓整个桌面。结果回传前再次检查授权修订；已发送的云端请求无法承诺远端撤回，应如实显示已发送与本地停止的区别。

原图默认仅用于当前观察，处理结束或到期释放。保存为长期来源需要单独明确操作；日志默认仅存标识、耗时、尺寸、结果状态。敏感区域屏蔽是辅助措施，不承诺自动识别全部秘密。

### 4.2 OCR 和视觉理解

OCR 和 VLM 分别声明能力；可只安装其中之一。不强制每次同时调用，不启动未选择引擎。OCR 保留区域坐标、阅读顺序、语言及引擎置信字段；VLM 保留 observation/source 引用和 unknown/partial/failed 状态。模型输出中的操作指令不构成工具授权。

支持多显示器、缩放和移动窗口坐标验证。重复图像可复用短期缓存，缓存键必须包含目标、画面 hash、授权代次和 Provider 修订。超限图片明确缩放/拒绝，不悄悄改变采集范围。

## 5. 主动陪伴

复用 InvitationStore 的配额、最小间隔、时区与来源失效；新增情境策略作为可选包，不另建全局轮次。建议初始沿用现有每天 2 次、间隔 3 小时的上限，用户可降低或关闭；持续观察采样频率是另一项配置，不能以邀请配额代替采集限流。

触发来源限于已授权当前观察或有效连续性条目。记录候选理由、来源及过期时间；同事件重放不增加邀请。免打扰、用户正在输入/录音/工作确认、达到配额或来源失效时不打断。

策略入口统一评估本地时间、授权事件、有效关系上下文和用户忙闲状态，输出 silent 或 invitation 及原因码。规则筛选先于可选模型润色；模型调用须显式启用并受预算限制，不为每次轮询调用 LLM。0.79 时钟模板路径继续零 LLM。静默、拒绝与过期同样可解释，诊断不记录私人正文。

当前 InvitationStore 的 eventId 外键指向 memory_records，并不直接接受临时 Observation。实施时扩展可验证的来源引用及兼容迁移，沿用既有配额/投递权威；不得为满足外键把每次截图伪装成长期记忆。现有 start_voice 邀请语义须保留；新增普通文本邀请独立标识动作，接受它不会自动开麦。

默认先给短文本邀请，接受后进入正常轮次；不得自动打开麦克风、截图更多窗口或调用工作工具。忽略/拒绝应降低同类打扰，设置页可暂停和清空候选。窗口标题和单次画面不能直接升级为稳定用户画像。

## 6. Work/ACP/MCP 接入

保留现有 DesktopWork/HarnessForwarding 的草稿与确认回执。ACP 承担外部 agent 会话/任务适配；MCP 承担已配置工具/资源的能力适配，二者不能统一假设为相同任务状态机。协议版本、传输和支持子集在实施 SPEC 中查官方文档冻结；本 RPD 不承诺最新协议全覆盖。

首版范围：一个 ACP adapter、一条 MCP 工具接入路径，加保留已有窄 relay 的兼容测试。实际目标和传输待 SPEC 按用户现有环境选择。工具发现只读元数据，不执行任务、不启动非必要服务。

工作卡应展示目标项目/目录、执行器、实际任务、数据目的地和副作用。只读任务与写入/发送/删除分开授权；用户对明确动作已有授权时不重复询问。内容或目标修订使旧确认失效；请求使用 operationId 幂等提交。

发送超时必须区分明确失败与“可能已执行、回执未知”；未知不能自动重发有副作用的动作。取消本地等待不等于远端任务取消，需报告远端确认结果。工具输出按不可信数据处理，不改变权限、角色或系统设置。任务记录归工作域，不能自动沉淀为用户亲身经历。

### 7.1 事件传递与时间线

复用 `contracts/plugin.ts` 的 HostEventChannel 和 `core/turn-port.ts` 的轮次订阅，先核实宿主真实投递路径。现有 EventScope 只有 packageId/turnId/sessionId，不能独自证明用户×角色实例隔离；扩展事件须携带并校验 pairing 与来源修订。新增陪伴事件 schema、生产者适配和投影消费者，不预设需要替换内核或另建通用 Event Bus。事件通道负责传递，时间线负责查询投影，原业务存储继续拥有状态权威。

首批来源为真实对话结果、授权 OCR/VLM Observation、邀请及用户响应、已有情绪/关系变更、Work 回执。未接线来源显示未启用；App/Activity 仅来自已授权窗口元数据或应用自身交互，不默默增加系统级监控。

Canon 继续只呈现作品事实；Companion 呈现用户与角色的真实交互；Observation 标记短期且默认不跨重启保留正文；Work 以引用卡呈现，不改写为用户亲身经历。情绪推断必须标明推断与证据，不能当作用户自述或直接改变关系事实。时间线是跨域查询入口，不合并各域删除权限。

投影以 eventId 和来源修订去重，区分发生时间与接收时间；重复/乱序/重启不能重复沉淀或重复邀请。临时观察到期后卡片不可恢复正文，持久元数据遵守保留策略。明确保存的条目走 0.7 维护与来源链；遗忘须覆盖派生事实、邀请、Context/cache 和界面投影，重建投影不得复活被撤销内容。投递错误可重试投影，不能重放外部副作用。

## 8. 界面与失败恢复

提供感知设置和采集预览、当前观察清单、主动陪伴策略、工作卡/运行记录四类入口。错误给出原因及本地可操作恢复：重新选窗口、重授权限、改已配置来源、重试只读处理或查询未知回执。不得用“绿色已连接”表示尚未验证的模型能力。

性能门槛在首个 SPEC 固定参考机器/图片集/采样上限/超时/预算，未达标如实报告。只读 OCR/VLM 可有有界重试；持久化、通知和外部动作不盲重试。实时采集撤销和取消属于必需行为，不等待 1.0 再补。

### 8.1 桌宠聊天：气泡与展开视图

已有气泡和 drawer，在其上逐个重写交互。默认轻量回复不强制展开；长回复可由用户打开完整内容，气泡淡出不能删除历史。展开、收起或换显示模式不创建新 session、不重复提交、不触发额外 TTS。保留文字输入、语音入口、取消、错误恢复、Work 卡与原话定位；是否新增轻量输入条由用户参考图确认。

聊天视图消费同一 Conversation 状态投影，通过现有轮次入口发命令；气泡、展开列表和 Presentation 消费同一带 Scope 的结果。Live2D 不承担会话历史、模型请求或 Memory 写入。沿用 ExpressionIntent/PetPresentation 与动作白名单，不把模型给出的任意 motion 名直接交给渲染器。

展示优先级为当前用户轮次及其错误 > 待确认工作/邀请 > 闲时问候；前台忙时不叠加抢占。取消、断线、角色切换和超时以实际轮次终态为准，旧 generation 的迟到回复不能覆盖新界面。输入法组合键不误发、键盘焦点可恢复、穿透区域与可交互区域分别验证。

当前 DesktopChatLog 仅保留每角色最近 50 条会话内显示行；完整历史必须通过实际后端历史能力分页读取并验证权限，不能把临时日志称为持久历史。当前 TurnPort 没有 delta 事件，本版默认按真实 reply 展示；若用户要求逐字流式，先另列契约及直接消费者改造，不能用假打字证明流式已接通。

### 8.2 控制台与聊天入口

保留现有 routes.mjs 中页面与旧深链映射。按用户任务分层：总览展示真实可用状态与最近交互；感知展示授权、目的地、观察与暂停；记忆/Timeline/Soul/Wiki/知识库展示来源、不同数据域及纠正/遗忘；项目与任务展示 Work；健康与 events 承担 Trace、Token 和技术错误。导航名称、排版、侧栏位置与样式留白，不以本表替代参考图。

总览数据必须来自真实接口：未检测显示未检测，统计注明配对/范围；不得写死在线状态、Memory 数量或关系百分比。知识库是用户外部资料，不能与用户事实列表混为一个“记忆”集合。

控制台的“聊天”首版定义为会话历史查看、来源定位和跳转关联 Trace；当前路由没有独立 chat 页面，不宣称已存在第二个聊天客户端。若参考确认要在控制台直接发送消息，必须接入同一会话/轮次权威，补跨窗口冲突、重复提交、断线恢复与取消契约后再实施，不另建直连 Provider 的对话链。

逐界面顺序：①桌宠气泡 ②展开聊天/输入 ③控制台会话查看 ④Timeline 与资料详情 ⑤感知授权/预览 ⑥主动策略 ⑦总览与诊断分层 ⑧Work 卡。每项先问“XX 前端要改成什么样” → 等回答 → 索取参考图 → 确认本项范围 → 实施 → 展示结果并主动请用户逐项对照审核 → 修改至明确通过，再进入下一项。已有参考只能在用户明确同意复用后使用；右键菜单保留减负，不重做桌宠模型表现。
