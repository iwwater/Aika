## 1. 目标与负责边界

落实 [0.8 RPD](../RPD.md) §5 及验收矩阵 08-E、08-F，构建桌宠主动陪伴邀请与免打扰仲裁引擎：
1. **统一仲裁器（`ProactiveArbitrator`）**：
   - 统一管理配额（默认每日最多 2 次）、冷却最小间隔（默认 3 小时）、时区日历与免打扰时段（DND）；
   - 前台忙闲状态检测：当用户正在打字输入、语音录入、处于对话思考/播报中或等待工作卡确认时，**绝不打扰**；
   - 假时钟可测试性：全流程注入受控时钟函数，支持毫秒级时区与冷却推演。
2. **多源有效性与撤销联动**：
   - 候选邀请必须绑定明确来源（`sourceRef`：`observation`、`continuity_fact` 或 `schedule`）；当前生产接线仅实现 `continuity_fact`，且只消费用户明确晋升、仍为 active 并满足证据门槛的事实/里程碑；
   - 来源事实或感知画面一旦撤销/遗忘，关联候选邀请立即失效（`expired`），杜绝过期幽灵问候；
   - 相同事件触发幂等去重：同一事件或画面在本地自然日内不重复生成/展示邀请。
3. **动作与权限严格分离**：
   - 呈现形式仅为轻量桌面气泡提示（不主动开麦，不抢夺输入焦点）；
   - `actionKind === 'text'`：点击仅展开聊天抽屉承接文本，绝不自动开启麦克风录音；
   - `actionKind === 'voice_start'`：仅当用户**明确主动点击气泡**时，才派发开启麦克风录音指令；
   - `actionKind === 'clarify'`：引导至待确认的工作任务卡。
4. **多角色与租户隔离**：
   - 候选队列和策略按 `PairingScope` 隔离；展示配额/冷却沿用 `InvitationStore` 的本地全角色共享上限，角色切换仍屏蔽其他配对的待定邀请。
5. **事件总线审计追溯**：
   - 邀请呈现（presented）、接受（accepted）、忽略/关闭（dismissed）、过期（expired）均向 `CompanionEventHub` 广播 `CompanionEventEnvelope` 审计事件。

## 2. 接口与契约定义

```typescript
export interface ProactivePolicy {
  readonly enabled: boolean;
  readonly dailyMax: number;
  readonly minIntervalMs: number;
  readonly timezone: string;
  readonly dndStartHour?: number; // e.g. 23 (23:00)
  readonly dndEndHour?: number;   // e.g. 7 (07:00)
}

export interface UserBusyState {
  readonly isTyping?: boolean;
  readonly isSpeaking?: boolean;
  readonly isTurnActive?: boolean; // thinking or speaking
  readonly isWorkPendingConfirmation?: boolean;
}

export interface ArbitrationDecision {
  readonly canPresent: boolean;
  readonly reasonCode: 'ok' | 'disabled' | 'user_busy' | 'dnd_active' | 'daily_quota_exceeded' | 'cooldown_active' | 'source_revoked' | 'no_candidates';
  readonly candidate?: InvitationCandidate;
}

export class ProactiveCompanionService {
  constructor(
    eventHub: CompanionEventHub,
    policy: ProactivePolicy,
    clock?: () => string,
    isSourceValid: (sourceRef: InvitationCandidate['sourceRef']) => boolean,
  );

  registerCandidate(candidate: InvitationCandidate): void;
  evaluateArbitration(pairing: PairingScope, busyState: UserBusyState): ArbitrationDecision;
  presentNext(pairing: PairingScope, busyState: UserBusyState): InvitationCandidate | null;
  accept(invitationId: string, pairing: PairingScope): { action: InvitationActionKind; text: string } | null;
  dismiss(invitationId: string, pairing: PairingScope): boolean;
  revokeBySource(sourceId: string): number;
}
```

## 3. 验收条件 (AC)

- **AC-0804-1（假时钟配额、间隔与时区守卫）**：在假时钟驱动下，同一天展示达上限后被拒绝；间隔未满 `minIntervalMs` 被拒绝；跨越时区午夜后配额自动刷新；
- **AC-0804-2（免打扰与忙闲状态拦截）**：在 DND 时段内，或用户正在输入、录音、处于对话轮次中时，仲裁器返回拒绝并标明原因码，绝不弹窗打扰；
- **AC-0804-3（来源事实撤销即时失效）**：当关联的 Observation 或事实被撤销时，在途候选邀请立即转为 `expired`，不再展示；
- **AC-0804-4（动作与权限隔离）**：展示邀请绝不自动开麦；接受 `text` 邀请返回纯文本动作且开麦标志为 false；仅接受 `voice_start` 邀请且经显式用户交互才触发录音；
- **AC-0804-5（重复事件重放幂等去重）**：相同来源事件重复注册或重放时，不增加新的展示次数；
- **AC-0804-6（租户与角色切换隔离）**：切换到角色 B 时，角色 A 的候选邀请被过滤，配额与投递记录按角色/租户独立隔离。
- **AC-0804-7（正式连续性来源链）**：正式 `trial-backend` 默认关闭主动策略；启用时保存连续性 revision checkpoint、不回填旧事实；普通对话只能创建带来源的待审核候选，不能自动晋升事实；只有后续显式晋升且证据有效的 active fact/milestone 才可在延迟后生成通用文本邀请。候选、策略跨进程持久化；重复同步幂等；接受/忽略校验 source ID/version、展示状态和 TTL；邀请点击进入正常文本 `TurnScope`、不采集麦克风；遗忘来源后查询隐藏相关活动。
- **AC-0804-8（气泡与共享投递限制）**：renderer 的可见邀请 8 秒后自动收起并提交 ignore；邀请过期时间更早时按较早时间失效。角色间候选/策略分隔，但每日投递上限和冷却按既有全局本地策略共享。
