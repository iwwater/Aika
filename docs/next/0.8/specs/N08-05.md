## 1. 目标与负责边界

落实 [0.8 RPD](../RPD.md) §6 及验收矩阵 08-G、08-H，建立外部工程协作通道：
1. **工作任务确认与幂等派发引擎（`WorkDispatchManager`）**：
   - 严格基于 `operationId` 执行幂等提交与去重：重复确认或重放仅派发一次，杜绝外部副作用重复执行；
   - 目标与内容修订失效：在任务确认前，若目标项目、路径或指令内容发生修订，原草稿请求自动失效；
   - 超时与未知状态安全防护：外部响应超时或网络中断时，状态明确标记为 `uncertain`（未知），绝不盲目自动重发可能具有写副作用的请求；
   - 任务取消与回执追踪：支持取消在途任务并向远端适配器传播取消信号。
2. **ACP 协议适配器（`AcpProtocolAdapter`）**：
   - 冻结 ACP v1（`protocolVersion: 1`）与 stdio JSON-RPC 传输；遵循 `initialize`、`session/new`、`session/prompt`、`session/update`、`session/cancel` 生命周期；
   - 严格进行协议版本协商，遇到不支持版本时抛出受控的 `unsupported_protocol_version` 异常；
   - 默认不向 Agent 暴露客户端文件系统或 terminal 能力；当前没有交互式权限桥，所有 Agent `session/request_permission` 都以 `cancelled` 回答；
   - 子进程命令必须为绝对路径，禁用 shell，使用最小环境变量白名单、消息大小上限和请求超时。
3. **MCP 工具适配器（`McpToolProtocolAdapter`）**：
   - 冻结现代 MCP `2026-07-28` 与兼容旧服务的 `2025-11-25`，stdio 先探测 `server/discover`，未识别现代响应时回退旧版 `initialize`；
   - 每个现代请求携带 `_meta` 版本、客户端信息与能力；工具发现支持分页，只读元数据不触发工具调用；
   - 远端 `readOnlyHint` 等 annotation 不作为权限依据，只有本机可信策略可将工具标为只读；其余工具默认要求权限 grant；
   - `tools/call` 发送 `notifications/cancelled`，远端错误转为失败回执；传输取消未确认时由 Work 管理器记录 `uncertain`，禁止自动重发。
4. **工作域边界与审计**：
   - 任务请求与回执均向 `CompanionEventHub` 派发 `CompanionEventEnvelope`，业务域严格归属于 `domain: 'work'`，严禁冒充生活伴侣记忆。

## 2. 接口与契约定义

```typescript
export interface AcpServerCapabilities {
  readonly protocolVersion: number;
  readonly agents?: readonly string[];
  readonly streaming?: boolean;
}

export interface StdioJsonRpcConfig {
  readonly command: string; // absolute executable path; shell is never used
  readonly args?: readonly string[];
  readonly cwd?: string;
  readonly env?: Readonly<Record<string, string>>;
}

export interface McpServerCapabilities {
  readonly protocolVersion: string;
  readonly tools?: boolean;
}

export interface McpToolDefinition {
  readonly name: string;
  readonly description: string;
  readonly readOnly: boolean;
  readonly inputSchema: Record<string, unknown>;
}

export class AcpProtocolAdapter {
  constructor(capabilities?: AcpServerCapabilities, executor?: AcpTaskExecutor,
    canceller?: AcpTaskCanceller, stdio?: StdioJsonRpcConfig);
  connect(): Promise<void>;
  dispatchTask(request: WorkRequest, signal?: AbortSignal): Promise<WorkReceipt>;
  cancelTask(operationId: string): Promise<boolean>;
}

export class McpToolProtocolAdapter {
  constructor(capabilities?: McpServerCapabilities, tools?: readonly McpToolDefinition[], stdio?: StdioJsonRpcConfig);
  connect(): Promise<void>;
  listTools(): Promise<readonly McpToolDefinition[]>;
  callTool(name: string, args: Record<string, unknown>, grants: readonly string[]): Promise<unknown>;
}

export class WorkDispatchManager {
  constructor(
    eventHub: CompanionEventHub,
    acpAdapter: AcpProtocolAdapter,
    mcpAdapter: McpToolProtocolAdapter,
    clock?: () => string,
    cancelTimeoutMs?: number,
    journal?: SqliteWorkProtocolJournal,
  );
  ready(): Promise<void>;
  prepareRequest(request: Omit<WorkRequest, 'requestedAt' | 'revision'>, pairing?: PairingScope): WorkRequest;
  getRequest(operationId: string, pairing?: PairingScope): WorkRequest | null;
  reviseRequest(operationId: string, expectedRevision: number,
    updates: Partial<Omit<WorkRequest, 'operationId' | 'revision' | 'requestedAt'>>, pairing?: PairingScope): WorkRequest;
  dispatch(operationId: string, pairing: PairingScope, expectedRevision: number, signal?: AbortSignal): Promise<WorkReceipt>;
  cancel(operationId: string, pairing: PairingScope, expectedRevision: number): Promise<WorkReceipt>;
  getReceipt(operationId: string, pairing?: PairingScope): WorkReceipt | null;
}
```

## 3. 验收条件 (AC)

- **AC-0805-1（重复确认幂等只发一次）**：同一 `operationId` 重复触发派发时，直接复用首次派发中的 Promise/回执，远端适配器仅被调用一次；
- **AC-0805-2（版本化确认使旧草稿失效）**：对未派发草稿修改 target 或 instruction 时，request `revision` 单调递增；确认、取消或跨进程恢复提交必须携带当前 revision，旧 revision 在调用 executor 前被拒绝；
- **AC-0805-3（超时未知状态保护不盲重发）**：远端调用发生未知超时或无应答时，回执状态转为 `uncertain`，系统阻止盲目自动重发；
- **AC-0805-4（ACP 适配器握手、派发、取消与版本守卫）**：ACP 适配器正常完成 initialize 握手与任务派发；在不支持的协议版本下明确抛出版本错误；支持任务取消传播；
- **AC-0805-5（MCP 工具发现只读与权限隔离）**：MCP `tools/list` 仅读取元数据；非只读工具在缺少本地配置的 `permissionGrant` 时调用直接被拒绝；远端只读 annotation 不授予权限；
- **AC-0805-6（工作域隔离与时间线回执）**：派发成功后广播的 `CompanionEventEnvelope` 域恒为 `work`，严格与 `companion` 域伴侣记忆物理隔离。
- **AC-0805-7（真实 stdio wire 行为）**：ACP v1、MCP 现代发现/调用、MCP 2025 兼容握手必须通过独立 JSON-RPC 子进程回放；此 fixture 证据不替代真实 ACP/MCP 服务和正式运行时接线验收。
- **AC-0805-8（持久化回执与 Timeline 投影）**：派发前原子记录请求与 pairing；进程重启时已跨越派发边界但无终态回执的操作恢复为不可自动重试的 `uncertain`；终态回执先落库，Timeline 投影失败时不确认 outbox，重启后以稳定事件 ID 重放。
- **AC-0805-9（正式组合根与工作卡生命周期）**：从正式 `trial-backend` 启动后，经认证管理 API 配置 ACP profile 不启动子进程；准备卡不派发；仅明确确认启动一个 stdio executor；成功回执进入同一 Work Timeline；进程重启可读取回执且重复确认不重跑；遗忘撤销 Timeline source、删除可读正文并阻止重派。
