# N085-03 · 有限关联、状态变化与冲突

状态：`NOT_STARTED`。前置：[N085-02](N085-02.md) 的候选和现有 `correct/forget` 生效。对应 N085-R04、85-C。

## 改动边界

基于已有 `ContinuityFact.status/kind/validFrom/validTo/supersedesId` 建现行/历史视图和少量类型化关联。首版只需“目标 ↔ 准备事件”“角色事实 ↔ 原作人物/事件”等有来源的稳定 ID 关系；关系项自身引用来源和作用域，不能用相似文本建立跨配对边。无需 Neo4j、通用实体图或全域自动合并。Character Pack 中的原作事实仍受包版本、作品分支和知情截止点约束。

## 实施与测试

1. 先为同一目标的重复消息、先前状态到新状态、用户纠正、相互矛盾、跨域同文不同来源写固定用例。制定判定顺序：来源/权限有效 → 同一来源幂等 → 同实体与时间检查 → 明确纠正优先 → 可解释的状态变化 → 无法解释则 disputed。不能按最后写入时间无条件覆盖。
2. 同一事件重放仅命中既有 operationId/条目；不同独立证据可关联同一主张，但不得自动把推断写成事实。状态变化保留历史及有效区间，当前读取只给现行状态；纠正保留 supersedes 链并立即使旧确定事实退出 Context。
3. 如果既有状态枚举无法表示 disputed，冻结最小兼容扩展及旧库迁移；旧读者忽略/明确排除争议项，不能把未知状态当 active。关联删除或来源撤销时，索引与重建必须失效，不能留下孤立可召回边。
4. 定向回归 `ContinuityMemoryStore`、Character Pack 版本切换、后台 lease、旧数据恢复和直接 Context 消费者。用户主动忘记的是事实时，相关派生关联不可继续表达该事实。

## AC

- 85-C：同源重放幂等；“开始准备→暂停准备”返回当前暂停并保留历史；“我之前说错了”走纠正；无可解释冲突不注入确定事实；旧事实经 supersession 后不能在当前 Context 复活。
- 关联有稳定 ID、来源和 scope；跨配对/作品分支、撤销来源或失效包不会形成可用链接。旧库迁移/回退不会把争议项误标 active。
