# N085-02 · typed 候选与有据编纂

状态：`NOT_STARTED`。前置：[N085-01](N085-01.md)；N079-08 的 User Wiki/Soul 候选**正式生产写入**已验证。若该前置缺失，可完成纯编纂规则/fixture，但整步不得 `AUTO_PASS`。对应 N085-R02/R03、85-B。

## 目标与归属

已提交用户消息经现有 Memory lifecycle 的后台维护入口，产生 `user_wiki`、`user_soul` 或 `relationship` 的候选；短期琐事保持 History/Timeline。角色原作事实经 `CharacterDistiller → CharacterPackDraft`，待校验/显式激活；外部 Knowledge Library 留在资料域。编纂不更新 Character Soul 活动包，不按每轮聊天全量重写页面。

逻辑候选至少表达：类型、文字、事实/推断/用户自设性质、来源 ID 与片段 locator、抽取批次/方法版本、记录时间、有效时间、配对或角色包版本、状态。已有 `ContinuityFact` 的 `layer/kind/status/sourceIds/validFrom/validTo/supersedesId` 要复用；新增元数据只在确需持久化和追溯时加兼容字段或旁路结构，不复制来源正文。候选默认不注入确定事实 Context。

## 实施与测试

1. 固定资料先写失败用例：明确目标进入 User Wiki 候选；独立重复表达的稳定偏好可以成为 User Soul 候选；一日情绪/琐事不升级稳定 Soul；双方实际重要互动可关联 Companion Timeline；原作区块只进入 Character Pack 草稿。引用、假设、助手自述与模型臆测不能单独作证。
2. 接现有生产 outbox/后台 queue 与 `ContinuityMemoryPort.beginDerived/commitDerived`（或当时等效端口），使用稳定 operationId、来源修订和 lease。抽取可由受控模型完成，入库前必须再做确定性来源/作用域/状态校验；生成前台回复不等待编纂。
3. 角色事实复用 `SourceBlock`、`validateDraftEvidence`、剧情截止点和显式 Pack 激活。校验只证明引用存在，还需固定语料抽查事实是否由引用支持； unsupported 内容留草稿/缺口。
4. 故障用例覆盖模型无结果、畸形输出、超预算、取消、后台失败重试、消息重放和重启；重复处理不能提升证据权重或自动晋升候选。质量/调用量按 N085-00 冻结规则记录。
