# N085-01 · 来源分流与授权边界

状态：`NOT_STARTED`。前置：[N085-00](N085-00.md) 的实际来源矩阵；0.7/0.79 的 History、Character Pack 来源和配对校验可用。对应 N085-R01、85-A。Observation 正式接入额外依赖 0.8 授权保存/撤销契约，不阻塞已存在来源的实现。

## 改动边界与接口

在现有 Memory 生命周期或 Character Distiller 入口前添加有界分流/校验适配，不另建后台队列。逻辑输出为 `eligible + targetDomain + evidenceRef` 或带原因码的 `rejected/unavailable`；映射到既有 `ContinuityRecordInput/ContinuityDerivedCommit` 与 Character Pack 草稿来源。凡来源有 pairing，必须核实 userId、characterId、characterInstanceId；角色资料还要核实 characterId、packVersion、作品分支/截止点。Knowledge Library 只保持外部知识身份，不自动成为 User Wiki。

候选源码影响范围以 N085-00 核对为准，预计涉及 `memory/continuity-memory-store.ts` 的写入边界、`memory/character-pack-store.ts` 的来源/区块验证、生产消息投影及其直接消费者。公共字段若必须新增，按版本迁移并保留旧来源 ID；不直接修改历史正文或 0.8 的采集授权权威。

## 实施与测试

1. 先用固定输入复现：跨配对 History、撤销 SourceBlock、未保存 Observation、过期 grant、错误 packVersion、Work 回执和助手自述均不能进入用户事实候选。正例为已提交真实用户消息、当前角色包内有效区块、经明确保存的有效 Observation（该接口交付后）。
2. 实现来源分类和有效性快照；在写候选前、后台提交前和读入 Context 前复查来源/撤销代次。对失效来源给可定位原因码，避免静默当空白或换用更宽权限来源。
3. 0.8 接口尚未交付时保持 Observation 长期入口关闭；只以拒绝 fixture 测试安全边界。交付后加同一来源 ID、授权修订与撤销回放，不把临时 OCR 文本复制到长期库。
4. 定向测试包括重复投递、取消后晚到、角色切换、来源撤销、重启重放及旧来源 ID 兼容；被测分流走生产适配，不用测试专用写入绕过校验。

## AC

- 85-A：四类来源（History、角色资料、外部资料、Observation）落到正确域；未授权/不匹配的输入为零候选、零 Wiki 写入。Work 与助手文字不能被伪装成用户经历。
