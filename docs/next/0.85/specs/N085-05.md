# N085-05 · 候选、证据管理与遗忘闭包

状态：`NOT_STARTED`。前置：[N085-02～04](../SPEC.md#2-顺序依赖和需求映射) 的数据/检索契约；本机鉴权管理入口有效。对应 N085-R06、85-E。后端可先实施；可见页面遵守逐页要求、参考图和用户审核门槛。

## 范围与接口

复用现有 `/api/continuity/snapshot|record|promote|correct|forget`、Character Pack 草稿/激活接口、History/Trace 来源读取及 0.7/0.8 的 Timeline/记忆页面。补最少的候选列表、证据定位、当前/历史状态与入选/排除原因读取能力；写操作仍由现有权威端口执行。新增 read model/API 必须有 pairing、版本、鉴权、分页和失效语义，不创建一套并行 Wiki 编辑存储。

## 实施与测试

1. 后端先提供“候选及其来源 → 预览影响 → 确认/拒绝/纠正/遗忘 → 下一轮状态”的可验证流程。拒绝候选不得再次由同一来源重放复活；写入带 operationId 与 expectedVersion，冲突返回需要刷新，不悄悄覆盖他人更新。
2. 证据详情只在本机授权后按来源权威读取；来源已清理、无权或撤销时显示对应状态，不从 Trace/Markdown/缓存恢复正文。显示事实、推断、用户自设、当前/历史、有效时间和属于哪个配对/角色包。
3. 遗忘一次要检验原条目、派生 Soul/Wiki/Relationship、有限关联、检索索引、页面投影、缓存、在途 Context 和后台重建。若部分失败，报告未完成域及重试/修复入口，不先显示“已全部忘记”。对于 History 原文删除与派生撤销分别描述结果。
4. 页面实施前向用户询问该页要求并取得参考图；确认后只改相应已有页面及直接依赖，不重做控制台导航。页面完成时主动提交用户对照审核，未确认只记自动通过/待审核。
5. 定向用例覆盖旧深链、鉴权、无数据、无权、版本冲突、异步离页、角色切换、来源清理、重启重建与部分失败。所有 UI 测试使用真实管理端口，外部模型可 fake。
