# N085-04 · 分域召回与正式 Context 消费

状态：`NOT_STARTED`。前置：[N085-01](N085-01.md)、[N085-03](N085-03.md)；0.75/0.79 的正式 `ProductionContinuityContext` 消费和在途失效已用生产链验证。对应 N085-R05、85-D。

## 现有缺口与改动边界

当前 `ContinuityContextComposer` 有 Character Soul、Canon Timeline、User Soul/Wiki、Relationship、Companion Timeline 的 segment；`ContinuityContextSource` 尚无独立 `character_wiki`。本步必须让有效 Character Wiki 事实按问题命中，不能用只召回 Canon 事件冒充角色知识覆盖。先核对实际 Character Pack 中事实的存储/读取路径，再作最薄只读扩展；不造新的 DialoguePipeline 或全量向量索引。

继续沿用 `ContinuityContextRequest/Result`、正式 `ProductionContinuityContext` 和当前总请求预算。新增 segment/source 类型或查询参数时，更新兼容类型、序列化消费者和管理诊断。检索顺序先鉴权/配对/角色包版本/剧情截止点/知情/有效期/撤销，再按问题意图选择候选域、相关性与时间；无匹配返回空段。Soul/Relationship 只作表达和互动适应，不能作为未经证实的用户事件证据。

## 实施与测试

1. 固定问题集分别询问近期生活、长期目标、角色原作事实、原作剧情先后和外部资料；记录期望来源域和禁止域。先写失败用例证明现有 Character Wiki 事实未被独立命中或错误混入 Canon。
2. 用结构化过滤 + 关键词/全文 + 时间排序实现有界召回；去重以事实/来源稳定引用优先，文本相等只作辅助。每域限定候选数和预算，最终不得超过正式总 Context 上限，也不能修改 0.61 冻结前缀。
3. 每段返回稳定 key、来源/证据 ID、版本、选入/排除原因和 token 估算；诊断默认只记录 ID、状态、预算。发送前再次检查配对、包版本、来源撤销与连续性 revision，纠正/遗忘在途后旧结果必须被拒。
4. 经正式桌面对话执行两类问答，记录实际组合出的请求、选入来源及回复；无资料和知识缺口保持未知。定向回归普通无连续性包文字、History/Memory、Character Pack 切换与管理 Inspector。
