- 一次执行一个 SPEC。开工先读根 [AGENTS.md](../../../AGENTS.md)、本索引、当前 SPEC、目标路径的 Git diff、0.7/0.79 的实际报告与当时源码；记录实际基线提交，不沿用本稿列出的源码路径作为已验证接口。
- 状态分开记 `IMPLEMENTED`（模块行为）、`WIRED`（正式生产链消费）、`EXPOSED`（本机管理入口可用），并分别标自动、真实模型和人工结果。状态仅能是 `NOT_STARTED`、`IN_PROGRESS`、`AUTO_PASS`、`BLOCKED`、`PENDING_USER_ACCEPTANCE`；前置未过的子能力可独立验证，但不得把整步升为 `AUTO_PASS`。
- 沿用已有 History/Source、Character Pack、ContinuityMemoryPort、Memory lifecycle、唯一 DialoguePipeline 和 ContextSource；新增 schema/API 时记录版本、旧数据迁移/恢复及直接消费者。不得通过手工 seed、独立脚本对话或假路由证明生产闭环。
- N079-08 的 User Wiki/Soul 自动候选链、N079-01 的派生遗忘及实际 Context 失效必须先核验。0.8 Observation 只有在授权保存、来源撤销和生产事件契约有证据时才接入长期候选；缺席时明确 `unavailable`，不把临时 OCR 文本代作 History。Work 回执和 Knowledge Library 保持独立域。
- 新行为先用确定性固定资料写失败测试，再最小实现、定向回归；真实模型回放单列。只运行当前模块、直接消费者和必要共享契约测试；版本收口才做代表组合、迁移/恢复与真实桌面对话。
- 可见界面沿用 0.75/0.8 逐页规则：先问用户该页要怎样改，再索取参考图、确认范围，实施后主动交用户审核；未拿到参考时只做后端/契约部分，不自行设计页面。
- 每步在 `reports/N085-xx.md` 记录改动、受影响接口、AC 证据、命令/退出码、真实与 fixture 区分及未完成项。没有执行证据时保持 `NOT_STARTED`，不预写 PASS。

## 3. 共同验收资料与硬边界

N085-00 固定一套自写/已获授权资料，并在实现前登记样本和期望：至少两个用户×角色配对、同角色两个实例、同角色两个包版本、一个剧情截止点；至少 12 条应沉淀来源（目标、独立重复的偏好、重要经历、角色事实各至少 3 条）和 12 条不应成为用户事实的来源（琐事、引用/假设、助手自述、Work/外部资料各至少 3 条）；另有至少 6 组状态变化/纠正/冲突和 12 个带期望来源域的查询。角色资料含截止点前后事实和可定位区块；临时/明确保存的 Observation 各有正反例。样本要包含取消、重放、撤销、重启与旧数据副本，不提交真人隐私正文。0.8 不可用时，Observation 只作拒绝输入的契约 fixture，不能算正式接入。

全部数据安全不变量为 **零容忍**：跨配对泄露、未授权 Observation 沉淀、无来源事实自动激活、已撤销内容复活、超剧情截止事实进入普通角色 Context、超过实际总 Context 预算、重复事件增加证据权重，任一出现即 FAIL。固定样本的最低质量门槛：12 条负例中零条成为用户事实；12 条正例至少 10 条生成正确域且有有效证据的候选；6 组更新/冲突全部给出正确现行状态或 disputed；12 个查询至少 10 个在前三条候选中命中期望来源，12 个均不得返回禁止域。候选精确率/召回率、检索命中/漏召回、错误归因、前台检索 P95 延迟和模型 Token/调用量仍须完整报告。参考机器、输入大小、前台延迟上限及后台调用预算在 N085-00 实现前预登记；不看到结果后降低阈值。真实模型波动单列，不用单次样本替代确定性门槛。
