## 1. 目标与体验闭环

让文字、语音和角色动作同步、可中断、可恢复。用户能选择当前支持的声音和皮肤，知道麦克风何时工作，旧轮取消后不会继续说话或播放旧动作。已有基础语音与 Live2D 是起点，本版负责完成更稳定、自然的组合体验。

典型路径：选择输入设备并试麦 → 选择已配置来源/音色 → 开始说话与查看 partial → 一次 final 提交 → 分段回复及播放 → 用户打断 → 新轮接续。文字输入、纯文字输出仍独立可用。

## 4. 语音会话与播放

### 4.1 输入

采集会话独立于已提交对话轮，但不自行分配全局轮次。partial 仅展示；用户结束输入或启用的端点检测产生一次 final。重复 final、迟到 chunk、重新连接旧会话均不能重复提交。

默认保留明确开/停和按键说话。自动端点检测、唤醒和说话打断由用户显式启用；播放回声不能默认当用户新指令。缺回声抑制能力时标记限制并保留手动打断，不宣称全双工质量。

试麦、正式采集、唤醒共享设备租约。设备拔出时停止当前采集并显示选择/重试；不悄悄切另一个麦克风。唤醒关闭后立即停止采集；缺模型显示不可用。

### 4.2 合成与播放

流式 Provider 与 batch Provider 都有真实能力声明。文本按完整可读片段切分，设置最大排队字符/段数/音频时长及首段超时；具体阈值由 SPEC 在参考设备和语料上冻结。段使用 turnId、generation、segmentId、sequence，重试不能重复播同一段。

已输出后同来源失败显示部分完成；不拼接另一来源声音掩盖错误。音频下载/解码失败可保留已确认的文字回复；文字完成与音频失败分别显示，不撤回已完成文本冒充整轮未发生。

取消时先停止实际播放设备、清空缓冲和取消合成，再关闭口型/动作；迟到音频即使解码成功也不得重新播放。新一轮优先于旧播放。音频资源释放和 ESM 代码卸载状态分开。

## 5. 角色表现与桌宠协作

表现 adapter 消费已提交的带 Scope 事件，不发起新的对话或写 Memory。动作来源优先级建议为直接用户交互/明确状态、正在播放的口型、允许的情绪手势、低优先级待机；互斥参数不能由多个循环竞争写入。

模型声明可用参数、motion、expression、点击区域和口型支持。未支持的动作有明确无动作/通用状态退化，不以资源名相似猜测。声学口型可以先基于振幅；没有音素时间数据时不宣称音素级同步。

换肤准备成功再替换，失败保留原模型；旧纹理、监听、动作和音频绑定有释放证据。角色包切换影响身份和上下文，皮肤切换只改变外观，两种操作在界面分清。

“桌宠协作”首版指同一用户交互空间中聊天、工作进度和主动邀请的协调：用户输入优先，工作完成提示可排队合并，免打扰时不播放声音；通知不能误用另一角色的当前轮次。多桌宠互相对话仍后置。

## 6. 契约、资源与设置

逻辑事件需包含 scope、source/model/voice 修订、段序号、播放进度和终态。具体 SDK 类型实施时冻结；升级必须让旧的整段 text/reply 消费者仍能工作。总轮次只终结一次，分段播放结束不反复提交聊天记录。

| 设置域 | 持久化与隔离 |
| --- | --- |
| 麦克风/扬声器 | 机器级设备偏好；失效提示，不把硬件 ID 当跨设备通用标识 |
| 声音 | source + model + voice 的组合；切源重新验证音色 |
| 角色/皮肤 | 实例选择与外观关联分离；不覆盖 Soul/关系 |
| 窗口 | 尺寸/位置/穿透可恢复；显示器断开后回到可见区域 |
| 表现策略 | 支持能力与用户开关共同裁决；降低动态效果设置可关闭自动动作 |

默认不保存私人录音。设备日志记录状态、采样率、排队和耗时，不写正文和凭据。来源资源由包登记，停用后设备/worker/socket 可验证释放，用户外部服务不被终止。

## 8. 实施与后置项

建议拆为“语音/表现事件基线 → STT 可靠性 → TTS 分段与播放 → 中断同步 → Live2D/窗口 → 协作提示与组合验收”。先冻结公共事件的唯一修改责任，再按模块分工；是否启动多 Agent 以实际任务授权为准。

Mobile 独立评估客户端形态、连接/配对、音频权限、电量、通知和数据同步，不自动共用 Windows 本地路径或同步私人数据库。模型安装器、完整 Trace 和极简配置面仍是[TODO](../TODO.md)中的候选优化，本版不暗中升级其排期。
