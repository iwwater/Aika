# NEXT-09 · 版本末尾人工验收

状态：NOT RUN。需求：N06-R10。前置：NEXT-08 AUTO_PASS。

## 边界

这是本版唯一计划中的用户人工验收阶段。worker 提供已构建的可运行版本和简明操作清单，不把环境调试、缺失功能或必需自动测试转交给用户补做。不规定必须连续日用 3～7 天。

## 用户验收清单

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| 09-A | 启动、修改角色/Provider、重启 | 设置保留、可正常使用，旧 Aika 数据不受影响 |
| 09-B | 连续文字对话、快速发送、取消后重发 | 上下文连续、无旧回复覆盖、无永久忙碌 |
| 09-C | 真麦克风说话、听取回复、讲话或点击停止 | 实际输入输出可用，停止后旧语音不恢复，无明显漏句/乱序 |
| 09-D | 测试记忆、纠正和遗忘，查看 Timeline | 可见行为符合需求，已遗忘/删除来源的正文不重新出现 |
| 09-E | 触发一次可恢复服务错误，再恢复配置 | 提示真实清楚，恢复后可继续使用 |
| 09-F | 检查 UI 与语音体验 | 用户确认本版基本可用；明确区分缺陷与后续增强建议 |

验收环境与选择的实际后端要记录。真人听感由用户判断，不能用自动评分替代其确认。worker 不代填 PASS。

## 缺陷闭环与发布条件

- 崩溃、数据破坏、串会话、取消后旧音频恢复、核心输入输出不可用均阻塞验收。
- 可自动复现的问题先加失败回归测试，再修复并运行受影响测试；涉及集成/构建的修复更新候选包并复验受影响项目。
- 仅设备/体验问题保留现场复现证据，不编造可自动化的结论。
- 修复后的候选 commit 必须匹配报告和包 hash，不能拿旧包验收新代码。
- 用户明确验收通过后标 RELEASE_ACCEPTED；发布标签建议 `aika-next-v0.6.0`，与旧项目版本区分。创建标签、推送、对外分发按后续授权执行。

产物：reports/NEXT-09_ACCEPTANCE.md，记录用户确认、缺陷、修复 commit 和最终候选版本。没有用户结果时保持 MANUAL_PENDING。
