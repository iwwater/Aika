# Aika Next 总路线图 RPD

状态：规划；版本：1.0；日期：2026-09-19。

## 1. 产品目标

以 AAAAGENT 已有运行流水线为底座，逐步接入 Aika 的 Provider、Timeline、记忆扩展、感知和表现能力，得到可测试、可替换、可持续维护的陪伴助手。旧 Aika 是行为、素材和实现参考库，不再承担新架构主线。

首要使用平台 Windows 11。源码可在本地构建，模块可在无真人输入的情况下自动测试；每个版本完成开发后才集中人工验收。上游已有测试不代表本地基线或未来扩展自动通过。

## 2. 架构边界

```text
文本 / 音频 → 输入适配 → 上游轮次与作用域 → 上游对话流水线
                                    ↓
                              Context / Memory
                                    ↓
                             DialogueProvider
                                    ↓
                      回复 → 展示 / TTS / Timeline
```

- 上游轮次、取消、记忆维护、上下文和工作路由优先保留。缺少扩展点时，先以失败契约用例证明，再做最小接口改动，不复制第二套运行时。
- Aika 独有能力通过端口/适配器接入。Plugin Kernel 暂不迁入；只有后续真实动态组合需求出现才评估。
- Timeline 是事件记录，Memory 是长期记忆策略，Wiki 是知识组织；三者可共享来源标识，但不得重复承担同一职责。
- Context 扩展与对应能力一起交付，不能积累多个未接入主链的孤立模块。
- 角色配置不等于动态关系系统；基础语音不等于音色克隆、声学优化或唤醒。

## 3. 版本路线

| 版本 | 交付目标 | 不属于该版的能力 |
| --- | --- | --- |
| 0.6 | Windows 基线、Aika 静态身份、OpenAI-compatible 与 Gemini、文本对话、上游 Memory、最小聊天 Timeline、基础语音、必要配置与状态 UI | 新 Wiki、动态关系、OCR/VLM 增强、ACP/MCP 新接入、Live2D 移植、Mobile、插件内核 |
| 0.7（规划） | Timeline/Memory 使用深化、Persona/Relationship、Wiki MVP、对应 Context 预算 | 未完成需求设计前不自动开发 |
| 0.8（规划） | OCR/VLM 感知、主动陪伴、Work/ACP/MCP 按独立 SPEC 接入 | 外部动作必须遵守产品权限与确认语义 |
| 0.9（规划） | 高级 Voice、Live2D/表现适配、桌宠协作；Mobile 单独评估 | 不默认同时实现所有表现后端 |
| 1.0（规划） | 稳定化、升级与数据迁移、分发和长期维护；按实际需要评估插件化 | 不以版本号代替验收 |

0.7 以后是方向，不是已授权 worker 任务。0.6 的具体需求以本目录 [RPD](0.6/RPD.md) 为准。

## 4. 开发与 Git 路线

当前 `aika-next` 是独立历史的文档种子。NEXT-00 引入完整上游历史和固定基线，保留本目录，不与旧 master 混合。所有后续功能分支从该新主线派生，例 `feat/next06-provider`；通过本 SPEC 自动门槛和 diff 审阅后回到新主线。

版本开发过程中，新主线允许集成已通过的增量；发布以通过人工验收的版本提交为准，不要求把全部远期能力完成后才首次发布。若未来改名为新仓库 main，另行操作；禁止将 orphan 分支直接合入旧 master。

## 5. 统一完成定义

1. 模块完成：本模块 AC 自动通过，相关回归通过，有证据，待集成项明确。
2. 版本开发完成：版本所有必需自动门槛通过、必要构建可用，可交用户验收。
3. 版本验收完成：用户确认真实使用结果；需修复的问题补测试后修复，再定向复验。
4. 发布：对应验收通过提交，记录版本与来源；推送、分发由后续明确授权决定。

既有语音/文字用例优先复用。新行为要新增必要失败测试；不能因“只用既有测试”而放弃对新增行为的验证。

## 6. 主要风险与出口

| 风险 | 处理与出口 |
| --- | --- |
| 上游 Windows 与 macOS 能力不同 | NEXT-00 先核实 Windows 路径、构建和可用性，不跨平台复制假设 |
| 原测试耦合旧 Kernel/Runtime | 复用行为、输入和预期，改 harness；不为了跑旧测试把旧架构搬入 |
| 模型随机性或服务不可用 | fixture 确保逻辑确定性，真实回放单列；必需真实门槛未跑不宣布开发完成 |
| 数据误覆盖 | Next 使用独立用户数据目录；旧数据库导入不在 0.6 范围 |
| 上游扩展点不足 | 记录最小变更、上游差异和契约测试，不大改核心 |
| 来源/资产限制 | 导入保留 LICENSE、版权与来源；本路线不承诺商业可分发性 |

参考：[AAAAGENT README](https://github.com/phoiex/AAAAGENT)，查阅日期 2026-09-19；详细接口与可运行性尚待源码基线核实。
