## 2. 核心机制落实证据链

1. **增量无损迁移与旧授权隔离（AC-08202-1）**：
   - 数据库自动安全追加三张 additive 新表，保留全部 0.81 既有图片、活动、配对与 counters 结构；
   - 旧 keyboard 授权依然被严格限定为活动计数，不得携带正文或派生权限。
2. **文本/文件候选幂等与派生文本绑定（AC-08202-2）**：
   - 候选基于 `(user_id, character_id, character_instance_id, source_kind, native_event_id)` 保证严格幂等，重复提交返回已有 `sampleId` 与 `duplicate` 结果；
   - `listPending` 支持 cutoff 时间截断；`commitDerived` 原子标记父来源为 `processed` 并绑定 `processingKey`，跨配对严格隔离。
3. **共享资产与文本暂存全口径容量计算（彻底防退化 P1-6，AC-08202-3）**：
   - `managedBytes()` 全面覆盖 `collection_assets`（物理图片文件）+ `collection_candidates`（未决文本）+ `collection_derived_text`（派生文本），任何文本暂存膨胀均受 1 GiB / 64 MiB 硬预算约束。
4. **级联作废与墓碑双键防护（AC-08202-4）**：
   - 来源撤销或全量清除时，级联将关联候选与派生文本置为 `invalidated`，并把 `native_event_id` 与 `idempotencyKey` 同步写入 `collection_tombstones`；
   - 彻底防范重放已撤销文件或文本导致的“僵尸复活”。
