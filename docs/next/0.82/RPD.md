## 1. 目标与用户决定

用户选择桌宠如何了解当前活动：主动模式周期抓屏、识别文字，并在合适时机提供陪伴；被动模式收集所选来源的文本、已有截图和下载文件，按用户触发或每日一次处理。两种模式共用来源记录、回看、删除和角色上下文体系，避免产生两套互不一致的经历。

已明确的决定：两种模式；主动模式有周期屏幕 OCR 与陪伴；被动模式包含文本、截图和下载文件，文本同时覆盖剪贴板、键盘/输入法接入、桌宠对话、主动提交和图片/文档解析；每日到设定时间自动处理，也可手动触发；这一阶段结束后再做最终测试；先审核 RPD，之后拆 SPEC。

以下解释随本次 RPD 审核作为执行基线；尚需工程验证的覆盖范围由 N082-00 留证，不以产品要求冒充已实现能力：

| 项目 | 执行基线 |
| --- | --- |
| 两模式关系 | 互斥选择；主动模式在同一被动资料收集能力上增加周期抓屏与情境陪伴。来源授权仍分别控制；切主动不会自动增加目录或文本来源。 |
| 被动的“主动触发” | 指用户点“立即收集/整理”，不是桌宠主动开口，也不是定时截屏。 |
| 每日一次的对象 | 对已授权来源做一次增量收集、解析和索引；不是每天截一张屏，也不是每日自动发送总结。 |
| 文本来源 | 用户已明确全部纳入：剪贴板文本、键盘/输入法提交文本、已有对话、主动提交、截图 OCR 和文档解析。键盘/输入法是获取实际文本的接入路线，支持范围须验证；不随旧 keyboard 活动开关自动开放正文。 |
| 下载文件 | 用户已下载到所选本地目录的文件；桌宠不主动联网下载。记录下载目录来源，不把文件出现时间冒充浏览器下载时间，也不声称知道原网址。 |
| 自动陪伴形式 | 基于新观察给出简短、可忽略的情境气泡；用户回复后进入既有对话轮次。被动模式不因采集自动开口，但仍正常回答用户提问。 |

## 2. 用户可见模式与操作

| 行为 | 被动模式 | 主动模式 |
| --- | --- | --- |
| 获取当前屏幕 | 不做后台抓屏 | 按设定周期抓取明确授权的屏幕、窗口或区域 |
| 收集已有文本、截图、下载文件 | 用户触发及每日增量处理 | 保留同一批次能力和来源范围 |
| OCR | 可解析已收集且获解析授权的图片；不因此获取实时屏幕 | 对周期抓屏执行真实 OCR；失败显示失败，不把图像尺寸当识别文字 |
| 陪伴输出 | 收集过程静默；用户提问时可引用有效资料 | 新观察可产生情境候选，经忙闲、勿扰、配额和冷却判断后展示 |
| 已有数据 | 可回看、标注、删除，停止来源不等于删除旧资料 | 同左；切回被动后撤回尚未展示的屏幕情境候选 |

“暂停全部”是独立运行状态，不是第三种采集模式。初次安装或升级后不自动扩大旧授权；只有用户选定模式、来源和处理目的地后才启动相应任务。保留 0.81 keyboard 活动统计作为可选辅助来源；本版新增 keyboard/IME 正文来源，二者分别授权和展示，不把按键计数当作文本采集，也不使它成为主动抓屏的必需依赖。

用户在 Settings/隐私与采集选择模式、来源、屏幕目标、频率、OCR 引擎及陪伴策略。界面显示当前模式、实际运行/暂停/错误状态、最近成功与下一次任务、来源与本地留存范围。提供“立即收集/整理”“立即观察一次”（仅主动模式）、“暂停全部”和“恢复”。Dashboard 显示轻量状态与最近收集摘要；详细来源、OCR 和调度记录归 Developer；普通回看和删除无需打开 Developer。

## 3. 主动模式

流程：用户启用并确认屏幕范围 → 周期抓取 → OCR → 去重与有效性检查 → 短期观察 → 陪伴候选 → 既有气泡仲裁 → 用户回复进入原有轮次。

抓屏频率、OCR 频率、陪伴发言频率是不同预算。每次抓屏不等于必须调用对话模型或开口；空白、未变化、识别失败、过期画面不生成新情境。用户正在聊天、输入、录音或确认工作时不抢占；勿扰与全局暂停生效。内容不足时保持安静，不根据窗口标题断言用户完成了某事。

持续观察需要新的有时限授权语义，绑定配对、目标、用途、处理目的地和修订。现有单帧确认不能被循环重用。目标消失、权限失效、切角色、锁屏或睡眠时暂停并取消未提交任务；沿用当前规格，解锁及重启后需主动恢复，不跨会话自动续采。

首版本地真实 OCR 为必需能力，具体引擎在后续 SPEC 按实际 Windows 能力、质量与部署条件选定。VLM 不作为每次 OCR 的必经步骤。若陪伴回复使用已配置云端 LLM，必须明确说明 OCR 文本将进入该模型上下文；“本地 OCR”不等于整条陪伴链没有外发。没有相应处理授权时仍可本地观察，但显示陪伴生成不可用，不静默换目的地。

## 4. 被动模式及增量收集

用户选定截图目录、下载目录及文本来源。启用时建立边界：默认只接收此后新增/变更的内容，历史文件通过独立“导入已有资料”操作选择。首版默认只处理所选目录本层；子目录范围须明确设置，重解析点不能扩大实际授权根。

文件通知用于发现候选、稳定性判定和登记版本；用户触发或每日批次才做集中解析与索引。剪贴板文本/图片和键盘/输入法提交是瞬时来源，无法在晚上恢复白天内容，因此在来源已启用的期间进行事件接收和有界本地暂存，**到每日设定时间或手动触发时集中处理**。事件暂存不触发陪伴发言，不逐键调用模型。界面区分“接收中”“待处理”“已处理”；每日频率描述处理批次，不意味着全天不接收来源事件。

| 来源 | 首版产物与限制 |
| --- | --- |
| 剪贴板文本 | 独立文本来源开关，接收变化后的纯文本并保留观察时间、版本与可信来源信息；重复通知去重，复制与真实键入不得混标。来源应用无法确定时显示 unknown。 |
| 键盘/输入法文本 | 新增实际正文来源，与旧 keyboard 活动分开。优先获取支持应用或输入法提供的已提交文本；编辑中 composition 不当成最终正文。keyboard adapter 只有在能可靠还原应用实际提交文本时才计入正文覆盖，不能将原始键码简单拼接冒充输入结果。选定并实测至少一条真实正文路线后交付，列明支持的应用、输入法、语言与缺口；不预先承诺所有 Windows 程序均可读。 |
| 对话、主动提交、解析文本 | 保留来源引用、采集时间和有效修订；已有对话复用原 History，不复制永久聊天库。主动提交文本可直接进入有界样本；解析文本保留对应图片/文档出处。 |
| 截图/剪贴板图片 | 沿用 0.81 稳定读取、真实内容校验、双通道关联及资产共享；批次可 OCR。普通复制图片保持来源不确定。 |
| 下载文件 | 记录文件名、类型、大小、发现时间和稳定版本。首版解析 TXT/Markdown、含文本层 PDF、DOCX；图片走现有 OCR。扫描 PDF、压缩包、加密文档和不支持类型明确标未解析，不执行文件或宏。 |

原文件属于用户，清理受管数据不删除原文件。批次开始、读取后、提交前核对授权与文件版本；原文件在收集前被删除时显示缺失，不伪造成功。大文件仅记录元数据并说明跳过原因；不默认复制整个 Downloads。内容摘要、提取文本与必要受管快照共享同一预算和留存规则。

正文来源首次开启显示其与活动统计的区别，采用明确的应用/输入法范围。密码控件、不可判定的受保护输入场景不采正文；无法可靠排除时该接入范围不可启用，不能声称仅靠正则即可过滤敏感信息。源端按提交片段聚合，不持久保留逐键序列；文本可回看、删除并随来源撤销失效。输入正文、复制的第三方文字和 OCR 文字保留各自证据类型，不自动视为用户自述事实。键盘/IME 路线若在某应用不可用，应显示不可用，不能悄悄改用抓屏来完成被动文本收集。

## 5. 频率与资源默认值

以下为本版产品默认值；执行预算与测试阈值按 SPEC 在测量前冻结，没有实测通过承诺。

| 项目 | 默认与行为 |
| --- | --- |
| 主动抓屏/OCR | 每 5 分钟一次；设置范围 1～60 分钟；同一配对最多一个任务在途，慢任务不并发堆积、不补抓错过的历史画面。 |
| 主动陪伴 | 继承当前共享上限：每日最多 2 次、最短间隔 3 小时；可在设置调整。与原问候共用总配额，不能各自叠加。 |
| 被动批次 | 手动触发 + 每日本地时间 20:00 一次，时间可改；手动任务不重置每日计划，相同文件版本不重复解析。 |
| 错过每日任务 | 应用停机不要求常驻系统服务；重新运行且用户恢复授权后至多补一次增量批次，不补发多天任务。时区/日期变动不造成同一计划日重复成功批次。 |
| 失败与排队 | 一个批次在途，重复点击复用当前任务；失败项可手动重试，自动重试有上限，不能用无穷重试拖住对话。 |
| 留存 | 主动原始抓屏默认处理后释放；短期 Observation 沿用现有有效期。被动样本与解析文本沿用 7 天、受管资产总额 1 GiB；原始用户文件不计作受管副本。 |
| 图片/文档边界 | 图片沿用 0.81 的 20 MiB、40 MP 上限；文档 20 MiB、PDF 最多 200 页与有界提取文本，超限明确降级。DOCX 另设解压与提取限额，不依赖不稳定分页。具体时延/内存通过线在验收测量前冻结。 |

用户可单独明确保存主动观察；周期屏幕内容不默认形成七天全屏图像档案。任何来源撤销、删除、TTL 到期，必须使其派生文本、候选、缓存和投影同步失效。

## 6. 工程基线与改造责任

本节为源码核对后的能力边界，不是任务拆分或目标 API。

| 当前入口 | 核对事实 | 本阶段改造 |
| --- | --- | --- |
| `core/collection-service.ts`、`memory/collection-store.ts` | 已有 keyboard 活动/目录/剪贴板图片采集与有界样本存储，没有因此获得输入正文能力 | 新增剪贴板文本、keyboard/IME 提交文本、下载文件候选及批次进度；正文接入的系统/输入法可行性须在后续规格前置核验，复用同一来源权威、去重和撤销机制。 |
| `management/perception-runtime.ts` | 管理入口当前签发单帧授权，接收图片并处理 | 增加明确持续范围与周期任务生命周期；不得以重复调用单帧授权模拟已获持续授权。 |
| `core/screen-perception.ts`、`core/observation-context.ts` | 有 OCR/VLM engine 接口、短期观察、取消及上下文入口 | 接入真实抓屏→OCR，保证当前角色、时效与处理目的地；临时观察和持久来源保持分工。 |
| `core/local-ocr-engine.ts` | 当前读取 PNG 文本元数据，或返回“本地屏幕图像 宽×高”；不是像素文字识别 | 替换/接入真实 OCR；用不含文本元数据的真实截图证明识别能力，不能以返回 `ok` 验收。 |
| `companion/proactive-invitation-runtime.ts`、`core/proactive-companion.ts`、`companion/invitations.ts` | 已有候选、冷却、配额、忙闲与来源校验；既有路径不等于新屏幕来源已接通 | 接入有效 Observation 情境，复用一个仲裁与轮次入口，禁止新增抢占气泡的第二套循环。 |
| Settings、Dashboard、Developer | 已有管理与诊断分层 | 增加两模式和批次/观察状态，保留普通用户控制入口；视觉风格不作为本轮前置。 |

模式配置属于产品策略；采集与解析归能力 adapter，宿主负责资源生命周期和取消，来源 owner 负责持久性与删除，管理端经正式鉴权接口操作。OCR/文件文本是待理解资料，不是工具执行指令。收集、解析、用于陪伴、长期晋升分别有目的范围；本版不实现 0.85 全套 Wiki 编纂，不新增 Work 自动执行，不把文档作者观点当成用户经历。

切主动到被动，立即停止实时屏幕任务并取消其迟到结果和候选，保留已授权的被动来源；切被动到主动，先完成新增屏幕/处理授权。升级保留旧样本与 tombstone，已有 0.81 来源不自动获得正文解析、云处理或屏幕采集权限。旧自动问候在被动模式下随模式策略静默，用户显式设置的提醒另按其原用途处理。

## 8. 改造与最终测试顺序

1. 用户已审核本 RPD 并同意拆分；文本来源与每日/手动处理、接收与处理的区别、默认频率及模式关系作为实施基线。
2. 已拆 N082-00～09，见 [SPEC](SPEC.md)，覆盖来源/授权、真实 OCR、模式调度、陪伴接线、管理入口与合并验收；实施尚未开始。
3. 开发期间持续进行 Agent 定向回归与真实接线验证，0.81 未关闭缺陷作为直接前置处理。最终人工验收集中后置，不表示可以跳过开发中的自动检查。
4. 本阶段完成后，合并 0.81 与本版相关场景进行一次最终 Agent 验收，通过后再做人工测试：剪贴板与 keyboard/IME 真正文 → 被动手动/每日处理 → 主动周期 OCR 与陪伴 → 切换/暂停 → 仅目录场景锁屏 → 睡眠/重启 → 撤销与删除 → 聊天和资源成本。旧 0.81 的“零键盘正文”断言继续约束活动通道，新正文通道按新授权单独验证，不能直接删旧断言来过测。
5. 正常试运行沿用至少 3 个使用日、累计 8 小时与样本标注的现有要求；同时覆盖两种模式、一次真实每日批次及主动 OCR 观察。已有同版同范围证据可复用，不能拿旧版本、smoke 或 fixture 充当自然使用。此前所有版本不因本 RPD 被标为通过，用户确认实际体验后才记本阶段 ACCEPTED。

需求审核与规格拆分不等于用户在产品中启用了真实采集；运行来源仍按产品授权流程生效。
