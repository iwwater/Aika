## 范围与修改路径

核对真正运行的 Windows 组合根、来源 owner、包/资源注册、共享配额与 API 鉴权。完成输入正文路线、真实 OCR 引擎和持续目标捕获的最小可行性验证，再冻结公共契约与预算。不实现完整模式 UI、不默认开启用户来源、不新增全局输入监控来替代可行性结论。

现有：`contracts/collection.ts`、`contracts/perception.ts`、`app/trial-backend.ts`、`core/local-ocr-engine.ts`、`core/perception-grant.ts`、`companion/proactive-invitation-runtime.ts`；目标新增 `contracts/companion-mode.ts`、`tests/next082/`、`tools/run-next082-smoke.mjs` 和必要最小探针。只在实际需要时修改构建/依赖锁，记录许可证和部署前提。

## 本步接口、消费者与生命周期

提供 CONTRACTS 中 ModePolicy/ModeStatus、SourceCandidate/DerivedText、SourceGrant/ContextUseGrant、JobStatus、TextSourcePort/FileSourcePort/ScreenCapturePort/OcrPort 的类型和校验基线，明确配对、代次、版本、取消和错误。01～08 为直接消费者。本步没有生产监听实现，默认拒绝不可用能力。

真实 OCR 用无 PNG 文本元数据的中英文像素截图；正文探针验证至少一个用户实际可用的应用/输入法组合的 commit、composition 取消和保护控件拒绝。明确需要何种安装/扩展、架构位数/权限和不支持应用，不能假定任意第三方 IME 可被读取。持续捕获验证选定窗口/区域/屏幕的可信 targetRef 与目标失效；引擎/捕获技术依据记录原始官方资料和实际结果。失败为 BLOCKED，可独立继续不受影响步骤。

冻结增量数据库迁移/回滚保护、helper 新旧协议协商、旧单帧保持及持续 grant 扩展。测试工具拟提供 `test:next082`、`dev:next082:smoke`、`measure:next082`；smoke 只准备隔离根，不签发真实授权。按 TESTING 冻结参考机器、数据集、正文/文档/OCR资源上限、质量与性能数值，未填项明确阻塞相关验收。
