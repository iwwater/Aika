# N082-06 · 手动/每日批次与周期观察调度

状态：**NOT_STARTED**。前置：01～05，02 作业 owner 与 05 OCR 接口稳定。权威：[RPD](../RPD.md)、[SPEC](../SPEC.md)、[共用契约](../CONTRACTS.md)、[测试规则](../TESTING.md)。源码路径以下均相对 Windows 工程根，标“新增”的是目标文件，不声称已存在。

## 范围与修改路径

交付两类有界任务：每日/手动增量解析、主动周期观察。复用同一生命周期和共享 OCR 执行预算，不创建另一 Memory Extractor 或后台常驻服务。不实现陪伴生成和 UI。

目标新增 `core/collection-batch-runner.ts`、`core/observation-scheduler.ts`，在 `memory/collection-store.ts` 使用 02 作业/幂等端口；既有 `core/distillation-scheduler.ts` 仅核对职责，不把来源批处理塞入 Wiki 维护。

## 本步接口、消费者与生命周期

提供 BatchRunner.request/status/cancel 与 ObservationScheduler.tick/observeNow/cancel，消费 ModePolicy、grants/generation、listPending、Text/File parser/OCR。08 管理端和 07 Observation 候选为直接消费者。

批次 snapshot cutoff+稳定 cursor，checkpoint、processingKey 和结果原子提交；新到项留下一批。手动与定时重叠复用在途 job，来源版本已成功不重复解析；daily/catchup 计划账本持久，用户改时间/时区不产生同计划日重复成功。夏令时跳过小时选择当日下一有效时刻、重复小时只跑一次；重启/停机需手动恢复后至多补一个增量批次，不追跑多天。失败最多一次自动重试、保持同 job/key，partial 与失败项可单独重试。

主动只在 running+active+有效持续授权下调度，最多一项在途，不补历史帧。observeNow 与 tick 共享在途任务；慢 OCR 不积压。批次和观察共享 OCR 并发1及队列预算，超限记 dropped/queued 而非内存无界；用户对话优先。暂停/切模式/授权变化取消相应任务，恢复不处理暂停期间瞬时事件；已合法收到但尚未处理候选需现行 parse 权限并保留原接收来源。
