# N079-08 · 0.7 最小生产连续性写读闭环

状态：IMPLEMENTED · AUTOMATED PASS；BackendSession 的普通用户消息可生成带 History 来源的 Wiki/Soul 候选；候选 outbox、重启恢复、幂等、遗忘联动通过。候选始终等待显式审核，不会自动晋升为事实。

入口：[RPD](../RPD.md) · [SPEC](../SPEC.md) · [源码核对](../SOURCE_AUDIT.md) · [执行报告](../reports/N079-08.md)。

## 改造范围

正式消息提交和既有后台维护扩展、Companion Timeline/连续性候选投影、重启恢复与消费接线；完整 UI 和长期策略优化后置。

## 使用与提供的接口

唯一提交事件、pairing、session/turn/messageId、来源版本、operationId、现有 queue/lease、Pack 版本。

## 实施步骤

成功提交的对话通过 ID-only outbox 幂等投影 Companion Timeline，并通过独立 ID-only 候选 outbox 将符合保守规则的用户原话写成 Wiki/Soul 候选。新安装时先建立 History 高水位，不回填旧消息；候选引用确切的 `history:<messageId>`，仅接受明确的一人称偏好/目标，过滤敏感内容，重复恢复按稳定 operationId 幂等。助手自述不会进入用户事实。

## 验收

正式 BackendSession→保存 hook→候选 outbox→审核候选→下一轮连续性读取；验证不回填、重启恢复、重复恢复、明确来源、手动晋升、候选撤销、History 到期后候选与已晋升记录一起撤销/脱敏；单轮仅一份 Dialogue 请求，后台不阻塞文字回复。

## 完成与交接

Timeline 与候选子路径均已接入正式保存回调，并通过合成 SQLite 自动测试。仅候选持久化和安全不变量获自动验收；没有宣称候选语义质量或长期效果经过人工评估。依赖长期事实的主动陪伴仅可消费显式审核晋升的事实。

执行证据见 [报告](../reports/N079-08.md)，其中记录基线、改动、测试/真实证据、用户审核与遗留项。
