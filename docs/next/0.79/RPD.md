# Aika Next 0.79 RPD：进入 0.8 前的修复与兼容基线

版本：0.1；日期：2026-09-23；状态：规划完成，未实施。审查基线：`3ade2be`。本轮只审查、运行定向验证和编写文档，不修改产品实现。

目录：[目标](#1-目标与结论) · [范围](#2-本版范围) · [需求](#3-需求与验收映射) · [接口](#4-接口与兼容约束) · [实施](#5-实施与用户审核) · [门槛](#6-进入-08-的门槛)

## 1. 目标与结论

版本顺序：**0.7 → 0.75 → 0.79 → 0.8**。0.79 是 0.8 前的修复轮，接收 0.75 的五项现场问题和本地时间问候，并修复源码核对发现的直接影响后续数据正确性的缺陷。

用户允许知识库/记忆长期观察及尚未完成的 UI 互动继续后置，不要求本轮补完全部 0.7/0.75。**这不等于确认所有 MVP 已经存在，也不等于保证后续零破坏。** 本次结论是：0.7 核心模块和受控文字路径存在，正式 Context 读取已有接线；自动连续性投影、部分管理入口、可选包交付与长期质量仍不能算整版完成。详见 [MVP 与代码复核](SOURCE_AUDIT.md)。

本版出口是有证据的兼容基线及清楚的延后清单。0.8 无依赖的临时观察/协议模块可独立推进；涉及长期记忆的主动陪伴须先通过本版对应数据门槛。

### Trace 正文需求的实现方向

保留默认 Trace 日志脱敏，不因“个人使用”默认永久复制全部正文。优先由鉴权管理端用稳定 messageId/scope 从既有 History 权威按需读取，界面切换只决定是否显示；不能从 SHA256 digest 解密。已遗忘/清理内容不得靠 Trace、缓存或调试副本恢复。旧 Trace 无稳定关联时显示原因，不按模糊时间猜配。若另需持久明文调试，单独显式 opt-in、限定留存/清理和导出规则，不作为本需求的默认解法。

### 时间问候的产品约束

由本地时段和应用内交互间隔选择模板，只发轻量提示，不进入普通对话/记忆提炼流水线。没有观察到的行为不能写成事实；例如深夜可问“还没睡呀？”，不能断言“你工作了三小时”。零 Token 指模型调用为零，不承诺物理零延迟。

复用已有邀请配额/冷却/勿扰语义；不让 renderer 定时器和 0.8 邀请各自抢气泡。展示优先级建议为用户回复/错误高于主动提示；具体时段、频次、停留时长、文案和初始开关状态在实施前确认。之前文档的 6～8 秒仅为提案，不自动视为用户已批准。

## 4. 接口与兼容约束

- Memory 遗忘复用 POST `/api/memory/forget`，按现有 DTO 传 characterId、id、expectedVersion、reason；Continuity 遗忘使用其 pairing/targetId/operationId 契约，不混用 ID 空间。不能通过前端删行代替生命周期。
- Trace 正文关联接口为待设计增量，实施时固定 method/DTO/权限、删除状态与日志规则；现有 `/api/traces` 不直接扩成任意 DB 查询。
- 情绪页继续校验实例、角色、版本、来源权限，不能为消除 loading 接受跨作用域内容。历史字段兼容与数据损坏分开处理。
- presentation 复用现有资源白名单、同源加载和独立预览适配；检查实际 core/model/texture/shader 请求，不能开放任意本地文件路径或修改桌宠渲染引擎。
- 所有 schema 变化增量迁移；兼容旧库、暂停后台时恢复、冲突拒绝与回退；不为 review 打开或迁移真实用户库。
- 0.8 Observation、邀请和 Work 均沿用当前 scope、取消、来源版本及输出权威；未知能力返回 unavailable，不能创建空 Runtime 充当已运行。

## 5. 实施与用户审核

执行入口为 [SPEC](SPEC.md)，拆成 N079-00～09。界面修改必须按用户既定流程：**先问“XX 前端要改成什么样”→收到回答→索取参考图→确认复现范围→修改→主动展示效果请用户审核→不通过继续修改→明确通过再进入下一页**。允许用户明确沿用先前参考；已有具体反馈不用重复询问。此轮写规格不等于已经获得所有页面的实施参考。

只做业务逻辑/接口的步骤可独立执行；涉及可见文案、布局或新增开关仍过上述门槛。尚未开始的 SPEC 统一 NOT_STARTED，页面参考状态单独记 WAIT_REQUIREMENTS/WAIT_REFERENCE，不提前创建 PASS 报告。
