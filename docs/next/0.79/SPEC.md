## 1. 执行纪律

每步先固定源码和真实接口，复现问题，再最小修复和定向验证；业务未接通不能用 UI fixture 换成功。所列前置是技术依赖，不是要求把全部旧版人工验收先清零。

所有界面单独经过：问用户要改成什么样→随后索取参考图→确认本页复现范围→实现→主动提交审核→返工复审→明确通过后进入下一页。现有明确要求可沿用，参考图是否沿用由用户确认；本轮未启动任何页面改造。

## 3. 排期与完成定义

建议先 00→01，08 的非 UI 生产接线可随后优先完成；页面按 02～07 逐一向用户取参考并审核，最后 09 收口。用户可调整页面顺序，但不能绕过数据/接口前置。

每步报告区分 IMPLEMENTED（代码）、WIRED（正式消费者）、EXPOSED（实际接口）、自动验证和用户审核，不把一个 PASS 泛化成全部完成。源码修复未执行、长期观察未跑、截图未审核均不得填通过。

0.8 的独立 adapter/临时观察开发不必等待全部 UI；但依赖长期连续性的功能必须先通过 01/08，实际发布/联合交付须通过 09 对应门槛。延期项记录能力开关、影响和复验条件，不能静默启用。
