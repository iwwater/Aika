## 0. 2026-09-23 复核勘误与收口校准

依据 2026-09-23 代码 review（`investigations/20260923-review/README.md`）及自动化复现探针（`results.txt`），此前报告结论作如下勘误与校准：

1. **唯一启动链偏离（RV75-01）**：虽然代码确立了 `trial-backend.ts` 为正式组合根，但实际联调仍由 `dev-desktop-real.mjs` 传 `--preview` 启动 `real-backend.mjs`，管理端由 `serve-management.mjs` 独立启动。必须由唯一入口生成并分发统一 Management Session，桌宠与控制台共同指向同一实例（进入 **RP75-01**）。
2. **连续性在途失效缺口（RV75-02，已复现）**：T6 仅覆盖了旧 `memory_records` 的纠正失效，未覆盖 `continuity_facts` 遗忘；当用户在对话在途遗忘 User Soul 后，`assertContextCurrent()` 仍返回有效，导致在途回复继续输出旧事实。必须将连续性来源与修订纳入当前 Context 校验（进入 **RP75-02**）。
3. **Trace 阶段隐私与时序丢失（RV75-03/05，已复现）**：T8 仅断言了 `user_text` 与 `reply_text` 脱敏，未对 `stages.details` 实施白名单脱敏，导致私密记忆仍以明文存入 Trace details；且后台先于前台完成时 Trace 阶段丢失。必须实行安全白名单并解耦时序（进入 **RP75-03**）。
4. **Host/Flow 未真实注入（RV75-04）**：组合根未传入实际 PackageHost/Flow 实例，管理端退回新建空 FlowRuntime，未能代表真实运行态。正式路径需接入真实宿主，未接入时返回明确 unavailable 而非空对象（进入 **RP75-04**）。
5. **归因撤回**：撤回“100% 确认属于服务商问题”的断言，保留安全错误码与状态；撤回“4.6 秒播放完毕”的无音频回执断言，明确区分文字到达与音频回执。

## 1. 目标与执行边界

N075-01 目标为**彻底收口运行时真相（Runtime Truth Repair）**，确保前端 0.75 各页面改造前，后端具备唯一的生产运行时、真实消费 0.7 连续性、合规的异步记忆提炼生命周期、端到端阶段级 Trace、真实上下文快照检视与平滑 Provider 适配。

- **范围聚焦**：LLM、Memory、Continuity、Provider、Trace、Runtime wiring；
- **严格越界防御**：STT / TTS 核心声学逻辑不做非必要改动；
- **单模型单对话调用（Single Dialogue LLM Call Invariant）**：一轮对话仅有一份完整的 `DialogueContext`，由单次对话 LLM 调用消费，禁止建立第二条对话推理管线；
- **时序不变式（Timing Invariants）**：
  1. 用户发言（Raw Transcript）：优先立即持久化落库；
  2. 连续性与前台 Context：仅消费已提交状态；
  3. 普通事实提炼（Memory Distillation）：后台异步执行，绝不阻塞前台回复；
  4. 纠正/遗忘/不确定请求：立即触发 Pending 隐私保护屏障；
  5. 长期记忆写入：严格走 `MemoryTurnPlan` → CAS/版本校验 → `commitTurn()`，彻底禁止 direct SQL 写表。
