## 1. 目标与不变边界

保留已有 0.75 外壳、正式 Context 适配和既有 Memory 生命周期。先让桌宠、控制台、API 配置、记忆和诊断共同指向一个真实运行实例，再逐页重写。不能靠扩充实验脚本、复制配置权威或硬编码正常状态完成“接线”。

保留桌宠 renderer/模型/动效，不借修复改表现引擎。右键继续保留并减负；顶栏切左侧栏保持 TODO。知识库可看可删、轻量回复展示和 Trace 前后台区分纳入对应步骤；未获用户确认的漫画样式、位置、动画、超时数值先留白。

所有界面修改（包括总览错误文案、右键错误反馈和 Trace）仍按：**问“XX 前端要改成什么样”→等用户说明→索取参考图→确认复现范围→重写→提供实际效果主动请用户审核→不通过继续修改→明确通过才进入下一界面**。已有具体修改意见不用重复询问，但当前要改的内容与是否沿用原图必须明确。后端修复不以此为由重画 UI。

## 2. 修复步骤

### RP75-00：校准基线、证据与验收状态（文档步骤）

- 关联：N075-00/01/02、现场 Q1～Q7。
- 范围：SPEC、CONTRACTS、N075-01/02 报告与现场归因；保留原始记录，新增勘误和最新状态，不覆盖用户已认可的初稿。
- 动作：将“已实现”“已接线”“已暴露”“用户已审核”逐项分开；撤回证据不足的“100% 上游”“4.6 秒播放结束”“全部运行时收口”。补真实截图/脱敏阶段事件的可核对引用，缺失就标未提供。
- 验收：文档各处状态一致；模块测试不冒充启动器验收；每项问题映射一个后续步骤。

### RP75-01：恢复唯一生产启动与管理会话（首要接入修复）

- 关联：RV75-01/08、Q1/Q7，N075-01/02/03。
- 范围：dev-desktop-real、正式启动脚本、Electron backend 选择与 management session、管理 bootstrap；仅保留隔离样本用的 serve-management/real-backend harness。
- 动作：确认正式配置生成/激活要求后启动 trial-backend；管理服务由同一实例发布随机凭据和身份。统一数据库/配置/皮肤目录，以正式解析规则为准，不手填路径猜测。实验服务不用真实个人 DB，也不发布生产身份。
- 接口：BackendConnection、PET_TRIAL_CONFIG/activation、management-session、managementUrl、snapshot runtime identity；不绕过已有路径权限及身份校验。
- 验收：真正启动入口→桌宠 ready→右键打开→同实例 snapshot；控制台保存配置后该运行实例按既定生效规则更新。覆盖会话过期/重启/服务未就绪/preview 拒绝；禁止只测 URL 拼接。presentation/knowledge/continuity 通过该组合根验证，可选能力缺失返回明确 unavailable。

### RP75-02：补连续性在途失效与正式提交关系（隐私优先）

- 关联：RV75-02；0.7 N07-04/05 与 N075-01/08/09。
- 范围：ProductionContinuityContext、SqliteLifecycleMemoryPort/issued context、continuity Store 管理变更和唯一轮次的输出/播放校验。
- 动作：Context 绑定配对、Pack、连续性修订及来源；在模型前后、assistant 提交和播放时校验。遗忘/纠正/撤销后当前回复不可继续暴露旧事实。源数据派生的既存条目与重建任务一并核对，不能只挡旧 lease。
- 后续核实：将正常消息提交到 Companion Timeline、候选 Soul/Wiki/关系的投影接到既有提交/维护链；幂等、可恢复、有证据。若这部分仍未实现，就保留 0.7 对应项未完成，不在 UI 中虚构自动沉淀。
- 验收：先用 review 复现建立失败用例，再验证在途遗忘/纠正/换 Pack/撤来源和取消输出；跨实例不串，重启不恢复已撤内容；普通记忆和连续性两套来源均测。

### RP75-03：Trace 隐私、时序与失败语义

- 关联：RV75-03/05，Q5/Q6；N075-01/12。
- 范围：trace-store、dialogue-pipeline、memory-lifecycle-queue、ProviderTransport 的安全诊断数据，不先改 Trace 布局。
- 动作：阶段 details 白名单脱敏，record/appendStage 一致；轮次开始登记、后台可先写且幂等；阶段含开始/结束和前后台归属，规划/提交不复用一个累计耗时。记录失败发生阶段、取消和未执行状态。
- Provider 错误：保存可用且经过脱敏的 error code/type、requestId、HTTP/流状态和时点；不以总耗时推断供应商网络根因。重试/超时须沿用取消、预算和幂等语义，不自动无限重试。
- 验收：后台快于/慢于前台都不丢 Trace；失败不显示伪回复或伪成功；默认存储中没有用户/召回/提炼正文；时间区间能解释重叠。历史 Trace 敏感副本先设计迁移/备份方案，本步骤验收不直接清用户库。

### RP75-04：Host/Flow 与 Provider 管理真值

- 关联：RV75-04，N075-01/04/11。
- 范围：trial-backend、Next65Management、实际 PackageHost/FlowRuntime/ProviderRuntime 绑定。
- 动作：管理端读取实际运行实例；没接入的 Host/Flow 返回不可用而非空实例。核实配置保存与实际执行采用同一 Binding；保留 legacy adapter 作为兼容入口，不增加新 registry。
- 验收：真实加载/禁用包和 Flow 变化在管理端可见，错误/待重启不同于未安装；管理读取不启动未选择引擎；Provider 两来源和实际生效修订可验证。

### RP75-05：控制台错误与总览数据正确性

- 关联：RV75-06/07，N075-02/12。
- 范围：app read helper、modern-overview 应用状态和数据投影。
- 动作：修正错误 epoch 判断；绑定请求序号/作用域/实例；刷新和鉴权变化使缓存失效；使用实际总数，不用分页样本长度；加密/同步/健康只能显示有证据的状态。
- UI 门槛：实施前问本页调整要求，请用户提供或明确沿用参考图；对“未知/离线/不可用”具体呈现取得确认。功能修复与风格重设计分开验收。
- 验收：401、网络失败、空库、部分模块失败、旧会话迟到响应、刷新后数据变化；有 100 条记录时不能显示 10 条为总量；不展示无依据的“已加密同步”。

### RP75-06：知识库可看、可删闭环

- 关联：Q2，N075-10；先复用已存在的删除实现。
- 范围：knowledge-library、knowledge-routes、knowledge-view；新增受鉴权的正文查看/受限分页或分块投影，不把绝对路径暴露给浏览器。
- 动作：先盘点现有元数据/正文/selection，再补文档检视。删除提升修订，当前和在途 Context 失效；若未来增加持久化索引，必须同一删除链清理，不提前创建索引当修复。
- UI 门槛：先问知识库前端改成什么样，随后索取参考图；确认列表、正文、删除影响提示，再实现、主动提交审核。
- 验收：不同 libraryId 隔离；删除后列表/检索/后续和在途请求均不复用内容；冲突/失败可见，失败不从 UI 假删除。明确逻辑删除与备份/物理擦除范围。

### RP75-07：思考状态与无需大抽屉的回复体验

- 关联：Q3/Q4，N075-15；依赖真实入口及取消/失败语义。
- 范围：桌面聊天呈现、轻量回复层、thinking 指示器和窗口 UI 边界；不改 Cubism/口型/动作引擎。
- 动作：先问期望交互并索取参考图；确认回复位置、长文处理、停留/关闭、历史入口、键盘可达、窗口缩放/多屏、点击穿透关系后逐个实现。独立回复层不强制展开历史抽屉。
- 状态：thinking 由真实当前轮次驱动；超时/取消/断线都有终态，旧请求不得点亮新一轮气泡。不能靠隐藏指示器宣称请求已结束。
- 验收：回复可直接看、历史仍可打开、超时/断线/快速连续发送不挂住，缩放不遮挡关键区域；演示给用户审核，通过后再进入下一界面。

### RP75-08：Trace 界面与右键收尾，真实联调复验

- 关联：Q1/Q6/Q7，N075-03/12/14/16。
- 顺序：先右键错误反馈/减负界面，再 Trace 页面，最后受影响设置页面；每个界面独立问要求、取图、实现、审核，不能合成一次批量批准。
- Trace 接口消费 RP75-03 的真实时间数据，区分请求/文字/播放/后台；没有播放回执就显示未采集，不推测播报时间。
- 右键只迁入口，不删功能；表情动作/知识库/记忆等用真实实例 API 验证。其余未确认页面继续保留 WAIT_REQUIREMENTS。
- 验收：按完整现场 Q1～Q7 回放，留存脱敏运行身份、步骤、截图和错误证据；N075-02 的外观认可与启动接入分别结案。

## 3. 逐界面需求与审核安排

| 界面 | 已知需求 | 实施前还需要用户决定 |
| --- | --- | --- |
| 控制台外壳/总览 | 既有初稿曾获认可；侧栏切换仅 TODO | 正确数据/错误状态怎样呈现，是否沿用原参考 |
| 桌宠右键 | 保留、减负、功能可达 | 哪些快捷操作保留、分组与错误反馈参考图 |
| 知识库 | 查看文档内容、删除后不再被使用 | 列表/正文/删除交互参考图 |
| 轻量回复与思考提示 | 看回复无需大抽屉 | 位置、风格、长文与消失规则参考图；不默认漫画气泡 |
| Trace | 前后台分开、错误可解释 | 指标、时间线/详情的参考图；不使用未经采集的音频时长 |
| 表情与动作设置 | 能调用实际管理能力 | 现有错误修复与后续页面重写分别确认；表现引擎不改 |

## 4. 验收与停止条件

先按 RP75-01～04 修运行身份、隐私、Trace 和管理真值，再进入依赖这些数据的页面步骤。每个修复有定向失败→通过证据；改变公共生命周期才扩大到关联文字/语音/后台回归。继续保留现有 next07/next075 用例，不能删断言换通过。

新增门槛必须测真实组合根/启动器或实际装配对象；外部服务可 stub，不能手动组装缺失依赖后声称正式入口通过。`test:next075` 7/7 只是回归之一。

界面没有参考图/用户明确豁免，不实施该界面；用户未审核通过，不进入下一页。真实云调用、设备、真人操作未进行就记 NOT RUN；0.65 原 32 项不自动清零。

## 5. 最终 review 结论

**主方向可继续，当前实现与完成声明存在局部但实质性的偏移。** 最优先是唯一运行入口、连续性失效和 Trace 隐私；其次修 Host/Flow 接线、错误反馈和数据真实性，再按用户参考逐页交付。已有初稿无需推倒，不能继续在实验入口上堆修复，也不能将全部问题归给上游服务商。
