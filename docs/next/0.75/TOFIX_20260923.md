## 一、待修复问题与缺陷定位 (Issues to Fix)

### FIX-01：Trace 界面默认全脱敏导致用户看不见具体对话内容
- **现象**：Trace 界面用户和 Aika 的正文全显示为 `[digest:670d9743 len:2]` 和 `[digest:a72c65f8 len:21]`，用户无法核对真实问答内容。
- **定位**：`core/dialogue-pipeline.ts:240` 与 `core/trace-store.ts:112`。生产管线默认 `traceDebugOptIn: false` 将 `userText` 和 `replyText` 强制转为 sha256 digest。
- **修复**：
  1. 在个人桌面/本地试用运行态中，支持记录真实对话正文（或在管理端鉴权后解密展示）；
  2. 在 Trace 界面增加“显示正文明文 / 脱敏摘要”一键切换按钮，满足自用查验需求。

### FIX-02：长期记忆详情界面缺少“删除/遗忘”按钮与删除执行失败问题
- **现象**：
  1. 此前在 `角色 -> 记忆 -> 长期记忆详情` 中，只有“保存这条记录”，未提供删除/遗忘入口。
  2. 补上删除按钮后，用户现场点击「确认遗忘」依然删除失败，页面连续弹出两条红色警示条：`严格来源处理未完成，尚未执行遗忘。请稍后查看或重试。`，下方记忆列表丢失，UI 报错。
- **深度定位**：
  1. **后端模型依赖与无效模型阻断**：当记忆属于带有会话来源的提炼记忆（如 `mem-interactive-habit`）时，系统底层强制进入 `StrictManagementForget` 走模型来源规划；该链路绑定的 `memory_turn` 服务当前配置为 `deepseek-v4-pro`（云端实际不存在该模型 ID），导致模型规划直接抛错触发 `unavailable: 严格来源处理未完成，尚未执行遗忘`，硬性阻止了删除事务。
  2. **前端连接状态误降级与错误双重渲染**：当接口返回 503 时，`app.mjs:249` 执行了 `if (!e.status || e.status >= 500) s.connection = 'offline'`，将全局状态误判为 `offline`，触发全局 `main` 与局部视图同时渲染错误横幅（导致错误条重复出现两次）；且后续操作因 `s.connection !== 'online'` 全部被锁定。
- **后续优化方案**：
  1. 在后端 `StrictManagementForget` 引入无模型直接遗忘降级机制，当外部 LLM 不可用或模型 ID 不存在时，保障用户对记忆的绝对删除控制权；
  2. 区分单次业务错误与全局网络离线，避免 500/503 业务错误使整页连接状态掉线；
  3. 统一全局消息条，避免错误提示重复渲染。
- **状态**：**已定位深层根因与连锁 UI 缺陷，待后续版本系统性重构遗忘生命周期（记录入库）**。

### FIX-03：当前情绪卡在“正在读取情绪记录…”
- **现象**：切换到 `角色 -> 记忆 -> 当前情绪` 时，一直停留在 loading 状态无法展示。
- **定位**：`management/ui/emotion-view.mjs:33` 中的 `accept` 校验包含严格的 `v.messages.every(...)`，当历史中某些消息的 background 观察字段为 null 或结构不完全匹配时抛出 `Invalid emotion response`，导致进入错误重试或卡在读取。
- **修复**：增强 `emotion-view.mjs` 的数据容错与防崩处理，安全降级为空观察展示，正确呈现用户当前情绪与桌宠当前心情。

### FIX-04：Live2D 表情与动作预览空白看不了
- **现象**：进入 `角色 -> 表情与动作`，画布空白，无法查看动作与表情预览。
- **定位**：`management/ui/presentation-view.mjs` 中的 Live2D 画布初始化依赖 `cubism` core 脚本与相对路径，而在管理后台独立视口中未正确挂载全局 Cubism 渲染器或资源路径映射错误。
- **修复**：排查并修复 `presentation-view.mjs` 与预览容器的初始化接线，确保模型正常渲染。

### FIX-05：配置页面服务地址输入框样式重叠与栅格溢出
- **现象**：`配置 -> 对话大模型 / 语音合成 TTS` 编辑界面中，模型选择下拉框与超长服务地址（如 DeepSeek/百炼长 URL）发生视觉重叠，未自适应换行截断。
- **定位**：`management/ui/style.css` 缺少自定义选择控件 `.choice-trigger`、`.choice-value`、`.choice-menu` 样式规则，且 `.form-grid` 未设 `min-width: 0` 和 `box-sizing: border-box`，长文本按钮强制撑宽单元格。
- **修复**：在 `style.css` 中补全 choice 下拉触发器 flexbox 截断样式与弹出层规则，设置 `.form-grid > * { min-width: 0; }`，彻底解决各配置表单的栅格重叠和文本溢出问题。
- **状态**：**已修复**。

### FIX-08：角色与 Pack 管理页面（characters）显示正在准备中占位
- **现象**：点击进入 `角色 -> 角色与 Pack 管理`，页面显示空白卡片 `页面 "characters" 正在准备中...`，无法进行任何操作。
- **定位**：`management/ui/app.mjs:848` 路由分支尚未实现 `charactersView`，直接进入兜底占位分支。底层虽然已有 `CharacterPackStore` 等数据结构，但管理控制台前端视图缺失。
- **后续规划**：在 0.8 专题中完整落地 `characters-view.mjs`，支持角色底色配置、Pack 本地导入、人设关系网展示与版本平滑升级。
- **状态**：**待后续版本实现**。

### FIX-06：自助设置状态校验误报“暂时无法核对自助设置状态，操作已停用，请刷新”
- **现象**：在 `配置 -> API 与模型` 页面顶部出现黄色警告条，提示“暂时无法核对自助设置状态，操作已停用，请刷新。”，导致自助设置操作被禁用。
- **定位**：`self-setup-view.mjs:44` 的 `accept(value)` 快照校验中，硬编码要求所有已注册 adapter 的 provider 必须命中 `[{value:'deepseek'}, {value:'dashscope'}]`；当系统注册包含 `gemini-text` 等扩展 adapter 时，校验抛出 `Invalid setup snapshot` 触发异常降级。
- **修复**：将 adapter 与 credential 的 provider 校验调整为合法非空字符串校验，支持更多已登记来源；并在前端下拉中扩展 Google Gemini 等选项。
- **状态**：**已修复并通过浏览器自动化验收**。

### FIX-07：桌宠启动状态停滞在“正在装配对话服务 2/4 · 1 秒”
- **现象**：桌宠启动或非正常退出后再次启动时，界面文字停滞在 `正在装配对话服务 2/4 · 1 秒` 不再推进。
- **定位**：`app/trial-backend.ts:252` 使用独占标志 `wx` 打开 `backend.lock`，若此前后端异常退出留下孤儿锁文件，新进程在装配第 2 步抛出 `EEXIST` 崩溃退出，导致前端连接停滞在装配态。
- **修复**：在 `trial-backend.ts` 中增加孤儿锁自动探测与恢复机制（检查锁内 PID 是否存活，若已死则安全清理并重新占锁）；`emitStartup` 完成阶段推进到 `ready 4/4`。
- **状态**：**已修复**。

### PERF-01：桌面端点击打开控制台响应慢（卡在“打开中…”）
- **现象**：桌宠悬浮窗点击“控制台”后，按钮显示“打开中…”需数秒才弹出页面。
- **定位**：`tools/management-url.mjs` 每次调用均执行 `isPrivateFileSync`（在 Windows 上每次通过子进程启动 `powershell.exe` 解析 ACL，耗时 1.5~3 秒），且拉取完整的 `/api/snapshot`。
- **修复**：在 `core/platform-files.ts` 和 `management-url.mjs` 中增加基于文件 `mtimeMs/size` 的私有权限校验缓存与活跃 session 缓存，避免重复启动 powershell，点击控制台实现毫秒级响应。
- **状态**：**已修复**。

## 二、新增特性要求 (New Feature)

### FEAT-01：基于本地时间的零模型轻量主动问候
- **需求**：桌宠可主动感知当前系统时间，不调用大模型（0 费用、0 Token、即时响应），在用户长时间工作或特定时间节点主动弹出气泡问候（如深夜 `2:09 还没睡呀？`）。
- **设计**：
  1. 在桌面宠物端（`desktop/main.mjs`）引入轻量主动问候状态机；
  2. 根据本地时段（深夜、早晨、中午、下午、傍晚）和最近交互间隔生成暖心短语；
  3. 通过已落地的头部浮动气泡（`#speech-bubble`）优雅弹出，展示 6~8 秒后自动淡出。

### FEAT-02：凭据多源别名管理与模型分工灵活选用
- **需求来源**：用户现场验收明确指示（见配置管理规划图 6）。
- **具体设计**：
  1. **多 Key 别名登记**：支持在凭据中心登录多个 API Key，用户可赋予直观的自定义命名或编号（如“1”、“2”、“3”，或用途标签“主对话用”、“语音专用”、“低成本测试”等）；
  2. **明确模型分工插槽**：将系统所需模型严格按能力分工（LLM 对话主模型、STT 语音转写模型、TTS 语音合成/音色模型、视觉情绪/感知模型、记忆自动提炼与维护模型）；
  3. **自由绑定与映射**：在各个服务模块下方，用户可针对该分工自由选用具体模型，并一键绑定对应命名/编号的 API Key 凭据，实现多供应商、多 Key 的清晰分工与账目隔离。

### FEAT-03：自然语言智能驱动的记忆批量维护与数据表清理对话框
- **需求来源**：用户现场验收明确指示（见配置管理规划图 6）。
- **具体设计**：
  1. **批量维护对话框**：在配置页或记忆库管理界面嵌入一个专属的轻量对话框；
  2. **自然语言指令解析**：允许用户直接输入自然语言指令指挥大模型（例如：“帮我删掉关于XX的所有数据”、“清理7天前产生的所有闲聊记忆”、“把包含YY的记忆纠正为ZZ”）；
  3. **记忆数据表安全维护**：大模型根据指令调用结构化的维护与遗忘生命周期（`/api/memory/forget`、`/api/records/edit`），对底层长期记忆数据表进行批量定向清理、冲突校验与事务性提交，提供直观的受影响记录预览与撤销保障。

### FEAT-04：API Key 保存处增加自定义端点与在线可用模型动态拉取
- **需求来源**：用户现场验收明确指示（见保存 API Key 界面图 1）。
- **具体设计**：
  1. **自定义服务端点输入框**：在 `配置 -> API Key 与自定义音色 -> 保存 API Key` 区域增加「服务端点 / Base URL」配置项（支持默认官方地址如 `https://api.deepseek.com`，允许用户自定义为第三方代理、中转或局域网私有化部署地址）；
  2. **动态获取可用模型**：在 API Key 保存与编辑表单旁提供「获取当前可用模型」按钮，点击后使用当前填写的 Key 与端点发起轻量模型探测请求（如 `GET /v1/models`），动态展示该账户实际开通和可调用的模型列表下拉栏；
  3. **选择并一键绑定配置**：支持从拉取到的模型列表中直接勾选/选择目标模型，并一键保存绑定到下方对应的对话或后台服务插槽中。
