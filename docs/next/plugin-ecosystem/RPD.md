# Aika Next RPD · Companion Capability Runtime 改造与插件生态

状态：PLANNED（长期架构需求；未排入现有版本 SPEC）  
优先级：P1  
更新日期：2026-09-24  
目标版本：待排期；在 Aika Next Core 的基础文字闭环和包生命周期稳定后实施

本 RPD 定义从“可导入能力包”走向“可组合的陪伴 Agent Runtime”的改造目标：插件能力、受控扩展点、逻辑资源访问、事件触发、后台维护与最终分发。它不改变 [0.65 RPD](../0.65/RPD.md) 已确定的内核与能力包边界，也不把插件市场追加入 0.65～1.0 的现有验收范围。实施状态以届时的 SPEC、报告和生产接线证据为准。

需求来源为用户引用的 [FaustBot 项目分析对话](chatgpt-conversation://6ab5123c-7280-83e8-878e-f38c06b77cb9)。对话是设计输入，其细节不是 Aika 的实现证据。已核对 [FaustBot 官方仓库说明](https://github.com/liwusen/FaustBot-llm-vtuber) 与 [Gesellschaft 仓库说明](https://github.com/liwusen/gesellschaft)：两者分别公开描述了插件、Agent、Desktop Mood、Trigger、后台记忆维护，以及暂存、审阅、批准后安装的市场流程。具体 Hook/VFS API 与安全保障仍须在实施前按上游源码和 Aika 当前代码复核。

## 1. 背景与目标

当前架构已把内核、普通产品包、可选能力包分开，并定义了包发现、导入、Provider、Flow Profile 和受限事件契约。下一步需要让用户像管理扩展一样完成安装、启用、配置、选择和移除，而无需改源码或重装整应用。尤其是插件提供的设置入口、工具和能力必须随插件状态出现或消失。

产品目标是将 Aika 建成以陪伴为中心的 Agent Runtime + Plugin Ecosystem：内核掌管会话轮次、Agent 流程、状态与生命周期、受限事件通道、插件管理和 UI 宿主；记忆、STT、TTS、视觉及角色能力由可选包提供。普通文字聊天仍由最小普通包提供，长期 Memory 不是基础聊天的隐式前置条件。语音、记忆、角色和陪伴体验是产品主线；VFS、Trigger 和后台任务服务于这条主线。

| 目标 | 用户可观察的结果 |
| --- | --- |
| 能力按需获取 | 仅安装所选包及依赖；未选能力不启动模型、进程或采集 |
| Provider 可替换 | 同一能力可有多个提供者，用户按场景或阶段显式选择 |
| UI 随包注册 | 启用插件后出现其设置页、面板或状态项；停用后不再提供操作入口 |
| 插件可协作 | 插件通过有版本、受作用域约束的事件或公开能力接口协作 |
| 资源可统一查阅 | Agent 可按权限读取/搜索 Character、User、Timeline、Wiki 及插件资料的逻辑视图；原存储继续拥有事实 |
| 主动陪伴可控 | 已授权事件经过策略筛选后才可唤醒或邀请；后台维护不阻塞实时语音 |
| 可治理的生态 | 安装来源、兼容性、权限、数据去向、更新和恢复均可见 |

| 对标点 | Aika 的取舍 |
| --- | --- |
| FaustBot Plugin Hook 与自带 UI | 借鉴扩展点和随包出现的设置；只开放有版本、可限权的 Hook，不开放任意修改核心状态 |
| VFS | 建立逻辑资源投影与统一 `read/search`；不搬迁 Wiki/Timeline 的权威数据，也不让通用 `write` 越过业务维护入口 |
| Desktop Mood / Trigger | 复用 0.8 事件、邀请、配额与勿扰；新增的桌面来源必须逐项授权 |
| Subagent / Araya | 复用已有后台 Memory 队列与 0.85 编纂；需要时增加受限工作者，不复制第二条维护链 |
| Gesellschaft | 借鉴“暂存 → 查看 → 批准 → 启用”的门槛；市场、Agent 自动写/发布能力和 AI 论坛分别排期 |

## 2. 范围与分期

| 阶段 | 产品范围 | 前置条件 |
| --- | --- | --- |
| Phase 1：内部 Capability Runtime | 在现有 0.65 包契约上补齐代表性 Memory/TTS/STT 接线、显式绑定与受控 Hook；以一个只读资源视图验证逻辑资源访问；本地导入即可 | Core 文字闭环、包生命周期和公开 SDK 可用；核对现有事件、Memory 队列与资源读取入口 |
| Phase 2：动态 UI 与陪伴扩展 | 插件声明设置页、面板、状态和配置；按已交付的 0.8/0.85 能力接入授权事件 Trigger 与后台维护任务；扩展资源视图到实际需要的域 | Phase 1 状态权威稳定；0.8 事件/邀请和 0.85 来源/遗忘链的相关门槛通过 |
| Phase 3：Capability Hub | 浏览、暂存、审阅、安装、更新、移除经过验证的包；展示来源、版本、依赖、权限、资源、兼容性和更新信息 | Phase 1/2 验收；分发信任、回滚与运行权限强制执行在独立 SPEC 中确定 |

Phase 1 是对 0.65 能力包机制的产品接线与补齐，不再造插件加载器、Event Bus 或 Memory 生命周期。阶段内每条能力可分独立 SPEC；不要求 VFS 成为语音/文字基础交互的启动前置。Phase 3 是单独排期的分发产品，不以本 RPD 自动授权联网下载、执行第三方代码、安装模型或调用付费服务。

本 RPD 不包含任意脚本配置、任意循环 Agent 工作流、运行中代码热替换、跨端同步或通用不可信代码沙箱。AI 论坛、Agent 自行编写/发布插件、通用知识图谱、大量并行 Subagent、游戏/直播集成都不进入本改造。具体包目录、UI 渲染技术和市场服务实现由后续 SPEC/ADR 决定。

## 3. 用户流程

### 3.1 安装与启用

用户进入“设置 → 插件”，从本地导入包；市场上线后也可从目录选择。安装前能看到包身份、版本、提供能力、依赖、兼容性、资源需求、权限与数据访问范围。宿主先校验包，随后登记为“已安装”；安装本身不等于启用、授权、加载或下载模型。

用户启用 Memory 插件后，“设置”中出现由该插件声明的 Memory 入口。若同类插件已存在，保留各插件独立配置，并由用户在相应 Binding 处选择当前提供者。TTS 插件可提供音色、语速等设置；STT 插件可提供模型、语言及输入设备设置。没有安装相应插件时，不显示空白功能页。

包缺依赖、缺模型、凭据失效或设备不可用时，界面区分“已安装”“已启用”“已加载”“就绪”“失败”“待重启”，展示具体修复动作。基础文字聊天仍可用。

### 3.2 使用、切换和移除

Agent 流程通过能力 ID 与显式 Binding 调用已选 Provider。用户更换 Mem0、MemU 或其他 Memory 提供者时，新轮次按新 Binding 生效；在途轮次保持原版本与配置，撤销访问或停止采集立即生效。找不到提供者、存在多个候选但没有明确 Binding、提供者未就绪时，给出可恢复错误，不按注册顺序静默选择。

停用前显示受影响的流程、依赖者和数据。停止新调用，完成或取消在途工作，释放资源，并撤下对应 UI 和工具入口。更新可要求重启切换代码，但界面须准确标出待重启状态。卸载默认保留用户数据；删除数据是单独、明确的操作。重新安装不得恢复已经撤销或遗忘的内容。

### 3.3 角色组合包

角色包可组合 Soul、Character Wiki、Voice、Avatar 和 Memory Style，并声明必需/可选依赖。安装角色包不自动替换全局用户记忆或对其他角色开放私有经历；角色实例、用户与来源版本仍决定数据作用域。缺少可选 Voice 或 Avatar 时，界面说明降级体验，角色文本能力可按包声明继续使用。

### 3.4 资源查阅、事件与后台任务

用户问“你还记得我上周说的目标吗”时，Agent 在当前用户×角色实例权限内搜索 User Wiki、Companion Timeline 或 Memory 的**逻辑资源视图**，按已有 Context 预算选择有来源的结果。`aika://user/`、`aika://character/`、`aika://timeline/`、`aika://plugins/<packageId>/` 可作需求示意；具体 URI、分页与查询语义在 SPEC 冻结。不存在的条目返回未命中，不能让资源 URI 绕过角色、剧情进度、授权、撤销或遗忘。写入仍通过各域现有受控 API 和候选/确认流程。

用户显式开启某类主动陪伴来源后，传感器产生带来源、时间、有效期及事实/推断标记的 Observation；现有事件通道投递后，由策略判断是否形成邀请。屏幕或前台窗口信息未授权时不采集；“检测到游戏事件”只是一条候选观察，不自动写成成就记忆，也不直接发起 LLM 或外部动作。用户可查看触发原因、暂停该来源、忽略邀请或撤销授权。

对话后的记忆去重、Wiki 编纂、角色资料整理等可进入已有后台维护路径。后台工作有任务 ID、来源快照、作用域、预算、取消和可见状态；实时语音链不等待它完成。用户纠正、遗忘或撤销来源时，受影响任务立即失效，迟到结果不得重新落库。

## 4. 产品需求

| ID | 需求 | 完成判据 |
| --- | --- | --- |
| PLUG-R01 | 能力发现与版本 | 宿主只读扫描包元数据，列出能力、契约版本、状态和依赖；扫描不得执行插件入口 |
| PLUG-R02 | 统一插件路径 | 内置与导入包经同一校验、注册、调用、释放路径；新增合规插件不要求修改内核业务分支 |
| PLUG-R03 | 显式 Provider 选择 | 同一 capabilityId 可有多个 adapter；Binding → ModelProfile → SourceInstance → Adapter 决定实际来源，不按安装先后覆盖 |
| PLUG-R04 | Agent 能力接入 | Memory 的检索/保存、STT、TTS、视觉和 Tool 通过公开契约进入现有 Agent/Flow；插件不复制轮次控制器 |
| PLUG-R05 | 配置与状态 | 插件配置有版本、校验、迁移和独立数据命名空间；凭据使用引用，不在 manifest 或 UI 配置中存明文 |
| PLUG-R06 | 动态 UI | 启用插件后按声明注册设置页、面板或状态项；停用、失败、更新时导航和操作状态与插件真实状态一致 |
| PLUG-R07 | 受控 UI 权限 | 插件 UI 只通过宿主公开桥接调用自身配置和获授权能力；页面入口不获得宿主私有对象或其他插件数据 |
| PLUG-R08 | 事件协作 | 复用现有受限事件通道；事件有版本化 schema、来源与作用域；消费者自行决定是否写入 Timeline/Memory |
| PLUG-R09 | Tool 注册与副作用 | 工具声明输入输出、权限、副作用和取消语义；需要外部动作的工具遵守用户授权及幂等提交边界 |
| PLUG-R10 | 生命周期与恢复 | 导入、启用、惰性加载、停用、更新、卸载及失败恢复与在途轮次和资源租约协调；失败不破坏基础聊天 |
| PLUG-R11 | 最小安装 | 仅内核 + 普通包时可完成文字聊天；Memory/TTS/STT/Vision 专用代码、模型和依赖可缺席 |
| PLUG-R12 | 市场分发 | 市场阶段提供可核验来源、版本兼容、完整性、依赖与权限展示、独立更新和回滚；未通过校验的包不可启用 |
| PLUG-R13 | 角色组合 | 角色包通过现有能力与数据契约组合 Soul/Wiki/Voice/Avatar，不借安装动作跨角色读取记忆 |
| PLUG-R14 | 受控 Runtime Hook | 只在已定义的 Agent/Memory/TTS/Tool 生命周期边界开放声明式订阅；固定顺序、超时、取消、错误隔离和副作用规则，插件不能改写轮次权威 |
| PLUG-R15 | 逻辑资源视图 | 注册有所有者、schema、作用域与访问策略的资源视图；统一发现、读取、搜索和预算；撤销后旧 URI 与缓存不可继续返回正文 |
| PLUG-R16 | Tool 与资源分流 | 纯查询优先评估资源视图；需要动作、事务或外部副作用时使用 Tool；固定样本证明工具 schema 和 Context 开销没有无界增长 |
| PLUG-R17 | 事件触发陪伴 | 已授权事件经去重、显著性、冷却、勿扰、配额和可追溯原因过滤后才形成邀请；接受邀请复用现有轮次 |
| PLUG-R18 | 后台维护工作者 | 复用现有 Memory 队列和 0.85 编纂链，支持受限异步任务的状态、预算、取消、幂等提交及重启恢复；实时语音不被后台工作阻塞 |
| PLUG-R19 | 市场暂存与审阅 | 远程包先暂存并显示文件、来源、权限与变更，再由用户批准启用；下载、安装、启用分成可观察状态 |
| PLUG-R20 | 权限强制执行 | 宿主公开 API 对文件、网络、麦克风、屏幕、进程、剪贴板、Memory 读写和 UI 扩展按声明与用户授权执行；撤销立即阻止新访问及有效迟到结果；第三方代码的进程级隔离另为市场上线门槛 |

## 5. 架构与契约边界

```text
用户输入 / Agent Flow
        ↓
现有轮次、Scope、取消与状态权威
        ↓
能力解析 + 显式 Binding ──→ 已选 Provider / Tool
        ↓                         ↓
受限事件通道 ←───────────── 插件事件
        ↓
Timeline / Memory 等各自的投影与存储

插件 manifest ──→ 校验/注册 ──→ UI Host 扩展点

原始存储 ──→ 授权投影 ──→ 逻辑资源 read/search ──→ Context 预算
授权 Observation ──→ 既有 Event Hub ──→ 陪伴策略 ──→ 邀请/后台任务
```

- **现有代码映射**：`contracts/plugin.ts` 已定义 `HostContext`、能力注册、受限事件和包私有数据；`core/companion-event-hub.ts` 是现有事件路由；`core/memory-lifecycle-queue.ts` 与 0.85 编纂需求承载后台记忆；0.8 的 `InvitationCandidate`/策略承载主动陪伴。以上是复用入口，不等于本 RPD 的所有 UI、Hook、VFS 和市场需求已接线。实施前须核对实际生产消费者。
- **包与插件**：包是交付单元，可以携带多个相关插件；插件是运行时扩展单元。沿用现有 `manifest.json`、`packageId`、`pluginId`、`hostApiRange`、能力声明、依赖、权限和文件 hash，不以示例中的 `package.json + plugin.ts` 取代既有格式。
- **Capability 与 Provider**：`memory.retrieve`、`memory.store`、`speech.to_text`、`speech.synthesize`、`vision.*` 等名称在实施 SPEC 中与现有词表逐项对齐。RPD 中的 MemoryProvider 是逻辑端口示例，不宣称当前代码已导出同名接口。现有五层多源契约保持权威。
- **Hook**：首批候选边界为输入接收、工具执行前后、Memory 读写候选、TTS 文本/播放和配置变更。Hook 注册属于插件契约，事件属于异步通知，Provider 属于被显式选中的能力，三者语义分别冻结；不能让可选 Hook 绕过安全守卫或把私密正文默认广播给所有插件。可改写型 Hook 默认关闭，逐项证明顺序、作用域和失败恢复后再开放。
- **Memory 数据**：近期会话、Timeline、长期 Memory 和 Wiki 各有职责。Memory 插件可提供检索和保存策略，但不能自动接管原有数据、绕过用户纠正/遗忘，或把观察事件无条件写成长期事实。切换提供者须说明旧数据的保留、迁移和检索范围。
- **逻辑资源空间**：`aika://` 是对现有权威存储的只读、按需投影视图。资源所有者负责列出、读取、搜索、版本和撤销，宿主负责 URI 路由、身份/配对权限及预算。全文检索、语义检索和图关系可由各 Provider 实现；本 RPD 不强制统一底层数据库或迁移到图存储。逻辑资源不能绕开现有 Context 筛选，也不能把所有结果一次性塞入 Prompt。通用 `write` 不属于首版资源接口。
- **事件**：复用 `HostEventChannel`/轮次订阅的现有边界；补齐实际投递、schema、错误隔离与用户×角色实例作用域。事件负责传递，持久状态仍由对应业务模块拥有。插件间不得 import 对方私有实现。
- **Trigger 与后台任务**：Trigger 是对已授权事件/时间条件的策略订阅，不能通过配置文本执行任意脚本。主动邀请复用 0.8 的冷却、勿扰、配额和展示仲裁；后台任务复用既有 Memory/编纂权威，额外的 Subagent 仅在有独立工作需要、明确权限与资源上限时作为可选执行器。实时 VAD→STT→Context→LLM→TTS 路径不引入等待后台 Subagent 的步骤。
- **UI**：manifest 声明位置、入口、所需权限和配置 schema。宿主提供导航、加载状态、错误边界和撤销入口。可执行 UI 的隔离和信任模型必须在 Phase 2 SPEC 冻结；不能把插件代码直接等同于可信宿主组件。动态路由只是可选实现方式，不是产品契约。实际界面改造沿用 0.75 已确定的逐页参考与审核流程。
- **安全与分发**：现有受信任本地插件若在宿主进程内运行，manifest 权限和 API 检查不能阻止恶意代码直接访问进程能力。Phase 1/2 只承诺公开宿主 API 的权限边界，并明确受信任安装前提。Phase 3 在允许一般第三方远程包执行前，须冻结并验证运行隔离、来源校验、签名或等效信任、权限强制执行、恶意包处置、版本撤回及回滚；达不到时市场只能分发不可执行内容或经人工信任的本地包。文件 hash 只证明内容一致性，不证明发布者身份或代码安全。

关联基线：[0.65 能力包 RPD](../0.65/rpd/RPD-06-Capability-Packages.md)、[0.65 插件契约](../0.65/CONTRACTS.md)、[多源 Provider](../0.65/PROVIDERS.md)、[ADR-002](../../architecture/adr/ADR-002-plugin-boundary.md)、[0.8 事件接线要求](../0.8/RPD.md)、[0.85 记忆编纂](../0.85/RPD.md)、[DSH 分发意向](../../integrations/dsh/README.md)。DSH 和 FaustBot 提供对标方向，本 RPD 不要求迁入其 Runtime 或前端技术栈。

## 6. 完成定义

| 阶段 | 自动与真实接线门槛 | 用户验收 |
| --- | --- | --- |
| Phase 1 | 代表性 Memory/TTS/STT 包经真实 loader、registry 与 Agent 流程运行；缺包、双 Provider、切换、取消、失败、数据保留和最小安装可验证。一个受控 Hook 和一个只读资源视图从真实宿主调用，证明作用域、预算、错误隔离与撤销；被测宿主不可 mock | 用户可本地导入、启用、选 Provider、停用并恢复基础聊天；资源检索结果可回溯来源 |
| Phase 2 | 真实 UI 宿主验证安装前无入口、启用后出现、停用后撤下；配置和权限拒绝可见。固定事件回放验证重复/乱序、冷却、勿扰、撤销和“只形成邀请、不直接写记忆”；后台任务验证取消、幂等、迟到丢弃与实时语音延迟隔离 | 用户可从设置配置插件、查看事件触发原因并暂停；后台维护结果可纠正/遗忘 |
| Phase 3 | 干净环境完成发现、暂存、审阅、批准、启用、更新失败回滚和卸载；受篡改、不可信来源及不兼容包拒绝。第三方可执行包须证明权限在实际运行路径被强制执行；未达到隔离门槛不得公开启用 | 用户可理解来源、源码/文件、权限与数据影响，且能恢复最后有效版本 |

每阶段分别报告契约测试、生产接线、真实模型/设备和人工体验。市场上架数量、具体插件品牌和第三方生态规模不是首版通过条件。

## 7. 风险与待决策

| 风险/决策 | 影响 | 处理/出口 |
| --- | --- | --- |
| 0.65 基线与实际接线存在差距 | 重复设计或把未完成能力当作前置 | 启动 Phase 1 前核对源码、报告与生产链；只补实际缺口 |
| 可执行插件 UI 扩大宿主权限面 | 第三方代码可能越权或影响界面稳定 | Phase 2 冻结隔离、桥接、权限、错误边界；未满足前只开放受控扩展方式 |
| 多 Memory 提供者的数据迁移不明 | 丢失、重复或恢复已遗忘内容 | 明确每包数据所有权、迁移/回滚、来源撤销与遗忘传播；迁移单独验收 |
| 市场来源与依赖链复杂 | 恶意包、供应链与不兼容升级 | Phase 3 另定分发信任和依赖策略；不以 hash 冒充签名或沙箱 |
| 插件事件被误当成事实 | OCR/感知误判污染长期记忆 | 事件只作候选；Memory/Timeline 消费者依其证据与用户授权规则写入 |
| VFS 成为第二套数据权威 | Wiki、Timeline 和来源撤销分叉 | 资源层只投影，不持有新的事实副本；检查撤销后 URI、索引与缓存 |
| Hook 与 Tool 数量膨胀 | 行为不可预测、Context 与 Token 成本增加 | Hook 逐项开放；只读资料优先按需资源查询，动作保留 Tool；固定样本量化 |
| 后台 Subagent 与实时语音抢资源 | 首字延迟上升、取消复杂 | 复用已有队列，设并发/预算上限；语音链不等待后台；不以 Subagent 数量衡量完成 |

下一步在 Core 基线稳定后，将 Phase 1 拆为 SPEC：先核实 Provider Interface、现有事件通道、Memory 队列与资源读取的实际接线，再固定 Hook、逻辑资源、Binding、数据迁移及 UI 扩展契约。此 RPD 本身不启动实现。
