# N07-00 · 实际接口基线与文字闭环探针

版本：Aika Next 0.7；日期：2026-09-22；状态：AUTO_PASS（部分验收）。

## 1. 目的与边界

在写 0.7 业务代码前，把 RPD 的逻辑边界映射到当前 0.61/0.65 的真实源码。此步不实现完整 Character Pack，不加入联网 Wiki 抓取，不改鼠标/音频链路；只建立后续 SPEC 的可执行边界，并以不超过 2 次真实 LLM 调用验证文字链路探针。

## 2. 已核实的现有接口

| RPD 责任 | 当前实际入口 | 可以复用的语义 | 当前缺口 |
| --- | --- | --- | --- |
| 资料来源 | `memory/knowledge-library.ts` 的 `KnowledgeLibraryStore` | TXT/Markdown 导入、hash、文档 revision、稳定 block locator、active library、预算 | 不是 Character Pack；没有来源批次、角色/作品/剧情截止点和 Wiki 条目 |

## 3. 本步冻结的适配原则

- 初版来源只做本地 TXT/Markdown fixture 和用户显式输入；HTTP Wiki provider 留给 N07-02，失败必须显式报告，不伪称已读取。
- 角色包是不可变版本；草稿验证失败不替换活动版本。当前活动指针必须与普通知识库的 active library 分开。
- 每个事实/事件必须带 `evidenceIds`，且能回到来源快照的 block locator。未知 ID、无依据的原作事实或剧情截止点外事件时，草稿不可激活。
- 文字 Context 顺序固定为 Character Soul → Relationship/User Soul → 允许知晓的 Canon/Character Wiki → Companion/User Wiki → 近期对话；每层有独立预算和稳定去重键。
- 角色回复仍走 `DialogueProvider.reply(DialogueRequest)`；连续性只提供 ContextSource/pack 快照，不复制 `NextTurnPort` 或 `DialoguePipeline`。
- 多源 LLM/TTS/STT 继续使用 0.65 的 `SourceInstance → ModelProfile → Binding → ResolvedBinding` 体系。N07-02 只消费解析后的 binding，不读取 key 或硬编码 endpoint。
