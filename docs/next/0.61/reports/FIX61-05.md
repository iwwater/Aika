## 2. 渲染器生命周期实现（本轮真正补齐的部分）

上一轮只留下 `this.generation = 0` 与 `releaseCounts` 的**字段声明**，没有任何实现。实测证据（改动前）：

```

```

即 05-B"迟到不覆盖"与 05-C"释放计数平衡"**均未实现**。本轮按 TDD 补齐：

1. **先验证后切换**（AC 关键）：哈希只证明来源，不证明可构建——字节翻转的 moc 仍可能哈希成其自带目录所记录的值。故在释放任何东西之前，用**独立 `CubismMoc` 探针**真正构建一次候选（探针自带 `deleteModel`/`release`，不触碰屏上模型），并要求参数表非空。失败则原样抛出，`releaseCounts` 不变、旧皮肤存活。
2. **再释放**：验证通过后 `releaseSkinResources()` 删除旧纹理、调用 SDK `release()`（权威释放 renderer/moc/模型/各 manager）并计数 `models`（+`renderers` 当有 WebGL renderer 时）。**不额外显式释放 renderer**——SDK `release()` 已包含，否则双重释放。
3. **manager 复原**：SDK `release()` 会把 `_motionManager`/`_expressionManager` 置 null，导致切换后 `reset()`/`setAutomaticPolicy()` 抛 `Cannot read properties of null`。这两者属于实例而非某一皮肤，故复原（`_modelMatrix` 由 `loadModel()` 依新 rig 画布尺寸重建，不在此复原）。实测修复后 `policy: ok / reset: ok / updateView: ok`。
4. **generation 哨兵**：每次 `loadRig` 领取一个 generation；`stale()` 判断自己是否已被更新切换取代。被取代者在提交前抛 `模型切换已被更新的选择取代`，绝不回写 `skin`/`activeRevision`。
5. **原子提交**：`this.skin = skin; this.activeRevision = skin.revision;` 仅在全部成功后执行。

## 6. `digestInput` 复核（FIX61-03 §7 越界最小修复）

FIX61-03 报告 §7 声明：`loadRig` 内 `let binding` 与参数 `binding` 重复声明的 SyntaxError，已将循环内变量重命名为 `digestInput`，并要求 05 执行轮复核其原意。

**复核结论：符合 05 原意，予以确认保留。** 依据：
- 代码位置 `desktop/cubism-renderer.mjs` `loadRig`，`let digestInput = '';` 后 `digestInput += path + '\0' + hash(...) + '\n'`，仅用于拼接进场指纹字符串，随后 `hash(new TextEncoder().encode(digestInput))` 与 `skin.catalog.modelFingerprint` 比对。
- 该变量**仅**是"把各引用文件路径与其 SHA-256 拼成一段文本再整体哈希"的累加器，**语义与参数 `binding`（模型包绑定对象）完全不同**，故改名未改变任何行为——修复的是命名冲突，不是逻辑。
- 与 `management/skin-store.ts` 的 `legacy` 指纹算法（同样 `path + '\0' + digest + '\n'` 排序拼接后 sha256）**一致**，因此渲染器与注册表对同一套字节得出同一指纹；本轮 05-A/05-B/05-D 的指纹断言全部通过，反向印证该改名未破坏指纹契约。
- 本轮在此基础上新增了"**哈希之外**"的真实可构建性验证（§2 第 1 点）：哈希通过但 Core 建不出参数表时仍拒绝，补齐了仅靠哈希无法覆盖的损坏场景。
