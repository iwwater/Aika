## 1. 改动与设计

核心是把"模型能不能用"从**型号白名单 + 硬编码价格**改成**协议能力 + 端点来源 + 凭据引用 + 用量上界**四道边界。

| 文件 | 改动 |
| --- | --- |
| `contracts/management.ts` | `ProviderSelection` 增加 `protocol`（可选的迁移字段，读取时归一化）与自由 `provider` 标识（`ProviderId` + `isProviderId`）；`ProviderAdapterInfo` 增加 `open?: true` 标记能力型适配器；`CredentialInfo.provider` 放宽 |
| `contracts/self-setup.ts` | `SetupProvider` 放宽为预设 + 自定义；新增 `SavedCredential` |
| `management/settings.ts` | 新增 `resolveSlotAdapter`：用户只配置模型/端点/协议，适配器由协议推导。绑定一旦偏离已复核预设（模型、端点或供应商任一不符），自动落到同槽同协议的能力型适配器；仍在预设内则保留原复核适配器与其费率。校验改为在 `structuredClone` 副本上做（见 §4 缺陷） |
| `management/management-catalog` (`providers/management-catalog.ts`) | 新增 5 个能力型适配器：OpenAI 兼容文本/图像/ASR/TTS 与 Gemini 文本。它们不带 `choices`、不带型号列表、不带费率——即"任意自填模型" |
| `app/trial-config.ts` | 移除 provider 白名单（`感知和语音需要已登记的DashScope配置`）、DeepSeek 文本型号/费率锁、ASR 型号锁、MiniMax 型号-费率配对锁；保留 ASR 音频费率、TTS 字符费率、端点来源、凭据在项目外等真实边界 |
| `management/credential-store.ts` / `credentials.ts` | 凭据按任意已登记 provider 标识归属；自定义端点保留自己的 Key，不再被迫落到预设厂商凭据 |
| `providers/aika-dialogue.ts` | 身份取自本轮 `context.characterPrompt`（构造函数 prompt 降为兜底），阶段摘要作为上下文数据进入请求，记忆仍只注入一次 |
| `management/bootstrap.ts` | 生产组合根注册真实 Aika 管理端口（profile/timeline）+ Timeline recorder，随服务关闭停止 |
| `app/trial-backend.ts` | 用真实 `AikaProfileStore`/`AikaTimelineStore` 接入 `startRuntimeManagement`，控制台与组合根读写同一份配置 |

**能力边界（明确不夸大）**：本版本 ASR/TTS 只在 OpenAI 兼容协议上实现，Gemini 绑定这两个槽位会被明确拒绝（`本版本的 Gemini 协议不提供语音转写或语音合成槽位。`），而不是静默失败。

## 4. 执行中发现并修复的缺陷

**校验函数改写调用方对象**。`validateManagedSettings` 为了归一化 `protocol`/`adapterId` 直接在传入对象上赋值，导致调用方持有的 `settings` 快照在调用后发生变化（`defaults` 前后的 `JSON.stringify` 不再相等）。这正是"saved 与 effective 分离"要防的那类错误，会让 01-D 的「配置修订不混用」在真实页面保存路径上失效。已改为在 `structuredClone` 副本上归一化并返回该副本。修复证据：`Plus page selection reaches the real factory ... its own tariff` 由失败转为通过，且 `assert.equal(JSON.stringify(defaults), before)` 成立。
