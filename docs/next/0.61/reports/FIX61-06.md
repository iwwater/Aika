## 1. 它是什么，不是什么

**是**：用户导入 UTF-8 TXT/Markdown 得到的独立参考资料集合；一个会话可以指向其中一个；被选中的正文以**带来源标注的参考数据**进入 Provider 请求，并真实影响回答。

**不是**：第二份 Memory、第二个角色、第二个应用数据库、也不是会自动提炼自己的 Wiki（自动 Wiki 沉淀归 0.7）。

三条硬边界在实现中逐条落实：
1. **不是第二个数据库**：知识表加在**同一个 companion.sqlite** 上（`knowledge_libraries`/`knowledge_documents`/`knowledge_state` 三张可回退的附加表），共享同一个连接与事务边界。`SqliteMemoryStore.rawDatabaseForKnowledge()` 是唯一入口，注释里写明这是刻意的。
2. **不是第二份 Memory**：知识不写 `memory_records`、不进检索排序、不改 User Memory；它只作为 `DialogueContext.knowledge` 参与上下文装配。
3. **不是自动 Wiki**：不做 query 重排、不做语义检索、不自动提炼。顺序是稳定的（见 §3 稳定性）。

## 3. 关键设计

- **撤销修订与 CAS**：全局 `knowledge_state.revision`，导入/删文档/删库/改名/切库都会提高它。所有写操作带 `expectedRevision`，不匹配抛 `version_conflict` 并保留已接受状态（06-B 证据）。
- **激活基线 vs 当前修订**：`active()` 里的 `library_revision` 是**切库当时的库修订**（用于判定陈旧快照），而 `selection()` 返回**当前**库修订。两者都暴露，语义在代码注释里写清楚。
- **稳定性**：块顺序只由 `(document.created_at, document.id, 段序号)` 决定，**不按当前 query 重排**——这正是冻结前缀能保持字节稳定的前提。语义检索留给 0.7。
- **可追溯**：每个块带 `documentId`/`documentRevision`/`sourceName`/`ordinal`，`locator` 是**原文 Unicode code point 区间**。
- **预算**：默认上界 4096 输入 token（`KNOWLEDGE_LIMITS.defaultInputTokens`），块**整块取舍**而非截断（截断会破坏 locator）。放不下时 `omittedCount > 0`，Provider 文本里也如实写出「本次未载入 N 段」——**不宣传全库已读**。
- **数据不是指令**：Markdown/HTML 一律按字面文本保存与投递，链接不解析、文件不读取、脚本不执行（06-D 证据）。
- **隐私一致**：`privacyExcluded` 的轮次连同知识一起丢弃，不因「知识不是个人记忆」就绕过排除。
