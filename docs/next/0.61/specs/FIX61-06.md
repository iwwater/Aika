## 1. 源码定位

0.6 没有独立 Wiki/知识库切换接口。memory/sqlite-port.ts.createContext 和 memory/context.ts 是既有上下文入口；不得以切换 SQLite 文件或角色 ID 冒充知识库切换。0.7 仍负责自动提炼与维护。

## 2. 修复与接口边界

新增最小 KnowledgeLibrary：id/name/revision，KnowledgeDocument：id/libraryId/sourceName/contentHash/text/revision/deleted。导入 UTF-8 TXT/Markdown，本地逐文件选择；单文件上限 2 MiB、单次 20 文件、库总正文 20 MiB（可配置但有硬上限）。不读整个磁盘、不执行 Markdown HTML/指令，不联网抓 Wiki。

提供 list/create/rename/import/removeDocument/deleteLibrary/activate(expectedRevision,libraryId|null)，同库同 hash 重导幂等；所有写入与 activeRevision 事务化。正文与索引使用当前 Next SQLite 新表和可回退迁移，不另建应用数据库运行时。

0.61 选择器表示当前会话的参考知识库，可选择“无”；独立于换肤，不自动改 User Memory。跨会话默认库持久化，新轮固定 libraryId/revision；当前会话切库先取消当前生成/播放再应用，其他会话不受影响。

按库/文档/段顺序建立有界稳定知识块，携 documentId/revision/source locator，接入既有 Context；总预算内选择段落，默认最多 4096 输入 token 的保守上界；不足时可见 omittedCount，不能宣传全库均已读。0.61 采用稳定装配以兼容冻结前缀，不每轮对 query 重排；库大时提示精简选中文档，语义检索和自动 Wiki 沉淀留给 0.7。

删除/修改文档、删除活动库、切库都会提高知识撤销修订，旧 Context 与快照不得继续交付或重新落盘；删除活动库回到“无”，不自动选别库。将知识作为带来源的参考资料与 system 指令分隔。

最小 UI：建库、导入、文档清单、删除、当前库切换和生效状态；只做占位入口不得过关。

以上新接口名是设计建议，不声称已经存在；复用上游 Scope、取消、存储与鉴权边界。只修改本 SPEC 所需代码，共享接口变动同步记录消费者。
