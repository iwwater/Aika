## 2. 修复与接口边界

逻辑 PrefixSnapshot {id,key,revision,prefixText,hash,sources,historyWatermark,builtAt,privacyRevision}；key 含用户/角色/会话边界、profileRevision、libraryId/revision、协议和模型/预算配置。冻结系统设定、静态人物配置、已选核心记忆/摘要和知识块；0.61 不依赖未实现的 Soul。动态后缀只追加 watermark 后有界近期对话与当前输入，按 messageId 去重。

默认刷新模式 next-start（本次运行冻结，下次启动后台刷新），可选 interval 默认 6 小时；普通新增消息/记忆不更改已发布前缀。新记忆后台照常维护，UI 显示快照时间及可能尚未纳入新记忆；用户可主动刷新。

启动加载校验可复用持久快照；后台 single-flight 装配，CAS 校验配置/隐私/知识修订后原子发布。长任务放 worker 或分步调度，不在主线程做大段同步扫描；当前轮固定 snapshotId，下一轮才使用新版本。后台失败保留仍有效旧快照并报告。

无首份快照时立即使用可同步生成的最小当前身份前缀+动态输入，状态 building，不等待大库。用户改 prompt、切角色/库、来源纠正/遗忘/删除、收紧权限立即使旧快照不可用；同样先使用排除旧内容的安全前缀再后台重建，不以“零阻塞”为由继续泄露旧内容。若安全前缀也无法构造，则可见拒绝该轮。

普通数据增长与撤销分离：不得删除 assertContextCurrent；引入持久 privacy/revocation 修订和逐来源验证，旧轮结果/播放与后台旧快照都受控。每轮可做轻量来源校验，不重跑全库 recall；重启时先验有效性，失效快照不得恢复。

Provider 必须将冻结文本放在请求稳定前部；不含轮 ID、时间戳、随机排序。预算超出时截动态后缀；前缀本身无法容纳则重建/报配置错误，不能每轮悄悄截前缀。稳定前缀不等于供应商 KV 必中，也不减少逻辑输入 token 数；只报告实际可得 cache usage、费用和 TTFT，不预设收益。

以上新接口名是设计建议，不声称已经存在；复用上游 Scope、取消、存储与鉴权边界。只修改本 SPEC 所需代码，共享接口变动同步记录消费者。
