## 1. 源码定位

desktop/electron/transport.mjs 的 BackendConnection 当前 timeoutMs 默认 60000，不是 TODO 所写 15 秒；只识别 backend_ready，ready 前其他消息被忽略。close 异步等待退出，但 start 不等待 close，重试有进程重叠风险。

app/trial-launcher.ts 的 verifyTrialRuntime 按文件 readFile/hash；trial-backend.ts 启动也调用它；app/backend-session.ts 发布 backend_ready。

## 2. 修复与接口边界

沿用 NDJSON，新增类型化 backend_startup {sequence,phase,completed,total?,elapsedMs} 和启动失败码，在读配置、hash、数据库、Provider 装配阶段发出真实进展。stdout 仅协议，不输出路径/凭据正文。大文件采用有界分块 hash 并报告已处理字节，仍完整校验。

状态为 starting/verifying/initializing/ready/failed/cancelled；进展的 sequence 与 completed 必须前进才续期。心跳仅证明活着，重复心跳不无限延期。无进展窗口默认 60 秒、可配置；每个新进展延长窗口，继续保持可见等待和取消。保留未支持进度的旧后端兼容超时；无需一个绝对 15/60 秒总时限。

start/retry 串行 await 旧进程完全退出/锁释放再 spawn，generation 隔离迟到 ready/progress/exit。取消先 EOF、超出 shutdownTimeout 再终止，UI 显示原因与重试。失败的当前 generation 只能发布一次终态。

以上新接口名是设计建议，不声称已经存在；复用上游 Scope、取消、存储与鉴权边界。只修改本 SPEC 所需代码，共享接口变动同步记录消费者。
