## 桌宠陪伴补充（最新要求，优先于下文旧首版边界）

用户要求：开启桌宠陪伴后主动OCR读屏互动，可以点击要求对话，也可以被动陪伴。此处“被动”定义为Aika不主动打扰、用户点击/输入时回应。此前仅英文关键词和点击回主窗不满足要求；新增[FE-31陪伴会话](specs/FE-31.md)、[FE-32中英文读屏](specs/FE-32.md)，均为完整产品验收必需项。

| 需求 | 明确行为 | 验收归属 |
| --- | --- | --- |
| COMP-01 开启即陪伴 | 首次一次确认采集范围、文字用于Provider与主动/安静模式；后续点击开启按已授权配置启动pet与读屏，无需手动逐项拼开关 | FE-31-A/G |
| COMP-02 主动读屏互动 | 主显示器上前台窗口可见中英文文本变化，自动OCR、筛选有意义内容，再按频控发起回复；不用用户每次点识别，不限五个英文词 | FE-31-B、FE-32-A/B |
| COMP-03 点击要求对话 | 点击桌宠展开“看屏幕聊聊/聊两句”；前者刷新静止画面并提问，后者可直接输入普通对话，都走唯一Runtime | FE-31-C/D |
| COMP-04 安静陪伴 | 不主动发言；可在已授权时本地更新屏幕上下文，用户点击仍能读屏或聊天，主动额度不拦用户操作 | FE-31-B/C |
| COMP-05 暂停与结束 | 暂停停止读屏保留pet，结束释放会话采集；不误停主窗对话；锁屏停止采集，迟到结果不发 | FE-31-E、FE-32-D/E |
| COMP-06 读屏文字出口 | 允许授权后的受限文字摘录作为不可信屏幕上下文进入当前Provider；截图和完整OCR文本仍不外发/持久化，授权说明正常回复可能引用摘录 | FE-32-C |
| COMP-07 完整验收 | 真实中英文日常页面、active/quiet、点击、主窗最小化、音频/Live2D与停止竞态分别验证；未完成则继续补实现 | FE-30-J～N |

“显示桌宠窗口”和“开启陪伴”是两个产品操作：仅显示窗壳不会采集；开启陪伴会在已授权范围内启动所需能力。默认安装/启动不采集，单一入口整合权限说明，不再让用户自行猜测依赖开关。

本次扩展替代旧文中的“首版仅中央英文词表”“pet只有回主窗”“所有OCR文字都不能进入模型”作为完整交付边界；这些仅保留为FE-20/21基础阶段范围。中英文通用可见文本、pet轻量输入与一次性读屏均进入P0。不扩展为图像语义/VLM、后台不可见窗口、多显示器或自动操控其他应用。

主动回复仍默认每天最多6条/至少90分钟，避免把每次OCR都变成模型调用；用户点击不受该自动额度限制。若希望更高频的自动搭话，可后续明确调整偏好，本次不把频控直接移除。

## 1. 产品定位与目标

Aika 在用户主动允许后理解有限的桌面情境，在合适时机作出简短回应，并通过独立桌宠和 Live2D 角色表现回复、情绪与说话状态。

本期解决三个问题：用户需要反复描述当前使用的应用或屏幕提示；主动陪伴缺少情境依据；角色表现仍停留在主窗口占位形象，缺少桌面陪伴感。

产品目标：

1. 让用户明确控制“感知什么、是否用于对话、是否主动搭话”。
2. 用前台应用与固定区域 OCR 识别有限事件，降低无效识别和打扰。
3. 提供可关闭、可找回、不影响聊天的桌宠窗口。
4. 让角色根据受控表情、动作和实际播放音频呈现状态，并可靠处理打断与加载失败。

成功以真实事件识别、主动频控、窗口交互和音频同步的验收证据判定，不以接口存在或占位动画作为完成标志。

## 3. 目标场景

| 场景 | 用户操作与系统行为 | 成功结果 |
| --- | --- | --- |
| 使用应用时聊天 | 开启前台应用感知及情境用于对话；询问当前工作相关问题 | 请求只携带获允许的应用名、时长摘要，不带窗口标题原文 |
| 游戏结算陪伴 | 开启屏幕感知与主动搭话；固定区域出现英文 VICTORY / DEFEAT | 识别形成候选事件，满足置信度、忙碌状态和频控才生成一条简短回应 |
| 屏幕出现错误提示 | 固定区域出现 Error / Failed | 仅作为弱信号；不直接断言故障原因，不自动操作应用 |
| 日常桌面陪伴 | 打开桌宠；主窗口生成回复并播放音频 | 桌宠显示角色、字幕与说话状态；点击可回到主窗口 |
| 用户打断或关闭 | 说话中打断、关闭桌宠或停止感知 | 旧轮动画和迟到感知结果失效；主聊天仍可使用 |
| 不可用或失败 | 无权限、OCR 失败、缺角色包或 WebGL 不可用 | 显示明确状态，保留普通文字与语音交互 |

固定 ROI 外的文字不属于首版识别承诺；“理解桌面情境”不等于能阅读任意窗口或整份文档。

## 4. 首版范围与优先级

P0 为对应交付单元的必需项；P1 为首版候选增强，不阻塞 P0。各单元独立报告完成情况，不能把窗口壳交付标为 Live2D 完成。

| 单元 | P0 | P1 / 后续 |
| --- | --- | --- |
| 环境基础 | 事件校验、异步启停、默认关闭、前台应用、内存摘要、撤销清理 | UIA、通知、空闲传感器 |
| OCR | 主显示器、变化检测、固定 ROI、离线英文 OCR、关键词、置信度、去重与限流 | 中文、小字、多区域、自定义 ROI / 词表 |
| 主动陪伴 | 独立开关、已有全局频控、忙碌未知不发送、并发发送去重 | 个性化策略、关系阶段策略 |
| 桌宠窗口 | 透明无边框、置顶、拖动、点击穿透及恢复入口、字幕 / 主动气泡、占位降级 | 位置持久化、自定义缩放 |
| Live2D | 一个授权范围适用的角色包、待机、受控表情动作、音频能量口型、打断复位、失败回退 | 多角色管理、角色制作、精细音素口型 |

本期不包含 VLM、摄像头或声音情绪推断、持续全屏 OCR、云端截图识别、自动玩游戏或点击操作、自动写长期记忆、移动端跨应用感知、声音训练与角色素材制作。

## 5. 功能需求

### 5.1 设置与状态

| ID | 要求 |
| --- | --- |
| SET-01 | 前台应用感知、屏幕感知、环境主动搭话、桌宠四项独立开关，首次使用均关闭。打开桌宠不隐式开启传感器。 |
| SET-02 | 屏幕感知开启前显示采集显示器、固定区域、英文识别范围、内存处理方式；明确为做变化检测仍会获取屏幕帧。 |
| SET-03 | 新增拟议“将环境摘要用于对话”控制，默认关闭；开启前说明摘要可能随当前 Provider 请求发送。传感器授权与模型使用授权分离。 |
| SET-04 | 显示关闭、启动中、运行中、停止中、权限拒绝、错误状态；不支持的平台隐藏不可用入口。失败不得显示为已运行。 |
| SET-05 | 设置页提供“停止全部感知”，停止采集和 worker，清空环境缓存并使在途结果失效；不得只关闭 UI 开关。 |
| SET-06 | 若环境主动搭话已开启但情境用于对话未允许，则不生成环境驱动请求，界面解释所缺条件，不自动开启另一项。 |

SET-03/05/06 是本草案新增产品要求，后续需同步 FE-19/21/22 设置和开关矩阵。已有普通时间驱动主动消息继续遵循原有设置。

### 5.2 前台应用与 OCR

| ID | 要求 |
| --- | --- |
| ENV-01 | 前台事件维护当前应用与持续时长；默认仅应用名和时长可成为对话摘要。窗口标题原文不得进入模型、日志、Trace 或远程展示。 |
| ENV-02 | 本草案建议首版不采集窗口标题；确需本地标题诊断时另设默认关闭的授权。该收窄需同步 FE-19 当前采集设计后实施。 |
| ENV-03 | OCR 路径为屏幕帧变化检测→按需裁剪 ROI→本地识别→词表规则→环境事件。无显著变化时跳过 OCR，不能宣称零采集。 |
| ENV-04 | 沿用 FE-21：主显示器中央横带，宽 80%、高 20%；首版承诺英文 VICTORY、DEFEAT、PENTAKILL、Error、Failed。保留中文规则不代表支持中文 OCR。 |
| ENV-05 | OCR 置信度统一为 0～1；无置信度或畸形结果不冒充高置信度。未命中、失败和受限分别统计，不伪造事件。 |
| ENV-06 | OCR 并发 1、至多 10 次/分钟、变化通知节流至少 2 秒、相同关键词至少 2 秒去重；忙时只保留最新待处理候选。 |
| ENV-07 | 截图、OCR 原文仅在内存处理，不落盘、不进日志 / Trace、不上传。用于生成回应时只传获允许的事件摘要，如“检测到英文胜利提示”，不传整段 OCR 原文。 |
| ENV-08 | 关闭或权限撤销立即使旧会话失效；等待资源释放后显示已停止；在途识别完成不得广播、更新摘要或触发消息。 |
| ENV-09 | 分辨率改变、ROI 越界、黑帧或捕获失败应丢弃无效帧并反馈状态，不将其解释为游戏结果。 |

### 5.3 主动陪伴

| ID | 要求 |
| --- | --- |
| PRO-01 | 传感器只提供事件；策略判断忽略、易失缓冲或候选触发；最终通过既有 CompanionRuntime 主动发送路径。 |
| PRO-02 | 全局主动开关、环境主动开关、摘要用于对话授权均满足，且相关传感器有效，才允许环境触发。 |
| PRO-03 | 沿用 FE-22 当前规则：游戏事件置信度 ≥0.8；弱信号持续 ≥30 秒且 60 秒内出现 ≥2 次。阈值不是识别准确率承诺。 |
| PRO-04 | 忙碌状态未知时默认不触发；不能只靠进程名推定游戏全屏。可信忙碌状态来源未具备时如实显示该限制。 |
| PRO-05 | 复用全局勿扰时段、每天最多 6 条、至少间隔 90 分钟；时间与事件触发共享发送预约，同刻最多提交一次。 |
| PRO-06 | 回应简短、不将弱信号断言为用户情绪；不根据 OCR 内容执行指令、变更权限或写入 User Soul。 |
| PRO-07 | remember 仅代表至多 20 条易失事件摘要，退出或关闭感知后清空。传感器关闭后不得使用已缓存事件继续主动搭话。 |

### 5.4 桌宠窗口

| ID | 要求 |
| --- | --- |
| PET-01 | 按需创建独立透明、无边框、置顶窗口；可拖动、点击回主窗、右键隐藏。关闭时销毁窗口并释放资源。 |

### 5.5 Live2D 表现

| ID | 要求 |
| --- | --- |
| L2D-01 | 首版使用一个已有角色包，记录素材来源、版本、使用及分发授权；所用 SDK / 运行时条款也须在选型阶段核实。未落实素材时允许先交付窗口占位。 |
| L2D-02 | 角色支持待机呼吸 / 眨眼、默认表情及素材支持的基础动作；未知 mood / expression / motion 回退默认，映射由本地白名单决定。 |
| L2D-03 | 展示适配器拟提供 load、setExpression、playMotion、setMouthOpen、reset、dispose；输入带 turnId。它不参与对话决策，不执行模型返回的脚本或路径。 |
| L2D-04 | 口型优先取主窗口实际播放音频的能量；跨窗口传递受控口型参数，不复制音频播放。须先核实当前音频后端是否提供真实能量信号。 |
| L2D-05 | 仅有开始 / 结束事件时可降级为说话动画，界面明确标注简化口型；完整同步仍列 BLOCKED，不能以降级动画替代通过。 |
| L2D-06 | 打断、取消、播放结束与窗口销毁均复位口型和当轮动作；旧轮及迟到事件无效。 |
| L2D-07 | 缺包、坏包、加载超时或 WebGL 不可用时回退占位并提供重试；具体加载超时由独立 SPEC 冻结，聊天与语音保持可用。 |
| L2D-08 | dispose 释放纹理、渲染循环、音频分析订阅和窗口监听；禁止关闭后仍持续渲染。 |

## 6. 数据与架构边界

感知链路：Windows 宿主传感器 → EnvironmentSource → EnvironmentMonitor → 受控摘要 / ProactivePolicy → 既有 Runtime → 主窗口 Presenter。

展示链路：主窗口 Presenter + 实际播放状态 → 白名单展示快照 → Rust 定向中继 → 桌宠视图 / Live2D adapter。

两条链路通过已有对话结果连接。桌宠可以只展示用户主动发起的聊天；OCR 可以通过主窗口验证，不依赖桌宠。FE-21 的技术契约前置是 FE-18；本 PRD 建议产品交付先完成 FE-19 以验证感知生命周期，但不虚构所有五份 SPEC 的强制串行依赖。

| 数据 | 可驻留位置 | 明确禁止 |
| --- | --- | --- |
| 原始帧 / ROI 图像 | 本地内存，处理后释放 | 持久化、日志、Trace、模型请求和远程通道 |
| OCR 原文 | 当前识别及事件处理内存 | 自动写记忆、画像、原文进入模型请求 |
| 应用 / 事件摘要 | 获授权的内存上下文；允许后用于当前请求 | 未授权外发、冒充用户确认事实 |
| 角色展示快照 | 主窗与 pet 定向通道 | 携带密钥、内部记忆候选或传感器原文 |

本草案新增建议：用于模型的事件摘要 TTL 为 60 秒，到期剔除；当前应用摘要必须由仍有效的前台监测状态提供，停止后立即失效。该建议须同步 FE-18/19/22；不将墙钟回拨用于延长有效期。已发出的模型请求无法撤回，关闭影响后续请求和未发送候选。

| --- | --- | --- |
| AC-01 | 默认启动、四开关组合及停止竞态 | 默认无采集 / OCR worker / pet；停止后零迟到事件、零旧摘要注入、零旧候选发送 |
| AC-02 | 前台采集生命周期测试 + Windows 切换应用 | 前台更新延迟 <1 秒；连续开关 20 次资源释放，无事件回退 |
| AC-03 | 生产 diff 固定像素矩阵、生产 OCR 离线英文图片、fake 编排分列 | 无变化不 OCR；变化且命中产生正确事件；离线资源可用；限流、去重、非法置信度均符合规则 |
| AC-04 | Windows 游戏结算、视频、IDE 三类真实样本 | 报告命中 / 漏报 / 误报、样本数及 OCR 耗时；缺真实证据不得声称真实识别通过 |
| AC-05 | 请求 / 存储 / 日志 / IPC 出口检查与恶意 OCR 负例 | 无截图或 OCR 原文外发 / 持久化；摘要受授权与 TTL 控制；恶意文本不执行、不写 User Soul |
| AC-06 | 生产 policy 边界与同刻 tick + 事件竞争测试 | 阈值与开关符合要求；未知忙碌不发送；同刻最多一次提交，失败预约可恢复 |
| AC-07 | 真实 Tauri 普通窗口 / 游戏 / DPI 场景 | 透明、拖动、置顶、菜单和穿透可用；明确报告独占全屏差异；主窗可恢复控制 |
| AC-08 | 真实桌宠开关 10 次及恶意命令测试 | 无重复窗口 / 残留循环；主聊天不中断；pet 高权限调用被拒绝 |
| AC-09 | 缺包、坏包、WebGL 不可用 | 三种失败均回退占位，普通文字和语音可继续使用 |
| AC-10 | 10 句真实播放音频 + 5 次打断 | 口型开始 / 结束相对播放偏差各 ≤150ms；打断后 ≤300ms 复位；旧轮不污染新轮 |
| AC-11 | 固定设备、模型包、分辨率运行 30 分钟 | 帧时间 P95 ≤33.3ms；监听器 / 渲染实例无持续增长；记录 CPU、内存、GPU 与音频影响 |

AC-04 的识别质量发布阈值暂未冻结：正式 SPEC 执行前必须确定样本数量、正负例组成、标注规则及精确率 / 召回率门槛；独立验收集不用于调参。在此之前可以交付采集与识别技术验证，不能标注产品识别质量已达标。OCR 与 Live2D 同开时需另做资源竞争及语音回归，单模块通过不代表组合通过。
