# FE-33 真机验收 · 速查卡（一页版）

> 详细步骤见 [FE-33_真机执行手册](FE-33_真机执行手册.md)。本页只放「现场要按什么、看什么」。

## 开工三步

1. 任务管理器确认没有旧的 `aika-crossplatform.exe` 残留。
2. 双击 `aika-crossplatform\src-tauri\target\release\aika-crossplatform.exe`。
3. 先目视：主窗是否正常显示（**不是白屏**）。→ 若白屏，记录下来，这是最优先的缺陷。

## 七项速查

| ID | 一句话做什么 | 看到什么才算过 | 填 |
| --- | --- | --- | --- |
| **A** | 启动后开设置，找「环境感知」分组 | 分组在；两个 source 显示**「已关闭」**；启动瞬间无 CPU 采集 | ☐ |
| **B** | 开「前台应用感知」，VSCode/浏览器/游戏来回切；开关 20 次；锁屏一次 | 切换 **<1s** 且进程名对；句柄数不持续涨；锁屏显示 **unknown**（不是 false） | ☐ |
| **C** | 开「屏幕感知」，普通窗/pet/主窗/被 pet 遮挡各看一次 | 普通窗返回 ok+进程名（**无标题**）；pet/主窗时读**上一个外部窗口**；遮挡显示「请调整窗口」 | ☐ |
| **D** | 中文文章/英文文档/混排 IDE，手动+自动各读几次，记耗时 | 断网可用；热读屏 **P95≤3s**；摘录 ≤20段/2000字；限流显示下次时间 | ☐ |
| **E** | 四轮对话：全关 / 只开摘要 / 开摘录 / 关摘录（**花钱，量小**） | 全关**零环境内容**；只开摘要仅应用名+时长；开摘录标**「（未确认）」**；关后立即为空 | ☐ |
| **F** | 显示桌宠→最小化主窗→开陪伴(active)→quiet→看屏幕聊聊→输入→暂停→结束；期间拖动/双击/连点 | 拖动**不算点击**；双击**不发两轮**；quiet **不主动发**；暂停后普通聊天还能用；结束**不断现有轮** | ☐ |
| **G** | 各阶段分别触发 暂停读屏/结束陪伴/停止全部感知/锁屏 | 迟到结果**不外发**；停止全部感知显示**「已暂停」**；WGC/OCR/hook 线程**确已释放** | ☐ |

## 已知会遇到的坑（别当失败）

- **独占全屏游戏**下可能给黑帧 → FE-21 按无效帧丢弃，如实记录差异即可。
- **pet 置顶**在独占全屏下的表现依平台而定 → 如实记录。
- 我这边启动自检时"2 秒退出"是**测试方法问题**（重定向 stdout），你自己双击不会遇到。

# 第二轮 · 修复复验（2026-09-14 17:1x 起）

三项缺陷已定向修复并重建。本轮只回答：**修复在真机上是否真的生效**。

## 开工三步

1. **完全退出正在运行的 Aika**（托盘菜单「退出」）：任务管理器里不能有 `aika_crossplatform.exe`
   或 `aika-crossplatform.exe`。⚠️ 实测：旧实例持有 `target\release\deps\aika_crossplatform.exe`，
   不关就用 `cargo build` 会以 `LNK1104 无法打开文件` 失败。
2. 启动**新** exe：`aika-crossplatform\src-tauri\target\release\aika-crossplatform.exe`
   —— **先看文件修改时间是否为 17:29 之后**；若仍是 16:39，说明你启动的是旧构建
   （第一轮的三项现象就是在 16:39 那版上看到的）。
3. 目视主窗不是白屏。

## 复验一：BUG-01 桌宠（对应 FE-33-F 前置）

| 步骤 | 通过条件 | 填 |
| --- | --- | --- |
| 设置 → 桌宠 → 点「显示桌宠」 | **能看到角色立绘**（不是透明空壳/纯黑框）；开关变「已显示」 | ☐ |
| 看它在屏幕哪个位置 | 落在**当前显示器工作区中央**，不贴边、不屏外 | ☐ |
| 把它拖到屏幕角落 → 隐藏 → 再「显示桌宠」 | 按修复说明它会被**拉回中央**——确认这是否符合你的预期（见下方 W-02） | ☐ |
| 观察设置页有无**红字** | **若出现红字但桌宠其实可见** → 见下方 W-01，这是「仅聚焦失败」被当成整体失败，请如实记录 | ☐ |
| 左键点它 / 右键菜单 / 「看屏幕聊聊」 | 快捷菜单弹出；拖动结束**不**弹菜单 | ☐ |

## 复验二：BUG-02 环境感知活动证据

| 步骤 | 通过条件 | 填 |
| --- | --- | --- |
| 设置 → 环境感知 → 开「前台应用感知」 | 该行下方出现 **「传感器已启动，等待应用切换」** | ☐ |
| 切到 VSCode，再切到浏览器 | 1 秒内文案变为 **「最近检测到：Code.exe」** 之类，进程名**准确** | ☐ |
| 文案里**绝不能**出现窗口标题/文件名 | 只出现进程名 | ☐ |
| 开「屏幕感知」，在非私人画面上制造变化 | 出现 **「正在监听画面变化…」**；有信号后变 **「最近 1 分钟识别到 N 个屏幕信号」**，N 会**变化** | ☐ |
| 关掉开关再开 | 文案回到「已关闭」再回「运行中」，不卡在旧文案 | ☐ |

## 复验三：BUG-03 滚动

| 步骤 | 通过条件 | 填 |
| --- | --- | --- |
| 造出超过一屏的消息 | **鼠标滚轮能上下滚**；拖动**滚动条也能滚** | ☐ |
| 停在底部，再发一条/等回复 | **自动滚到最新** | ☐ |
| **主动往上滚**，然后让新消息到达 | **不被抢回底部**（这是修复的关键行为） | ☐ |
| 在输入框打字 | 视图**不跳**（打字不该触发抢滚动） | ☐ |
| 滚回最底部，再等新消息 | 恢复自动滚底 | ☐ |

## 本轮需特别关注的 3 个观察项（复核时发现，非缺陷）

| 编号 | 现象 | 怎么判 |
| --- | --- | --- |
| **W-01** | `pet_window_show` 现在把 **`set_focus` 失败**也当成整体失败返回。Windows 上抢前台焦点可能失败。 | 若「桌宠可见 + 设置页红字」同时出现 → 属误报，记录之，别当成桌宠没显示 |
| **W-02** | 每次显示桌宠都**强制回工作区中央**。 | 拖走后隐藏再显示会被拉回中间；确认是否符合预期 |
| **W-03** | `reset_to_work_area` 里有个恒真判断，每次显示都调一次 `set_size(当前尺寸)`（**既有代码**，非本次引入）。 | 若发现窗口尺寸/位置有 **1px 级抖动**，根因在此，不必另找 |
