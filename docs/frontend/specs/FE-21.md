## 架构与接口依据

本 SPEC 必须实现 [模块架构与接口](../ARCHITECTURE.md) 中对应阶段的端口、事件、状态与错误语义；通过 adapter 兼容现有实现。下方 AC 同时验证这些契约，无需启动其他真实模块。

需求与边界见 [模块 PRD](../PRD.md)「感知成本阶梯」与「隐私与默认」，依赖遵循 [共享契约](../../modules/CONTRACTS.md)。事件契约见 [FE-18](FE-18.md)。

核心次序：先判断「画面变没变」（低成本），变了才对固定 ROI 截图 + OCR（贵），OCR 命中关键词规则才产生事件。**绝不做定时全屏 OCR**。

## 设计

Rust（`src-tauri/src/screen.rs`，`cfg(windows)`）：

- invoke `environment_screen_enable(enabled: bool)`：开启后专用线程每 500ms 经 Windows.Graphics.Capture 抓主显示器帧 → 缩到 96×54 灰度 → 与上一帧平均绝对差；超阈值 emit `environment://screen-change` `{ magnitude }`；false 停线程。WGC crate（`windows` / `windows-capture`）实现时按成熟度选，emit/invoke 形状不变。
- invoke `environment_capture_region(roi)`：当前帧裁剪 ROI → PNG base64 返回。只在 screen-change 之后被调用。
- V1 只做主显示器；exclusive fullscreen 下 WGC 可能黑帧，如实记录到真机清单。

TS：

- `src/services/environment/screenSource.ts`：实现 `EnvironmentSource`。screen-change（节流 ≥ 2s）→ `capture_region`（V1 固定 ROI：屏幕中央横带，宽 80%、高 20%）→ OCR → 关键词规则 → emit `EnvironmentEvent`。
- `src/services/environment/ocrText.ts`：tesseract.js（WASM）**懒加载**——仅屏幕感知开启后创建 worker；`eng` traineddata 与 wasm 打包进 Tauri resources（安装包离线，不运行时外联）；`chi_sim` 体积大，后选。OCR 引擎不进契约：产出口径只有 `EnvironmentEvent`，换引擎不动消费方。
- `src/services/environment/keywordRules.ts`：默认词表 `{ pattern, kind, event }`（VICTORY/胜利/DEFEAT/失败/PENTAKILL/五杀 → `game_event`；Error/Failed/错误 → `screen_keyword`）；OCR 词置信度按具体引擎输出区间归一为0..1再作为事件confidence，不是原值直接透传。

隐私：设置键 `SETTING_KEYS.environmentScreenEnabled` 默认 `"false"`。关闭时无 capture 调用、不建 OCR worker；开启后原图只在内存中走 base64 → OCR → 丢弃，不落盘、不进日志、不进 Trace；OCR 文本只出现在 `EnvironmentEvent` 与 policy 输入，不自动写长期记忆。

## 取舍

**diff 在 Rust 做、OCR 在 TS 做**：帧抓取与缩放比较在采集侧完成才省得下来——不把全帧扔过 IPC；OCR 放 TS 是因为 tesseract.js 生态在 WASM 侧、且规则匹配本来就是 TS 域逻辑。边界是「Rust 只说画面变了 + 按需给 PNG」。

**WGC 而不是 GDI BitBlt**：WGC 是微软当前官方采集 API（窗口/显示器/帧流），BitBlt 在硬件加速窗口上不可靠。crate 成熟度留实现时定，接口（emit/invoke 形状）已在本 SPEC 冻结。

**tesseract.js 而不是 PaddleOCR-onnx**：V1 目标是固定词表命中（大字号英文为主），不追求全文档识别；tesseract.js WASM 免训练依赖、可离线打包。中文/小字/多区域留给 V2（RapidOCR/PaddleOCR ONNX，走 onnxruntime-web），由那时的效果数据决定。

**固定 ROI、不做区域配置 UI**：游戏提示区高度可预测（中央横带）；配置 UI 的复杂度留给真实误报数据说话。

## 算法/资源与性能口径

采集仍需获取帧才能做diff，不能宣传“画面没变零采集”；主机原始帧仅内存处理，跨IPC只传受限ROI。diff阈值为预冻结配置；默认OCR并发1、最多10次/分钟、重复关键词2秒去重，忙时合并最新帧不积压；ROI越界/分辨率变化需拒绝或重算并标诊断。记录配置但不在同一验收集上反复调参。

Windows资源与Tesseract JS依赖分开归Cargo、package/lock、Tauri resources；WASM/worker/traineddata必须离线可解析，使用生产ocrText和固定英文图真实跑一次，不允许只mock OCR返回词。仅cargo check不足以证明生产diff和OCR可工作。
