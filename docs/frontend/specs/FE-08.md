## 交付

## §7 问题 1 的处理

规划文档 §7 问题 1 问的是：Rewind 对滚动摘要该「不回滚 + 标注 gap」还是「摘要可重建」。

本 SPEC **按规划文档自己的建议执行前者**，理由写在代码注释里：摘要没有可用的消息溯源（`saveSummary` 只记 `coversUntil`），没法只摘掉其中一句；整段作废又会让每次回退都触发一次重新压缩。所以保守地留着摘要，但在内容末尾追加一行 gap 标注，让她不会把摘要里已经不存在的事当成真发生过。

**这是一个可被推翻的取舍**，不是查证出来的事实：如果要求「摘要可重建」，改动落在 LLM 侧（重新压缩剩余消息），FE 侧只需把这次追加换成一次重建调用。

只有回退点比摘要覆盖范围更早（`anchorAt < coversUntil`）时才标注——回退点更新时摘要覆盖的消息都还在，什么都不用做。

## 边界

- 不做：不新增存储端口（截断用 `deleteMessages`，见下）；不做多步撤销/重做；不做时间轴或分支对话；不改 `CompanionRuntime`。
- 不需要「按时间截断」端口：`listMessages` 返回的是**最近** N 条，锚点既然在已加载窗口里，它之后的消息必然也都在窗口里，按 id 删足够。
- 开场白不是回退目标：它从来不落库，且「回到开场白」等于清空整个对话，破坏面太大，不给这个入口。
- 界面侧要二次确认：Rewind 一次可能删掉很多条且不可撤销。
