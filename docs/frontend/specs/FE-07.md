# FE-07 · 点击朗读

## 架构与接口依据

本 SPEC 必须实现 [模块架构与接口](../ARCHITECTURE.md) 中对应阶段的端口、事件、状态与错误语义；通过 adapter 兼容现有实现。下方 AC 同时验证这些契约，无需启动其他真实模块。

需求与边界见 [模块 PRD](../PRD.md)，依赖遵循 [共享契约](../../modules/CONTRACTS.md)。

## 交付

[规划文档](../../PLAN_DEV_DEBUG_WORKBENCH.md) F1 的「点击发音」：在聊天页点一条消息就念出来，念到哪句就把那句亮出来。

复用既有链路，不新增音频逻辑：`SpeechQueue.speak()` + 现有输出引擎（系统合成或云端合成，取决于组合根装的是哪个），高亮走字幕那一套 `locateSentence` / `splitCaption`。语言由队列按句现判（`speechLanguageFor`），不需要用户选。

- 负责范围：`VoicePresenter` 的两个命令与一个快照字段、气泡正文的高亮渲染、操作行里的朗读入口、按行映射高亮的 domain 纯函数。
- 不做：不改 `SpeechOutputEngine` / `SpeechQueue` 契约；不加语速/音色设置项（已有全局设置）；不做整段连播多条消息；不碰 Live2D 口型。

## 两条边界的取舍

1. **语音会话开着时不接朗读请求**。机器只有一套嗓子，输出队列也只有一个。会话进行中点气泡会 `queue.begin` 掉正在播的那一轮，让那一轮的交付回执永远等不到（只能靠超时兜底）。所以会话开着时说话权归会话，朗读入口不可用。
2. **同一条再点一次＝停止**。用户第二次点同一条的意思只可能是「别念了」，不该重头再念一遍。

| AC | 模块内验收 |
| --- | --- |
| FE-07-A | 点朗读：文本按句入队交给输出引擎，`speakingMessageId` 指向这一条；念完自动清空 |
| FE-07-B | 高亮：逐句推进，`locateSentence` 找不到范围时整段不亮（宁可不亮也不亮错位置）；停止后高亮清空 |
| FE-07-C | 同一条再点一次＝停止：输出引擎收到 stop，状态清空，不重头念 |
| FE-07-D | 语音会话开着时朗读请求被拒（不入队、不改状态）；单句合成失败可见但不打断整段 |
| FE-07-E | 按行映射高亮是 domain 纯函数并单测覆盖：多行文本里高亮只落在它所在那一行，跨行只亮本行那一截 |
