# FE-04 · 双语对照字幕去重

## 架构与接口依据

本 SPEC 必须实现 [模块架构与接口](../ARCHITECTURE.md) 中对应阶段的端口、事件、状态与错误语义；通过 adapter 兼容现有实现。下方 AC 同时验证这些契约，无需启动其他真实模块。

需求与边界见 [模块 PRD](../PRD.md)，依赖遵循 [共享契约](../../modules/CONTRACTS.md)。

## 背景

气泡里正文和中文小字显示同一句话两遍（[规划文档](../../PLAN_DEV_DEBUG_WORKBENCH.md) §0.1 的现象）。

查证结论与规划文档的判断不同，据此收窄范围：

- `prompt.ts` 的输出契约本来就写明「整句本来就是中文时，两个字段写成一样即可」，`CODE_SWITCH_RULE` 又刻意规定日/中/英无主次、不设默认语言。模型把 `replyText` 与 `translation` 返回同一句是**符合**提示词的，**因此本 SPEC 不改提示词**，也不引入「replyText 必须是日语」这类与角色设定冲突的约束。
- 真正缺的是展示侧判定：`App.tsx` 的次级字幕只受 `showTranslation` 开关控制，没有「与正文是同一句就不显示」这一层。规划文档称其为「无条件渲染」，措辞需更正。

## 交付

在 domain 层给出「次级字幕是否值得显示」的判定，并接到两个现有消费者：桌面气泡与手机终端 payload。

- 不改 `ReplyEnvelopeV1`、不改 `prompt.ts`、不新增存储接口、不动解析器容错路径。
- 判定只比较「是不是同一句」，不按语言判断。

| AC | 模块内验收 |
| --- | --- |
| FE-04-A | `translation` 与正文同句时判定返回空串；仅差空白、标点或英文大小写仍算同句 |
| FE-04-B | `translation` 确实是另一句时照常返回；正文为纯汉字日语（「大丈夫」）不被按语言误杀 |
| FE-04-C | 手机终端 payload 走同一判定，同句时不下发 `translation` 字段；空翻译等既有行为不变 |

证据：`src/domain/conversation.test.ts`、`src/domain/remote.test.ts` 的定向 vitest 运行与退出码。本仓库无 DOM 测试环境，界面接线以「组件只转发 domain 判定、无自有分支」为可审阅依据。

只执行当前 SPEC 的本模块测试；其他模块使用 fake/mock。验收报告放 `../reports/FE-04_ACCEPTANCE.md`。重试按钮、撤回、重新生成、Rewind 不在本 SPEC。
