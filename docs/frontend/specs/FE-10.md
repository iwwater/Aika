## 交付

规划文档的 F5 与 F6，两个新页签。

- **F5 能力调用视图**：一轮之内各项能力做了什么——上下文检索到哪些来源、哪些来源被丢掉及原因、记忆抽取出几条、表情包挑了哪个、动作有哪些、语音念了几句。**按现有能力如实展示**：这个仓库的 tool call 面很窄（`actions` 只有 sticker 一种），页面不假装有一套通用工具链。
- **F6 数据流图**：两张。① plugin 依赖拓扑，从 `kernel.describe()` 的 `requires`/`provides` 现算（CORE-09 的用途），所以图不会与代码漂移；② 一轮的数据流，按这一轮**实际发生**的事件点亮，没发生的阶段显示为未走到。

## 边界

- 不做 F7 记忆管理页、F8 存储浏览、F9 成本页。
- 不引图形库：内联 SVG + 简单分层布局（规划文档 §3 F6 的约束）。
- 不做图执行引擎、不做可编辑拓扑。
- 未满足的 `optional` 依赖要**显式列出来**而不是当作不存在——「能力缺失即 token 不注册」是本仓库的常态，看不见缺了什么等于看不见一半装配。
