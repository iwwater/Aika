# FE-31 · 桌宠陪伴会话、主动读屏与点击对话

状态：待实现/验收；2026-09-14 用户补充的首版必需范围。需求见[专项 PRD](../PRD_ENVIRONMENT_AND_LIVE2D.md)“桌宠陪伴补充”。本次更新规格，不宣称代码或设备验收完成。

## 目标与依赖

开启陪伴后自动运行获授权的读屏；支持主动搭话、安静陪伴、点击读屏对话与普通聊天。复用唯一主窗 Runtime，pet 只是受控用户交互入口。

前置 FE-18/19 的感知与授权、FE-20 窗口、FE-22 发送预约、[FE-32](FE-32.md) 屏幕文本上下文端口。可用外部端口 fake 独立验生产会话控制器；完整真实验收需相应生产实现。Live2D 不阻塞会话逻辑，最终产品验收仍需 FE-28/29。

## 用户流程与状态

| 操作 / 模式 | 行为 |
| --- | --- |
| 初次“开启陪伴” | 展示范围（主显示器上的前台窗口）、本地OCR、用于当前Provider的受限屏幕摘录、主动/安静选择；用户一次确认后创建会话并启用获授权能力，不要求再逐个找技术开关 |
| 已授权后开启 | 使用已保存范围启动，直接显示“主动陪伴·正在读屏”或“安静陪伴·正在读屏”；范围或Provider外发边界变化需重新确认；应用启动本身不自动采集 |
| 主动陪伴 | 有意义的画面文本变化→本地OCR→候选筛选→统一主动频控→Runtime→字幕/音频/角色；没有变化不循环请求LLM |
| 安静陪伴 | 可更新本地短时上下文，但禁止所有非用户触发的陪伴消息和时间tick打扰；点击或输入才回复 |
| 点击角色 | 展开快捷操作：“看屏幕聊聊”“聊两句”“暂停读屏”“结束陪伴”“打开主窗口”；拖动结束不算点击 |
| 看屏幕聊聊 | 明确用户请求，一次性刷新当前屏幕上下文，然后发起一轮对话；静止画面也能读；有冷却或OCR失败时显示状态，不静默无反应 |
| 聊两句 | pet轻量文本输入/发送，消息走主窗既有用户发送路径；不要求先打开主窗；支持不带屏幕上下文聊天 |
| 暂停读屏 | 停止该会话采集/worker并清空屏幕上下文和候选，pet保留；普通聊天可用，“看屏幕聊聊”可明确授权一次性采集，完成即释放 |
| 结束陪伴 / 关闭桌宠 | 撤销该会话generation、停止其采集/自动候选、清除缓存并关闭pet；不取消主窗已有用户对话或TTS |

窗口穿透开启时主窗保留同等交互入口及关闭穿透。显示创建中、读屏中、暂停、无权限、识别失败、模型不可用、发送中状态；已创建窗口不能冒充整个陪伴会话启动成功。主窗最小化仍陪伴；主窗真正退出则会话结束，不假定后台Runtime存在。

## 控制、权限与消息语义

- 新建主窗 `CompanionSessionController`，模式 off/active/quiet，独立readState和generation；状态/配置键归既有settings端口，默认off。它协调已有传感器，不另建OCR循环或Runtime。
- 新增 `pet.intent.v1 { requestId, petEpoch, kind, text? }`，kind仅 talk/screen_talk/pause_reading/end_session/open_main。Rust校验真实窗口label，主窗校验当前会话、长度(text≤2000字符)、请求ID与epoch；120秒内至多缓存256个ID去重，旧epoch丢弃。pet不得提供system prompt、source、Provider、路径或工具调用参数。
- 点击/输入在可信主窗被映射成既有用户触发的submit，记录“看屏幕聊聊”等真实用户操作，屏幕证据保持environment来源，不能把OCR摘录拼成用户亲口文本。若需新增来源元数据，向后兼容登记共享契约。
- 手动请求不受主动每日6条/90分钟限制或主动开关限制，仍走用户路径的busy/取消规则；有当前轮时显示“等待/打断并发送”，不擅自丢弃或取消。连续相同点击发送中只接受一次；双击不发两轮。
- 主动陪伴首版继续默认共用每天6条、90分钟间隔与勿扰，不额外开第二套额度。界面显示“主动回应较少/冷却中”；点击对话始终可用。产品不承诺每次OCR变化都会搭话；高频陪伴偏好不在本次擅自放宽。
- 主动新文本需有效置信度、相同前台内容稳定≥3秒、与上次已处理文本规范化差异≥20%；无可靠busy观测不主动发送。锁屏/会话非活动强制停止读屏与发送，解锁不回放积压候选。主动与用户同刻竞争时用户优先，未提交的自动候选撤销。
- 安静模式门禁在统一自动发送预约处执行，不能只断开OCR订阅而让时间tick继续说话；不改变用户发送路径。
- 会话只停止自己取得的source租约；实现若尚不支持多持有者，明确单一所有者并拒绝重复启动。结束陪伴不得误停用户独立开启的感知；全局“停止全部感知”仍撤销所有租约并将会话读屏标为暂停。
