# FE-05 · 失败轮重试

## 架构与接口依据

本 SPEC 必须实现 [模块架构与接口](../ARCHITECTURE.md) 中对应阶段的端口、事件、状态与错误语义；通过 adapter 兼容现有实现。下方 AC 同时验证这些契约，无需启动其他真实模块。

需求与边界见 [模块 PRD](../PRD.md)，依赖遵循 [共享契约](../../modules/CONTRACTS.md)。

前置：[CORE-08](../../core/specs/CORE-08_MESSAGE_DELETION.md)（`AikaStorage.deleteMessages`）已通过。

## 交付

失败气泡上的重试入口，以及它背后的「重跑这一轮」命令。

重试不是「再发一次」：一轮失败后库里已经有两行——`CompanionRuntime` 在生成前落的用户消息，和 Presenter 判失败后落的失败气泡。直接重投会留下两条相同的用户消息加一条永久失败气泡。所以顺序是**先整轮删掉，再用同一句话重新提交**。

归组依据是 `runtimeTurnId`：Runtime 给用户消息写 `runtimeTurnId: turn.id`，Presenter 给失败气泡写 `runtimeTurnId: handle.turnId`，同一轮的两行天然同号。旧数据没有这个字段，回退到「失败气泡之前最近的那条用户消息」。

- 负责范围：domain 归组纯函数、Presenter 的 `retry(messageId)` 命令、Hook 转发、气泡按钮与样式。
- 不做：撤回、重新生成、Rewind、用户消息编辑；不改 `CompanionRuntime` 契约；不做失败原因分类与重试退避；不动记忆候选（撤回是否连带撤记忆见 [规划文档](../../PLAN_DEV_DEBUG_WORKBENCH.md) §7 问题 4，本 SPEC 不回答）。

| AC | 模块内验收 |
| --- | --- |
| FE-05-A | 重试只对失败的 assistant 气泡可用；正常消息不出现入口；找不到用户原话的失败轮（主动消息）不出现入口 |
| FE-05-B | 点重试后：该轮两行先从存储与界面消失，再以同一句原话重投；重试成功后库里只有一条该用户消息，没有失败气泡残留 |
| FE-05-C | 重试中不可重复触发（`sending` 时入口禁用）；重试再失败会得到新的失败气泡且仍可再次重试 |
| FE-05-D | 归组逻辑是 domain 纯函数并单测覆盖（含旧数据无 `runtimeTurnId` 的回退、主动轮返回 null）；Presenter 命令在无 React 的 node 环境用 fake Runtime + fake storage 驱动 |

证据：`src/domain/conversation.test.ts`、`src/presentation/companionPresenter.test.ts` 的定向 vitest 运行与退出码。本仓库无 DOM 测试环境，按钮接线以「按钮只派发 Presenter 命令、无自有逻辑」为可审阅依据。

只执行当前 SPEC 的本模块测试；其他模块使用 fake/mock。验收报告放 `../reports/FE-05_ACCEPTANCE.md`。
