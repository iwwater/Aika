## 设计

Rust（`src-tauri/src/foreground.rs`，`cfg(windows)`）：

- invoke `environment_foreground_enable(enabled: bool)`：true 时在专用线程 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)`；回调内 `GetWindowThreadProcessId` + `QueryFullProcessImageNameW`（取文件名）+ `GetWindowTextW`，只向获授权主窗口推送 `environment://foreground`，包含sourceId/eventId/epoch/seq/process/title及测点时间，禁止全WebView广播；false 时卸载 hook。
- invoke `environment_foreground_current()`：返回当前前台（hook 触发前的初始状态）。
- 非 Windows 编译目标：模块整体 `cfg(windows)`，命令不存在——TS 探测即知能力缺失。

TS：

- `src/services/environment/foregroundSource.ts`：`createForegroundSource(bridge)` 实现 `EnvironmentSource`；bridge 形状同 `services/remote/bridge.ts`（invoke/listen 注入，便于 fake）。`start(emit, signal)` 先await listen，再enable，再current兜底；按epoch/seq去重，停止同时unlisten/disable。
- `src/services/environment/contextSource.ts`：`createEnvironmentContextSource(monitor)` 实现 LLM 已发布的 `ContextSource`（`id: "environment"`，`section: "environment"`——`domain/context.ts` 已预留该 section）。`load` 把 snapshot 转成一条摘要 snippet：应用名 + 持续时长 + 最近事件 kind 计数；**窗口标题原文不进上下文**。
- 装配：tauri 宿主插件组通过不读取窗口内容的能力探测成功才把 foreground source 放进 `EnvironmentSourcesToken`；环境插件提供 `EnvironmentContextSourceToken`；`ContextSourcesToken` 的提供点追加 `tryResolve` 环境源（在 memoryPlugin 现 provider 内追加或独立装配插件，实现时定；registry 每 token 单提供者，禁止两处 provide 同一 token）。
- 设置：`SETTING_KEYS.environmentForegroundEnabled`（`"environment.foregroundEnabled"`，默认 `"false"`）；App.tsx 设置区新增环境感知分组，开关即 enable/disable。

## 取舍

**hook 事件式，不做常驻轮询**：`EVENT_SYSTEM_FOREGROUND` 由系统推送，空载成本≈0。探测失败就如实降级为「无此能力」，不写兜底轮询去掩盖。

**默认关 = Rust 根本没装 hook**：开关关闭时 TS 不调用 enable，Rust 侧不存在 hook；不是「装了但不转发」。隐私边界可在代码路径上验证，而非靠过滤。

**Context 注入复用 `ContextSource`，不动 Assembler**：`environment` section 与 `ContextSource` 都是 LLM 侧早已发布的接口（注释里本来就写了环境由后续实现），本 SPEC 只新增一个源实现与注册；Assembler「缺源不失败」的降级语义原样生效。

**只取进程名与窗口标题**：标题可能含隐私文本（文件名等），所以标题只存在于 snapshot 与调试显示；进 LLM 上下文的摘要由 contextSource 控制为「应用名 + 时长」。

## Win32可执行性与隐私出口

SetWinEventHook所在专用线程必须有消息循环；停止投递退出消息并在该线程Unhook，回调快速入有界队列，防重入/关闭竞争。能力探测只返回支持标记，不在默认关闭时调用current读取标题。完整窗口标题只驻留获授权本地主窗内存，日志/Trace使用受控摘要。

依据：[Microsoft SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)。补Rust生命周期测试：初始化失败/停止前事件/重复开关资源释放；真实<1s与20次切换仍需设备。
