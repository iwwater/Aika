# FE-33 · 环境链路真机装配验收（不含 Live2D）

状态：READY，2026-09-14 新增。依据：[专项 PRD](../PRD_ENVIRONMENT_AND_LIVE2D.md)、[FE-31](FE-31.md)/[FE-32](FE-32.md) 验收报告里的遗留设备项、[共享契约](../../modules/CONTRACTS.md)「FE-32/FE-31 追加」节。

**为什么单立一份**：FE-18～22、31、32 的 PASS 全部是「模块内/逻辑轨」，而生产装配是 2026-09-14 才第一次接上的（此前 `environmentPlugin` 从未被 `kernel.use()`、两个 source 没有调用方、busy 观测者无提供方、FE-19 上下文源没进 `contextSourcesPlugin`、`ScreenState` 没 `.manage()`），**这条新装配从未在真实 Tauri 进程里运行过一次**。FE-30 要等角色线（FE-27～29）才能做，中间不能出现「六份 SPEC 都写着 PASS，但没人知道真机上到底起不起来」的空窗。本份只回答一个问题：**接上的这条线，在真机上是不是真的通的**。

## 进入条件与范围

前置：Windows 真机 + 可运行的 Tauri 桌面构建（`cargo build --release --features custom-protocol`，缺该 feature 会白屏，见 A6 记录）。需要用户在场操作与目视；需要一份可用的 Provider 凭据才能做 E。

范围**只有**「装配是否真的接通、真机传感器是否真的按 SPEC 行为」。**不含**：Live2D 渲染与口型（FE-27～29）、30 分钟组合负载与帧率/内存预算（FE-30-I/N）、FE-32-A 的冻结集 CER（缺真实素材，另行解决）。本份通过**不构成** FE-30 通过；FE-30 的 J～N 仍须在角色线完成后独立执行。

不新增业务架构。发现缺陷退回对应 SPEC 定向修复，不在验收脚本里绕过。截图与录屏只用非私人画面。

## 证据要求

每项记录：真机配置（Windows 版本、显示器分辨率与 DPI 缩放、构建号）、操作步骤、观测值、截图或录屏（非私人画面）。性能项给测量方法与时间序列，不只给一个数。

**不许**：把逻辑轨的测试结果抄进本报告充当设备证据；把「没观察到问题」写成通过；用 fixture 图代替真实窗口截图。做不到的项如实记 NOT RUN / BLOCKED 并说明缺什么。
