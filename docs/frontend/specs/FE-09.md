# FE-09 · 开发者模式入口与 Trace 查看页

## 架构与接口依据

本 SPEC 必须实现 [模块架构与接口](../ARCHITECTURE.md) 中对应阶段的端口、事件、状态与错误语义；通过 adapter 兼容现有实现。下方 AC 同时验证这些契约，无需启动其他真实模块。

需求与边界见 [模块 PRD](../PRD.md)，依赖遵循 [共享契约](../../modules/CONTRACTS.md)。

前置：[LLM-06](../../llm/specs/LLM-06_TRACE_PROTOCOL.md)～[LLM-08](../../llm/specs/LLM-08_TRACE_SOURCES.md) 已通过（七种事件都有真实来源）。

## 交付

规划文档的 F2（开发者模式入口）与 F4（Trace 查看页）。数据已经在了，这一份是让人看得见。

- **F2**：设置里的「开发者模式」开关（持久化），开启后标题栏出现 DevTools 入口；工作台是独立页签，不与聊天页耦合（沿用现有 state 切换，不引路由库）。同处提供 Trace 的两个开关——LLM-07 只交付了服务与键，界面在这里补上，并把持久化的值在启动时灌回去。
- **F4**：轮次时间线。每轮一行：状态、耗时、首 token 延迟、chunk 数、估算 token、错误码；展开看这一轮的完整事件序列与各阶段耗时；另有 JSONL 原始视图（对齐 waku 的 Ops Tab）。

## 边界

- 不做：F5 能力调用视图、F6 数据流图、F7 记忆管理页、F8 存储浏览、F9 成本页——都是各自独立的 SPEC。
- 不做实时推送：页面按「打开时读 + 手动刷新」取数。sink 没有订阅接口，为了一个调试页给它加一套推送不值得。
- 不改 Trace 协议与 sink 端口。
- 页面组件放 `src/pages/`，不往 `App.tsx` 堆（规划文档 §6 的约束）。

## 归属划分

| 层 | 放什么 | 为什么 |
| --- | --- | --- |
| `domain/traceView.ts` | 事件流 → 轮次摘要 / 单轮详情 / JSONL 文本的**纯函数** | 这是唯一有判断的地方（缺事件怎么算、耗时从哪减到哪），必须能单测 |
| `presentation/devToolsPresenter.ts` | 读 sink、刷新、开关读写与持久化 | 与 React 无关；无 DOM 测试环境时它是页面行为的唯一可测面 |
| `pages/DevToolsPage.tsx` | 渲染 | 只转发 domain 的结果与 Presenter 的命令，没有自己的判断 |

| AC | 模块内验收 |
| --- | --- |
| FE-09-A | 轮次摘要：状态、耗时、首 token、chunk 数、估算 token、错误码都取自对应事件；某个事件缺失时对应字段是 null 而不是 0 |
| FE-09-B | 只有 `turn_start` 没有 `turn_end` 的轮次（还在跑或进程被杀）标为「未结束」，仍然出现在列表里，不被静默丢掉 |
| FE-09-C | 列表按最近优先；单轮详情按 seq 升序并给出每一步相对轮次开始的偏移 |
| FE-09-D | Presenter：能力缺失（没装 Trace）时给出明确的「未启用」状态而不是空列表；刷新会重新读 sink |
| FE-09-E | 开关：开发者模式与 Trace 两个开关都持久化，启动时从存储灌回；关掉 Trace 后新轮次不再产生事件（由 LLM-07 的行为保证，这里只验开关真的写进了服务与存储） |
| FE-09-F | JSONL 视图每行一个事件、可被 `JSON.parse` 逐行解析回来 |

证据：`src/domain/traceView.test.ts`、`src/presentation/devToolsPresenter.test.ts` 的定向运行。无 DOM 测试环境，页面渲染以「组件只转发」为可审阅依据。

只执行当前 SPEC 的本模块测试；其他模块使用 fake/mock。验收报告放 `../reports/FE-09_ACCEPTANCE.md`。
