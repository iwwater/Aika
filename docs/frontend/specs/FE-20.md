## 架构与接口依据

需求与边界见 [模块 PRD](../PRD.md)「桌宠窗口」，依赖遵循 [共享契约](../../modules/CONTRACTS.md)。

MVP 4「桌宠窗口」的窗壳落地。关键架构事实：Tauri v2 多窗口 = 多 JS context，pet 窗口**拿不到主窗口的注册表**——它是薄展示端，展示态经 Rust 中继（与手机 remote 页同款模式）；全产品仍然只有一套 CompanionRuntime。

## 设计

Rust（`src-tauri/src/petWindow.rs`）：

- invoke `pet_window_show()`：`WebviewWindowBuilder` 创建 `pet` 窗口（transparent、decorations: false、always_on_top、skip_taskbar、约 320×420（CSS逻辑像素，DPI需真机验证）、`url: index.html?view=pet`）；已存在则 show + set_focus。
- invoke `pet_window_hide()`：**销毁**窗口（不是隐藏）。
- invoke `pet_window_set_click_through(enabled)`：`set_ignore_cursor_events`。
- invoke `pet_window_broadcast(payload)`：主窗口 TS 转发展示态，Rust `emit_to("pet", …)`。

TS：

- `src/main.tsx`：读 `?view=pet` 渲染 `src/pet/PetApp.tsx`，否则现 App。静态约束：`src/pet/` 不得 import `services/runtime|storage|voice`。
- `src/pet/relay.ts`（主窗口侧）：订阅 companionPresenter 快照，节流转发 `{ mood, speaking, currentSubtitle, lastProactive }` → `pet_window_broadcast`。
- `src/pet/PetController.tsx`：拖拽（drag region）、左键单击回主窗（set_focus）、右键菜单（点击穿透开关 / 隐藏 / 打开主窗）。
- `src/pet/Bubble.tsx`：显示最近一条 proactive 消息与当前说话字幕；说话结束后数秒淡出。
- 形象：复用 `components/AvatarPlaceholder`。
- 设置：`SETTING_KEYS.petWindowEnabled`（默认 `"false"`）；App.tsx 设置区开关。

## 取舍

**按需创建/销毁，不是常驻隐藏**：隐藏窗口仍占一份 webview 内存，且「窗口在」与「设置开着」会成为两个要同步的状态；销毁让状态只有一份。再次打开的创建延迟需实测，不预填数值。

**中继而不是共享状态**：多窗口 context 隔离是 Tauri 的产品边界。走 Rust 中继后，pet 窗口崩溃不影响主窗口编排，展示端的故障域是隔离的。

**气泡内容 = proactive 消息 + 说话字幕**：环境事件本身不直接上气泡——要不要说话是 FE-22 policy 的决定；环境驱动的消息走 Runtime 后自然出现在气泡里。pet 窗口**不做输入框**：交互只有「点回主窗」，避免第二个对话入口形成第二套编排。

**AvatarPlaceholder 先行**：Live2D 渲染与资产流水线是 MVP 4 既有待优化项，独立推进；窗口壳不阻塞在资产上。

## 主窗快照与命令权限

pet ready后请求一次主窗当前快照，再订阅增量，不能只靠创建前已广播的事件；speaking来自VoicePresenter，字幕/主动内容来自各自已授权Presenter，通过主窗聚合，不假定CompanionPresenter含全部字段。销毁取消定时器，开关状态与菜单隐藏保持一致。

Tauri自定义命令需审查AppManifest/permissions及窗口label检查；不能仅在capabilities列名就假定权限已生效。宠物窗口不能拥有通配主窗能力，多个capability的权限合并需检查。[Tauri能力文档](https://v2.tauri.app/security/capabilities/)。
