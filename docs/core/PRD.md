# 运行时内核与装配 · 模块 PRD

产品依据：[总 PRD](../PRD_V0.4.md)。本文件是模块边界，方案见 [重构计划书](REFACTOR_PLAN.md)，执行任务见 [SPEC 索引](SPEC.md)。

## 目标

把 CompanionRuntime、Memory、Storage、LLM Provider、语音引擎统一挂进服务注册表，由宿主装配、插件提供；React Hook 降级为只订阅状态、只派发命令的适配层。目标是让新能力以「新增插件」而不是「再改一次编排函数」的方式接入。

## 范围

- 负责：内核与服务注册表、插件与能力契约、宿主能力抽象、组合根、Presenter 层、旧编排路径的迁移与下线。
- 不负责：模型协议解析、记忆检索算法、ASR/TTS 算法、页面视觉；也不实现抓屏、情感识别、Live2D、Three.js、Unity。
- 依赖通过 [共享契约](../modules/CONTRACTS.md) 注入；本模块只改「谁装配、谁调用」，不改各模块既有算法与输出协议。

## 与其他模块的关系

CORE 是 LLM/STT/TTS/前端四模块的装配层，不取代它们的 SPEC。CORE 交付的接口一旦冻结，FE-01 的 Runtime 桥接、LLM-04 的后台维护队列、未来的表现层能力都在同一套注册表上接入。触及共享契约时按 [集成 SPEC](../integration/SPEC.md) 在 INT-01 安排消费者兼容测试。

## 开发方式

六份 SPEC 逐份下发，一次只执行一份。每份交付后应用必须仍可运行；高风险的编排切换带运行期开关，可回滚而不 revert 代码。当前小阶段只测试本模块与受影响的既有契约测试；必须联调或大任务完成后才进行全流程调试。验收报告与证据存放本目录 reports/。

模块完成与全产品完成分别标记。真实模型/音频/设备样本不能由 fixture 冒充；既有 DEFERRED 项不因本次重构改标签。具体执行要求见 [测试规则](../modules/TESTING.md)。
