## 一、结论先行

1. **「说日语被识别成中文」在本机 whisper 路径上未能复现**：57 段日语素材，**判成中文 0 段**。唯一的语言误判是 1 段判成**韩语**（S05，1.8%），且该段是笑声/非语音段。
2. **语言判定不是瓶颈**：56/57 判为日语（98.2%），cli 与 server 两路结论一致（同段同错）。
3. **真正的瓶颈是「真人情绪化语音的解码质量」**：合成语音 CER 中位 **0.0**，真人语音 CER 中位 **0.2198**（**22 倍差**），真人 6 段**没有一段全对**。
4. **指定 `language=ja` 零收益**：auto 与 ja 两路转写 **56/57 段逐字相同**，唯一差异来自语言误判段被强制改写。→ 靠改 `language` 参数修复本问题的方向**没有证据支持**。
5. **发现一个 SPEC 未列的维度**：解码策略（beam search 5 vs greedy）在**困难素材**上影响实质（去标点后 33/57 段内容不同，且集中在真人素材）；在合成语音上两者几乎一致。

## 六、诚实边界（结论的适用范围）

- **素材不是实时麦克风语音**：本次用的是离线 WAV 文件（ASMR 表演语音 + 合成语音），不含实时链路里的噪声、VAD 切分边界、极短片段。**不能据此断言「真人实时说话不会出问题」**。
- **用户报告的现象未复现，但未被否定**：57 段 0 次判成中文 ≠ 永远不会。可能来源（**均为假设，未被本次证据区分**）：① 当时实际走的是 Web Speech 退路（STT-04 已证该路径会产生「日语→中文」并已修）；② 实时麦克风的极短/含噪片段（本次 S05 判 ko、S11 乱码是同类的边缘案例证据）。
- **只测了一个模型**：H1（模型规模）**没有对照数据**。所有结论只能表述为「base 模型当前配置下的表现」。
- **S 组参照文本不可靠**：来自 ASR 产出（非人工校对），因此 S 组**只用于语言判定统计，未计入任何 CER**。个别条目（如 S24「オニーザン」vs 参照「お兄さん」）看起来是**参照错误**而非识别错误。
- **R 组与 S 组重叠**：R01=S01、R02=S02、R03=S16、R04=S03、R05=S31、R06=S36（md5 相同）。R 组不是独立样本，只是「有精确参照」的真人子集；全 57 段实际唯一文件 **51 个**。
- **情绪维度无法归因**：真人组（失败所在）没有 f0_cv 标注。
- **时长与素材来源共线**：不能声称「长音频更差」。
- **_mc 0 / -tp 0 与生产对齐，但两路前端默认值不同**：cli 用 beam search 5、server 用 greedy，这两组数据是并列观测，不是同一配置的重复测量。
