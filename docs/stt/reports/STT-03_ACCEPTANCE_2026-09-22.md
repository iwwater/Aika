## 关键发现 · 日语/混说的 auto 语言检测不稳（非 turbo 退化）

日语 5 句里最典型的两句：

| # | 台词 | 识别 | 归因 |
| --- | --- | --- | --- |
| 4 | アイカちゃん、おはよう。今日も元気だよ。 | **"Agachang Ohio? Ima mau kinky dayo."** | auto 把日语**误判成英语**，整句罗马字音译（专有名词「アイカ」→"Agachang"） |
| 16 | 今日の天気は really nice だね。（混） | **"Kjóa tínki var vel næsta ne"** | auto 把日语为主的混说句**误判成冰岛语** |

这**不是 turbo 变差**，而是 whisper `language=auto` 在日语上的已知弱点——与 STT-05 结论「whisper 天然对 en/zh token 更自信、真日语 logprob 反而更低」一致。其余日语错句（「聞けとれなかった」「もう一回→も一回」「うう分かった」）是**解码级残错**，属真人情绪语音解码质量问题，方向与 STT-07 一致。

**更重要的链路差异**：生产前端 `whisperClient.ts` 只送 `language=auto` 直接返回，**没有** `gateway_stt.py` 里的「语言纠偏」逻辑（`STT_LANG_WHITELIST` + 强制日语重跑 + 字符集裁决）。也就是说：

- **demo 网关**（`gateway_stt.stt()`）：有纠偏，会把「Agachang…」这类 auto 误判强制日语重跑翻案；
- **生产前端本地引擎**（`whisperInput.ts` → `whisperClient.ts`）：**无纠偏**，auto 误判会直接进对话。

→ 这是一条**真实缺口**，但**不在 STT-03 范围**（STT-03 只验收设备与识别链路，不修质量）。它应立一条独立 SPEC：把 demo 网关验证过的语言纠偏下沉到生产前端（或等价机制），属于 STT-08「落地为生产默认」后的必要跟进。**已据此立 [STT-09](../specs/STT-09.md)（SPEC 冻结，待合作者重构落地后执行）。**

## 结果 · 延迟

| 语种 | 延迟中位 |
| --- | --- |
| 整体 | **222 ms**（min 192 / max 404） |
| 日语 | 321 ms（长句 + 语言检测摇摆时更慢） |
| 中文 | 210 ms |
| 英语 | 222 ms |
| 混说 | 225 ms |

与 STT-08 契约复跑（jfk 稳态 217.59 ms）一致；日语长句与语言摇摆句（如第 1 句 404 ms、第 2 句 352 ms）偏慢，符合「auto 检测摇摆→可能触发额外路径」的预期。

## 方法偏差（如实记录）

1. **切段用「手动触发」而非生产 Silero VAD 自动切段**：因为 onnxruntime-web 在 Vite dev 下有 wasm 动态加载摩擦（`/ort/ort-wasm-simd-threaded.mjs` 被 dev server 当源码 404），本页退化为手动切段以隔离「切段」与「识别」两个变量。**识别质量与延迟结论不受此影响**（转写走的是与生产一致的端点/字段/编码）；但 STT-03-A 的「停顿拆轮」语义需在真实 Silero VAD 下复验。
2. **延迟口径**：本页「点击→返回」是转写延迟，**不含** App 内 turnReady 调度（`turnEnd.ts` 的尾静音等待 + 语义判断）。STT-03-B 的 P95 仍需 App 内测。
3. **语言判定的「完全匹配」口径**：忽略标点/空白后逐字相等。混说句里「ありがとう→arigato」（拉丁音译）、「アイカ→Akijang」这类即使语义对也记 `ok=false`，故混说匹配率被严格口径压低了——这不代表「完全不可懂」，只代表「未逐字还原」。

## 结论

- **识别链路本身连通、稳定**：20 句全部成功转写，无一次失败/超时；延迟中位 222ms，与 STT-08 契约复跑一致。
- **识别质量呈现清晰的语言分化**：英语 4/5、中文 3/5 尚可；**日语与混说是短板**，根因是 `language=auto` 的语言检测不稳 + 真人情绪语音解码残错——与 STT-05/07 结论一脉相承，非本次切换引入。
- **发现一条跨 SPEC 缺口**：生产前端本地引擎**缺少 demo 网关已有的语言纠偏**，应另立 SPEC（见上）。
- **STT-03 三个 AC 均未完全通过**：A 部分（手动切段下）、B/C 未测。真正的 B/C 需在 App 内 + 真实 Silero VAD 下复验。

## 后续

1. 立 SPEC「生产前端语言纠偏下沉」（把 `gateway_stt` 的语言纠偏逻辑纳入 `whisperInput`/`whisperClient` 或等价层），依据是本次日语 0/5 的实证。
2. STT-03-B/C 待 App 内测试（需合作者重构落地后的前端，或当前 Tauri 版可直接测则安排）。
3. 本报告不据此宣称「混说已修好」或「日语识别达标」——相反，它量化了「日语 auto 检测」是当前本地引擎的真实短板。
