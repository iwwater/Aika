# 待办、缺陷与技术债

这三个列表分别管理不同性质的工作，不能互相替代。

| 类型 | 判断标准 | 入口 |
| --- | --- | --- |
| **TODO** | 用户想做，但尚未形成当前 RPD | [全局 TODO](../next/TODO.md) |
| **TOFIX** | 已确认存在、需要复现和修复的 Bug/回归 | [0.65 TOFIX](../next/0.65/TOFIX.md)、[0.75/0.79 现场记录](../next/0.75/TOFIX_20260923.md) |
| **DEBT** | 不是当前故障，但结构性成本会阻碍后续维护/交付 | [DEBT](DEBT.md) |

## 生命周期

1. 新想法先进入 TODO；只有范围、边界和完成标准稳定后，才升级为 RPD。
2. 发现异常先登记 TOFIX，写清复现、影响、证据和状态；修复步骤进入对应 SPEC，结果进入 REPORT。
3. 已知但不影响当前功能、且需要未来架构工作偿还的事项写 DEBT，不把它伪装成 Bug 已修复。
4. 条目状态使用 `OPEN`、`IN_PROGRESS`、`BLOCKED`、`DONE`、`DEFERRED`；`DONE` 必须有链接证据。

## 录入规则

- 每项拥有稳定 ID，不因移动文件而改 ID。
- 不复制整段需求；使用链接关联 RPD、SPEC、ADR、CONTRACT 和 REPORT。
- “源码存在”“模块测试通过”“用户现场通过”分别记录，不能合并成一个 PASS。
