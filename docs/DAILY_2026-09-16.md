## 三、真实缺陷（本日最有价值的部分）

MVP-11 报告第 7 节记了 **10 条**，其中 1～7 来自浏览器跑真实模型，**8～10 只有真机会暴露**：

| # | 缺陷 | 性质 |
| --- | --- | --- |
| 1 | 缩放反馈回路（`model.width` 已含 scale，上一轮缩放喂进下一轮，模型被逐步放大到铺满画布） | 逻辑缺陷 |
| 2 | 换装注册竞态（用本地 ref 判据，异步设置先到会把切换锁死） | 逻辑缺陷 |
| 3 | `hidden` 语义失效（类选择器压过 UA 的 `[hidden]{display:none}`，MVP-10 承诺的「prepare 阶段不产生可见输出」其实一直没生效） | 回归缺陷 |
| 4 | 换装菜单项不重建（成功换装是 ready→ready，状态不变则菜单不重建） | UI 缺陷 |
| 5 | 上下文菜单末尾条目点不到（写死高度估算，条目变多后落到视口外） | UI 缺陷 |
| 6 | **换装后一帧都画不出来**（引擎模型贴图与渲染器共享，逐个 destroy 会破坏后续渲染）→ 改为整体重建舞台 | 引擎契约 |
| 7 | 旧舞台销毁抛 `reading 'next'`（同拍改 ticker 链表），会把**成功**的换装记成失败 | 并发缺陷 |
| 8 | **CSP 拦下 Pixi 的 eval 路径**，Live2D 真机上根本起不来（用户看到的是「Falling back to default renderer」）→ 改用官方 `pixi.js/unsafe-eval` 路径，**不放宽 CSP** | 真机独有 |
| 9 | **CSP 拦下 Pixi 的贴图解码 worker** → 补 `worker-src 'self' blob:`，并删掉两条被解析器忽略的无效源 | 真机独有 |
| 10 | **`dispose()` 中途抛错会跳过 DOM 清理，宿主还把切换记成成功**（切回 sprite 后 `.pet-live2d` 仍在文档里） | 真机独有 |

另外登记一条非缺陷的经验：**E2E 读像素必须用 `readPixels`，不能用 `drawImage` 到 2D 画布**——带 CSS filter 的合成上下文里后者会返回整帧不透明，把「画好了且背景透明」误判成「整块不透明」。

- **DEF-1（未修复，阻塞对外发行）**：`public/live2d/` 的 41 个文件被 vite 复制进 `dist/`，进而内嵌进 `petshell.exe`（exe 中可读出 41 条 `/live2d/…` 路径，与磁盘逐一对应，含 Cubism Core 与 Hiyori/Mao 的 moc3、贴图、动作、表情；约占包体 44%）。**gitignore 只挡 git、挡不住打包**，与「模型不入分发包」的声明冲突。
- **DEF-2（已修复并经人工真机复验）**：`renderer=live2d` 时整窗鼠标穿透——拖不动、点不动、右键菜单不出。根因：渲染器切换的提交顺序是「新实例 prepare/activate → 再释放旧实例」，而两个渲染器的 `dispose()` 都会 `onHitTargetChange(null)`，把新实例刚注册的命中元素覆盖掉；窗口命中测试恒 false → 持续 `setIgnoreCursorEvents(true)`。启动 fallback 恒为 sprite，所以只有「持久化 renderer ≠ sprite」才走到这条路径——这正是真机上「sprite 能拖、Live2D 拖不动」的原因。修复：pet-shell `a3d1d26`（命中元素按实例记录、只发布活跃实例的；单测 + 突变验证，重建后人工复验拖动恢复）。
- **Live2D 在 release 产物上的可见表现 PASS**：像素证据（[`MVP-13_live2d_hiyori.png`](integration/reports/evidence/MVP-13_live2d_hiyori.png)）+ 中文气泡逐字正确。
