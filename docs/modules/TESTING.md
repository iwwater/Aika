# 小阶段测试与验收规则

用户要求：**小阶段只测试自己的模块。** 不把整仓 `npm test`、全产品构建、真实跨服务链路或另一模块完成作为每个小阶段的默认门禁。

## 小阶段

1. 记录模块 ID、小阶段 ID、改动文件与 AC；执行明确的测试文件名单或该模块的独立测试配置。
2. 只 mock 其他模块、外部服务和设备；被测模块必须走生产代码。LLM 模块不能以 mock 的模型回答证明真人感，STT/TTS 不能以 fake 事件证明声学效果。
3. 命令在 `aika-crossplatform/` 运行，示例：`npx vitest run src/domain/character.test.ts src/domain/prompt.test.ts`。示例只覆盖相应已有文件，执行者须按实际变更补全名单；禁止使用 `--passWithNoTests` 冒充通过。
4. 模块级类型检查仅在有明确独立 tsconfig 时使用；全仓 `tsc` 不作为“小阶段模块检查”伪装。新增公共类型可做针对性编译 fixture；全局类型与生产打包留给 INT-01/03。
5. 每小阶段状态为 PASS/FAIL/BLOCKED/NOT RUN；明确后置的硬件/体验项目为 DEFERRED。报告区分工程实现完成、模块验收通过、集成未验收，三者不混用。
6. UI 用组件 harness 与 fake 数据；LLM 用生产适配 fixture、headless Runtime 和固定文本样本；STT 用固定音频/假 ASR；TTS 用固定文本/假输出引擎。付费真实请求只在既有授权范围内使用。

## 必要例外

若修改了共享契约、统一构建配置或跨模块桥接，不要求把整个产品测一遍，但必须列出受影响契约，在 INT-01 安排相应消费者兼容测试。报告可写“模块通过，集成待测”，不得因此宣称发布通过。改 Rust 的模块执行对应 Rust 模块测试；与 Rust 无关的小阶段不强制 Tauri 构建。

## 汇总验收

一个模块的本轮工程小阶段完成后，原任务审阅它的证据；尽量不重复跑测试。只有必须进行联调或明确定义的大任务/里程碑完成、并进入 [集成阶段](../integration/SPEC.md) 才运行跨模块链路、全量回归与打包。真实音频样本继续按用户已确认的后置安排，不阻塞当前 LLM 小阶段。

报告放 `docs/<module>/reports/<小阶段ID>_ACCEPTANCE.md`，证据放同目录 evidence/，不保存密钥或私人聊天/录音。每次新改动只复测受影响范围，不为了新增报告重跑未改模块。
