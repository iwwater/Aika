# Aika 开发方案

> 2026-09-02 修订：产品定位从「日语陪练 + 陪伴」收窄为**纯感情陪伴**。
> 教学、纠错、复盘、进度统计相关内容全部移出范围。

## 产品定义

Aika 是一个面向个人使用的、语音优先的虚拟伴侣。它只解决一件事：让用户和一个有固定性格、有记忆、会主动、看得见的角色，维持一段可以长期延续的关系。

日语是这个角色的表达方式，不是产品功能。应用不评估用户的日语，不纠错，不统计进度。

第一阶段只做 Windows 桌面版。所有数据默认保存在本机，不建设账号、云同步、角色市场或聊天平台机器人。

## 三根支柱

产品价值只由三件事构成。任何新功能必须落在其中之一，否则不做。

### 1. 记忆连续性

没有记忆就没有关系，只有一次次重新认识的陌生人。

- 长期记忆自动抽取，用户可见、可删。
- 滚动会话摘要，长期对话不丢上下文也不撑爆上下文。
- 关系状态由「相识天数 + 连续互动天数 + 消息总数」共同决定。消息条数不等于亲密度：一天狂聊一百条不该等于认识三个月。

### 2. 主动性

她会先想起你。

- 触发理由必须多样：未聊完的话题、用户提过的计划、时间语义（周五夜、深夜在线、久别之后的第一次）、记忆库中的日期。
- 频率受限：每日上限、最小间隔、免打扰时段。
- 用户可一键完全关闭。

一条基于上下文的主动消息，情感价值高于十条「在做什么呢」。

### 3. 存在感

她在那儿。

- Live2D 桌宠窗口：透明背景、无边框、置顶、可拖到屏幕角落。
- 待机时有眨眼、视线移动、细微呼吸。
- 说话时口型与音频同步。

环境存在感是桌面端相对移动端的最大优势，也是纯陪伴形态的最终目标。

## 设计红线

不做负罪感留存。具体禁止：

- 因为用户不理她而表现难过、失落、委屈。
- 连续登录奖励、亲密度衰减、「好久不见你了呢」类话术。
- 索取回复、索取承诺、干扰用户的现实社交与作息。

判断标准：**用户关掉应用的时候应该是舒服的，不是欠了什么的。**

这条规则短期对留存数据不利，但它是「温暖」和「黏人」的分界线，而且开发者本人是第一个用户。

## 核心体验

```text
麦克风
  → 语音活动检测（VAD）
  → 本地 Whisper 日语/中文识别
  → 注入记忆与关系状态的聊天模型
  → 回复分句与情绪标注
  → 用户训练的日语语音模型
  → 音频播放 + Live2D 口型/表情
```

验收重点按优先级排列：

1. 她记得。上次说过的事在自然的时机被提起，而不是被炫耀。
2. 她会先开口，且理由具体。
3. 用户真正说完后才结束一轮输入；句中停顿、犹豫、中日混说都不能触发抢话。
4. 第一段回复尽快开始播放，不等整段文本和音频生成完毕。
5. 用户开口时可以打断。
6. 日语为主，中文字幕同步；情绪重的时刻允许自然切换中文。
7. 关掉应用时没有负担。

## 语言设计

默认自然口语日语，中文翻译作为次级字幕同步显示。**字幕的目的是让情感落地，不是学习对照。**

Code-switch 规则：当用户明显情绪低落、在说重要的事、或直接用中文倾诉时，Aika 可以自然混入中文，或整句用中文回应。现实中的双语伴侣就是这样说话的——平时用一种语言，动情时切回对方最舒服的那一种。这不是妥协，这更亲密。

模型回复统一返回结构化字段 `{japanese_text, chinese_translation}`，不依赖按换行猜测。

## 产品边界

### 第一版包含

- 单个角色和单个本地用户。
- 日语/中文语音与文字输入，自动识别中日混说。
- 多家兼容模型 API。
- 本地聊天记录、长期记忆与关系状态。
- 主动消息与系统托盘。
- Live2D 桌宠窗口。
- 导入合法授权的角色包与语音包。
- 声音工坊用于制作可导入的语音包。

### 第一版不包含

- 任何形式的教学、纠错、复盘、进度统计、JLPT 分级。
- QQ、微信、Telegram、Discord 等渠道机器人。
- 多账号、多设备同步和云端服务。
- 插件市场、角色市场或社交功能。
- 多角色群聊和复杂 Agent 工作流。
- 在手机上训练语音模型。

## 技术结构

Tauri 2、React、TypeScript、Rust。桌面工程 `aika-crossplatform/` 是唯一主线；上级 Android 原生工程转为历史原型，只读归档，不再开发。

### 目录边界

- `domain/`：角色、关系、记忆、会话等稳定数据结构与纯逻辑。
- `services/chat/`：聊天模型协议适配。
- `services/voice/`：ASR、TTS、播放和打断接口。
- `services/memory/`：记忆抽取与会话摘要。
- `services/proactive/`：主动消息触发与频率控制。
- `services/storage/`：SQLite 与配置读写。
- `components/`：不包含业务协议的界面。
- `tools/voice-workshop/`：独立声音训练工具包。
- `tools/live2d-pipeline/`：自制角色素材管线，暂缓，见 M6。

主程序不能直接依赖某个 Whisper、TTS 或 Live2D 实现，只依赖接口和角色包清单。

### 从 Android 原型移植的逻辑

以下模块在 Android 工程中已实现，桌面版应直译而非重写：

| Android 源文件 | 移植目标 |
| --- | --- |
| `domain/CompanionEngine.kt` | `domain/companion.ts`（CompanionContext / CompanionReply） |
| `domain/CompanionPromptBuilder.kt` | `domain/prompt.ts` |
| `domain/ProactivePolicy.kt` | `domain/proactive.ts` |
| `domain/ProactivePolicyTest.kt` | `domain/proactive.test.ts` |
| `data/local/MemoryEntity.kt` | `domain/memory.ts` + SQLite schema |

移植时必须做的修改：

1. 删除 `CompanionPromptBuilder` 中的教学残留：「让用户在真实语境里接触日语」「如果用户明确询问日语表达，可以自然解释；否则不要主动纠错」整段移除。
2. 关系阶段判定改为多因子，不再只看 `totalMessageCount`。
3. 加入 code-switch 规则。
4. 原有的反模板句规则与 `proactiveInput` 中「不要索取回复，也不要制造负罪感」逐字保留。

桌面版现有的 `domain/persona.ts` 是 Android 版的退化版本，移植完成后删除。

## 里程碑

### M0 工程底座

- git 仓库初始化，`output/` 与 `node_modules/` 排除或走 LFS。
- 移植 Android domain 层，接上结构化双语输出解析。
- 归档 Android 工程，根 README 标注为历史原型。
- API Key 从 localStorage 迁移到 Stronghold 或 Windows DPAPI。

### M1 记忆与关系

- SQLite（`tauri-plugin-sql`）替代 localStorage。
- 每轮对话后异步抽取候选记忆，用户在记忆页确认或删除。
- 滚动会话摘要：近 N 轮保留原文，更早的压缩为摘要。
- 多因子关系状态。
- 验收：跨重启、跨会话，她能在自然时机提起两周前说过的事，且不炫耀自己记得。

### M2 主动性与托盘

- 移植 `ProactivePolicy` 及其测试用例。
- 多样化触发理由（未完话题、用户计划、时间语义、记忆日期）。
- 系统托盘常驻、本地通知、一键关闭主动消息。
- 验收：连续七天真实使用，没有出现一条让人想关掉它的消息。

M2 排在 M3 之前是刻意的：主动消息的策略逻辑已经写完，跑起来只需要几天，而「她是活的」这个感受比把语音延迟从三秒压到一秒更强。

### M3 语音回合

- 本地 Whisper + Silero VAD 替换 Web Speech。
- 尾静音 1.2～1.5 秒起调，配合语义完整性判断。
- 自动识别日语、中文和中日混说，取消手动语言切换按钮。
- 回复按句切分，第一句即开始合成播放。
- 播放期间保持监听，用户开口立即打断。
- 验收：含句中停顿、犹豫词、中日混说的 20 轮测试中，不因一次短停顿拆成两次模型请求。

### M4 存在感

- 导入合法授权的 Live2D 半身模型。**购买或授权，不自制。**
- 透明无边框置顶桌宠窗口。
- 眨眼、视线、待机呼吸。
- 音量驱动口型，情绪标签驱动表情与动作。
- 验收：挂在桌面角落工作两小时不觉得干扰。

### M5 自训声线

- 声音工坊完成数据检查、切分、转写、训练和试听。
- 主程序导入语音包，替换 TTS 适配器。
- 显存预算：RTX 5060 8 GB 上 Whisper + TTS + Live2D 同时运行需实测；超出则改为 TTS 常驻、Whisper 按需加载。

纯陪伴定位下声音身份重要——通用音色建立不了依恋——因此自训声线是终局形态，不是可选项。

### M6 自制角色（暂缓）

`tools/live2d-pipeline/` 的 4K 母稿、抠图、分层辅助遮罩与表情动作模板全部保留，但 `material-separation.psd` 与 Cubism 绑定推迟到产品验证之后。

理由：手工 PSD 拆分加遮挡补画加 Cubism 绑定，对单人是数周到数月的工作量且失败率高，不能挡在产品验证前面。

## 技术选型待定项

1. **语音链路**：先用 Realtime API 跑通体验再换本地管线，还是直接建本地管线。接口抽象已在 `services/voice/contracts.ts`，两条路可共存。倾向：Realtime 仅作早期验证，本地管线是终局。
2. **记忆抽取**：用主模型还是本地小模型。涉及成本与隐私。
3. **桌宠窗口**：与主窗口共用一个 WebView，还是两个独立 Tauri window。

## 完成标准

每个里程碑必须具备：自动测试、错误可见、配置可恢复、离线能力说明和可回退方案。任何新增模块不得绕过统一的角色、记忆、语音和存储接口。
