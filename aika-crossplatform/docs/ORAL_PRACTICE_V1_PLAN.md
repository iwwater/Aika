# Aika 自然口语陪练 V1 开发计划

日期：2026-09-05。

状态：仅完成计划，尚未开始实现。本轮只检查现有代码，未修改人设、提示词、界面或语音业务逻辑。

## 1. 当前目标

先做一版普通、自然、可日常使用的口语搭子，让用户愿意开口、能连续聊下去。论文研究作为独立后续支线，暂不把研究原型加入这一版。

根据现有项目的日语背景，V1 暂按「日语口语为主，中文帮助表达和理解，用户明确要求时可用英语」设计。这是规划假设；开始开发时若用户明确指定其他练习语言，以用户要求为准。

“真人感”的可验收含义：接住具体内容，有稳定偏好与适度不同意见，长短句有变化，不机械追问，允许自然停顿，记得相关话题。角色身份保持虚构，不通过假称现实经历或线下行动制造真实感。

## 2. V1 范围

### 必须有

- 普通温和的口语搭子人设：亲切、略俏皮，有观点；不预设恋爱关系。
- 日语为主的自然短对话：通常 1–3 句，用户明确要求解释时可更长。
- 根据用户实际表达调节用词和句子长度；说不出来时允许中文补充。
- 用户只想闲聊时顺着内容聊；用户指定咖啡店、点餐、面试等场景时直接进入，不先输出课程安排。
- 轻量纠正：先回应意思，只纠正明显影响理解或反复出现的问题，一轮最多一个点；能自然重述时不额外讲课。
- 用户说「先别纠正」「帮我改一下」「慢一点」「简单一点」时按要求调整，并在当前对话上下文内保持。
- 保留现有实时语音、字幕、停顿等待、打断及误识别清除功能，先验收其可用性。
- 模型、麦克风或识别服务不可用时，给出可理解的提示和文字聊天退路。

### 本版不做

- 病娇/三无人格切换、人格滑块、情绪状态机、论文评测框架。
- 等级测评、课程体系、打卡、每日任务、分数、自动课后报告。
- 发音评分、音素级纠正：当前聊天链路接收转写文字，不能据此判断用户真实发音。
- 自训练声线、情感 TTS、大型语音模型下载、Live2D 新素材。
- 新的学习档案数据库；短期纠正要求先由近期上下文承载，不承诺跨会话永久记住。

## 4. 对话行为设计

### 接话与推进

先接用户刚说的具体内容，再用自己的偏好、简短反应或具体问题推进。通常一轮最多一个问题，但不机械禁止相邻两轮提问；用户愿意展开时可以自然追问。不以固定的「真棒」「我理解你的感受」开头，不每轮重复用户原话。

用户回答简短时，不连续抛开放式问题；可以给一个小选择或一句自身偏好，降低接话难度。不会说某个词时，给一个能直接用的表达，再回到原话题。

### 轻量纠正

默认先保证交流流畅。区分真实用法问题、可接受的口语省略和可能的转写错误；不把所有不完整句子都改成教科书表达。

例子仅用于设计和人工验收，不要求模型逐字复现：

| 用户输入 | 期望方向 |
| --- | --- |
| 「昨日、友達と映画を見ます。」 | 自然重述为过去时，再接电影话题；不展开时态课程 |
| 「这个怎么用日语说，太挤了？」 | 给出简短日语表达，再回到原情境 |
| 「先别纠正，我想聊完。」 | 暂停主动纠正，持续接话 |
| 「嗯……让我想想。」 | 输入回合管理允许停顿；不靠模型提示词假装解决抢话 |
| 识别文字明显异常 | 简短确认意思，不根据不确定转写评判发音或能力 |
| 「刚才那句帮我改自然一点。」 | 给一个自然版本和必要的短解释，不自动生成多个练习题 |

重要情绪或生活话题优先回应内容，不在用户倾诉时纠正语法。用户主动要求详细讲解时允许暂时展开，但结束后能回到聊天。

### 语言与朗读

日语练习期间避免 Aika 无缘由整轮切成中文；必要解释可以简短用中文。用户明确说练英语或只用中文解释时应服从。中文翻译继续使用已有次级字幕，语音只念原话，避免自动把译文再读一遍。

“慢一点”不能只在提示词里承诺：若本版要提供稳定可控的慢速朗读，应在验收阶段决定是否加入最小语速控制；没有实际参数支持时，只能承诺缩短句子、分段说明，不能标为已实现慢速播放。

## 5. 实现顺序与阶段验收

### S0：确认运行基线（约半天）

- 检查当前应用启动、供应商配置路径、语音服务和现有测试。
- 记录实际可用的识别后端、系统音色、连续对话表现与已知问题。
- 先记录 3–5 段旧版本对话作对照，不清空已有历史或配置。

验收：能区分模型不可用、麦克风失败、识别失败与朗读问题；具备可用文字链路。没有实际语音条件时明确标记语音待验，不声称已完成端到端陪练。

### S1：普通搭子人设与回复规则（约 1 天）

- 调整 character 与 prompt，合并口语规则，移除冲突的旧规则及过时注释。
- 更新已有提示词测试中“不得出现纠错”等旧产品断言；测试用于验证拼接/契约，不宣称验证了自然感。
- 保持 JSON 字段、现有 mood、消息格式和存储兼容；不增加额外模型请求。

验收：文字样例覆盖闲聊、卡词、明确纠正、停止纠正、场景练习和情绪话题。回复短、能接话，既不默认撒娇恋爱，也不变成课堂。

### S2：入口与语音体验验收（约 1 天，按实际故障调整）

- 调整欢迎语、页面定位、少量开场建议和语音页说明，复用现有界面。
- 连续口语测试：犹豫停顿、接着补半句、清除误识别、用户打断、退出后再进入。
- 仅对复现的问题修改回合等待/朗读流程；不要为了“更自然”任意加随机延迟或抢话式语气词。
- 系统音色达不到预期时记录为独立后续改进，不悄悄引入新服务。

验收：实际浏览器/桌面端进入语音可用；无重复发送、重复朗读、退出后继续录音等问题；字幕与当前句对应。新增 UI 必须实际浏览器检查。

### S3：日常试用与交付（约半天至 1 天）

- 至少完成一段约 10 分钟的实际口语试用，记录卡住的位置而非只看截图。
- 对照 S0，人工检查接话、纠正频率、问题重复与语言切换。
- 运行适当的现有单测和构建；将验证结果、操作入口和已知限制写入交接文档。

验收：用户可以打开语音直接聊，偶尔得到有用表达帮助，正常聊天不会频繁被纠正打断；未通过的真机项明确列出。

整体预计约 3–4 个工作日，前提是现有供应商和语音链路可用。这里是任务量估计，不是交付时间承诺。

## 6. 验收清单

- [ ] 普通口语搭子人设，没有默认恋爱关系或强制教学流程。
- [ ] 练习期间以日语为主，中文支援不会吞掉整段练习。
- [ ] 正确表达不被无意义改写；有问题时一轮最多一个主动纠正点。
- [ ] 用户明确暂停纠正后，后续多轮遵守。
- [ ] 能顺着同一话题持续多轮；不反复问同一个问题或自动总结结束。
- [ ] 犹豫、停顿、打断、误识别清除和重新进入语音已实际验证。
- [ ] 不根据转写文字虚构发音评分。
- [ ] 没有重复朗读译文、重复提交、退出后继续监听等问题。
- [ ] 旧聊天、记忆、供应商配置保留可用。
- [ ] 测试与构建通过，真实语音待验项没有被写成完成。
