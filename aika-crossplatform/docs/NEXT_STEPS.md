## M7 手机端 ✅ 第一版已实现（2026-09-03），等你拿手机试

**一份数据 + 一个远程终端，不是同步。** 手机不存任何东西，也不直接连模型：
记忆只有电脑上那一份，Key 也只在电脑上。手机把「发一轮」交回电脑跑，跑完自己再拉一次。

### 你要做的

1. 电脑上打开设置 →「手机也能用」→ 点「开启手机访问」。
2. Windows 防火墙会弹一次，**放行私有网络**。
3. 把界面上那个地址发到手机上打开（点「复制地址」）。手机和电脑要在同一个 WiFi。

地址里带着访问口令，等于钥匙，只发给自己的手机。发错了人就点「换一把口令」，旧链接立刻失效。
出门用 Tailscale，**不要自己做公网穿透**——把她的记忆挂到公网上换来的方便不值得。

**服务不自动启动**，每次要用手动开一次：不想让一个监听端口在你不知情时一直开着。

### 已经做完的部分

- `src-tauri/src/remote.rs`：`tiny_http` 起的 HTTP 服务，每个路由都验 token
  （`Authorization: Bearer` 或 `?t=`），定长比较，不在第一个不同的字节上提前返回。
- `src-tauri/mobile/index.html`：手写的单文件页面，`include_str!` 进二进制。
  刻意不是桌面那套 React——手机只是一块屏幕，越简单越不容易在 iOS Safari 上出意外。
- **Rust 不碰业务。** 手机的每次请求转成事件送进桌面 WebView（`services/remote/bridge.ts`），
  桌面端跑完再交回去。提示词、模型调用、落库、记忆抽取都只有桌面那一份实现；
  在 Rust 里再写一遍就是两套会慢慢长歪的逻辑，而且 Key 也得离开 DPAPI 保险库。
- 局域网地址靠 UDP socket 选路拿到（std 没有枚举网卡的接口）。拿不到时界面会说手机可能连不上。

### 这一版还没有的

- **语音**：手机上只能打字。音频传回电脑用 Whisper 认，还没做。
- **表情包**：图片在桌面应用的包里，不在这个 HTTP 服务上，所以手机看不到。
- **主动消息推送**：Web Push 要 HTTPS 和 VAPID。手机开着时靠 3 秒轮询，关掉就静默。
- **电脑不开机手机就用不了。** 这是这条路的固有代价，没有绕开的办法。
- **端到端没在真机上验过。** 两侧都有单元测试，但「拿手机打开这个地址」得你来。

## 情绪（语气标签）✅ 已实现（2026-09-03）

**是她自己标的，不是我们事后猜的。** 拿一个分类器去猜她刚写完的那句话，
是在猜一个本来就有答案的东西，还要多一次请求的延迟和费用。

- `domain/mood.ts`：七个语气就是 `output/live2d/runtime-presets/expressions/` 的文件名，
  一个不多一个不少——M4 导入模型时标签直接对得上，不用再来一层映射表。
- schema 里 `mood` 是 enum 且**排在最前面**。流式时第一句可能在整段写完前就出声，
  语气排在后面等于拿不到；朗读参数必须在开口之前定下来。
- 认不出来一律 neutral：不支持结构化输出的协议会整个字段都没有，不能因此丢掉整轮回复。
- 流式解析只认**闭合了的** mood 字符串，否则会先 neutral 再跳到 happy。
- 落库加了 `messages.mood` 一列，M4 之后历史消息也能驱动表情。

### 现在只有一个消费者，说清楚

| 消费者 | 状态 |
| --- | --- |
| Web Speech 的 rate / pitch | **已接**（原来写死的 1.03 / 1.08 现在是 neutral 的取值） |
| Live2D 表情与动作 | M4，等模型来源 |
| 自训声线的 style（`voice.json` 的 `styles` 已经留好） | M5 |
| 表情包 | 没有互相驱动：表情包由她按清单自己挑，语气不去覆盖它 |

**调幅刻意很小。** Web Speech 的 rate/pitch 是很粗的旋钮，调大了不像情绪、像换了个人，
而「换语言不能换成另一个人」这条约束在这里同样成立。真正的情绪表达要等 M5。
所以：**现在加是为了铺路，不要指望今天就听得出来。**

### 用户那一侧刻意不做

不给用户的情绪打标签。猜错的代价在这个产品里特别高——「你今天是不是不开心」猜错既是
人机味又是冒犯，而且天然往索取和负罪感那边滑，正是设计红线要挡的东西。
模型本来就在读用户的原话，加一个 `user_mood` 标签不会让它更懂，只会让它更容易表演懂。

声学情绪（从语音里听）同样不做：8 GB 卡上要和 whisper.cpp 抢显存，真实场景的准确率
撑不起「因为听出你不开心所以换个说法」这种依赖。真要韵律信号，VAD 已经免费给了
「说了多久、停了几次」，比七分类可靠得多。

## 表情包 ✅ 机制完成（2026-09-03），等你把素材放进目录

「她会问的问题」的第二层。第一层是问句本身（已改），第二层是她只有文字这一种表达方式——
真人聊天里有大量只发一个表情、不需要回应的回合，那是存在感，不是信息。

### 你要做的三件事

1. 把图片丢进 `aika-crossplatform/public/stickers/`（png / gif / webp / jpg）。
2. 跑 `npm run stickers:scan`——它把还没登记的图片补进 `manifest.json`，`when` 留空。
3. **给每张写一句「什么时候该用它」**（`when` 字段）。这一句是脚本猜不出来的，
   而且 **`when` 空着的条目不会进提示词**：她看不见，也就选不到。

格式和限制见 `public/stickers/README.md`。图片走 ignore 不进仓库，清单进。

### 已经做完的部分

- `domain/stickers.ts`：清单解析、id 校验、提示词规则。**清单为空时整套机制隐身**——
  提示词里一个字都不提，结构化输出也不多这个字段，行为和没有这个功能完全一样。
- `companionReplySchema(stickerIds)`：有清单时 `sticker` 是 enum，枚举里带一个空串表示不发。
  strict 模式下每个属性都必须列进 `required`，所以「可选」只能靠空串表达，不能靠省略字段。
  OpenAI 协议下她因此编不出清单外的名字；其余协议靠提示词，编出来的由 `resolveSticker` 挡掉。
- 提示词写明「大多数时候不发」：每句话都配一张图不是熟人，是营销号。
- 落库加了 `messages.sticker` 一列。SQLite 的 `ALTER TABLE` 没有 `IF NOT EXISTS`，
  所以迁移逐条 try——老库加成功、新库报重复列，都是正常路径。
- 图片文件后来被删掉时静默隐藏，历史消息不会变成一个碎图标。

### 诚实的边界

**「人机味变没变」这条验不了，得等素材。** 机制有单元测试，但它只保证「她挑得出、
挑错了不显示、没有清单时完全隐身」，不保证她挑得对。挑得准不准取决于你写的那句使用场景。

## M3 本地识别 ✅ 代码完成（2026-09-03），等你把服务跑起来

链路：麦克风 → Silero VAD → whisper.cpp。实现的是和 Web Speech 同一个
`SpeechInputEngine` 契约，所以回合边界、缓冲区、打断这些上层逻辑一行没改。

### 你要做的三件事

**1. 拿 whisper.cpp 的预编译包**

这台机器没有 cmake 也没有 CUDA toolkit，所以不自己编译，直接用官方发布的二进制：
<https://github.com/ggml-org/whisper.cpp/releases>，挑 Windows x64 带 cuBLAS 的那个
（RTX 5060 + 驱动 581.80 能直接用，不需要装 CUDA toolkit）。

**2. 下一个多语模型**

必须是 multilingual，**不能挑 `.en` 结尾的**——那些只认英语。
<https://huggingface.co/ggerganov/whisper.cpp/tree/main>

| 模型 | 大小 | 说明 |
| --- | --- | --- |
| `ggml-small.bin` | 466 MB | 建议从这个起步，日语够用，8 GB 显存很宽裕 |
| `ggml-medium.bin` | 1.5 GB | 日语明显更好，显存还是够，延迟高一些 |
| `ggml-large-v3-turbo.bin` | 1.6 GB | 质量接近 large 而快得多，值得试 |

**3. 起服务**

```powershell
.\whisper-server.exe -m ggml-small.bin --port 8080 --host 127.0.0.1
```

然后在应用的设置页「语音识别」一节点「检测本地服务」。显示在线就行了，
进语音页会自动走本地链路。链路选「自动」时服务没开会退回系统识别，
并且**会在语音页上明确写出来**——不会让你以为混说已经修好了。

### 已经做完的部分

- `domain/audio.ts`：环形缓冲、重采样、WAV 封装。环形缓冲是**回补**的基础——
  VAD 判定开口时那个音节已经过去了，段首往前多取 220 毫秒，第一个字才不会丢。
  这是 Web Speech 结构上做不到的事，它不把音频交给我们。
- `domain/vadSegmenter.ts`：概率 → 语音段。带回滞区（0.5 进 / 0.35 出），
  否则概率在阈值附近抖动会把一句话切成碎片；句中换气不切段；一直说不停时按上限切开。
  纯逻辑，喂一串概率就能测，13 条测试。
- `services/voice/audioCapture.ts`：AudioWorklet 直接要 16 kHz，让浏览器自己重采样。
- `services/voice/sileroVad.ts`：输入输出名字运行时从 session 读，v4 / v5 都认。
  onnxruntime 走**动态 import**，退回 Web Speech 的用户不用为十几兆 wasm 等启动。
- `services/voice/whisperClient.ts`：`POST /inference`，multipart 自己拼字节
  （FormData 过 Tauri IPC 行为不好保证，自己拼是确定的、能测的）。
  **挡幻听**：whisper 对纯静音会稳定吐「ご視聴ありがとうございました」，
  按整段完全匹配过滤，不做包含匹配——用户真说了这句话时不能吞掉。
- `services/voice/inputEngine.ts`：链路选择。**退回必须看得见**，
  用户点名要本地却连不上时宁可报错，也不悄悄降级。
- 设置页新增「语音识别」一节：链路选择、服务地址、连通性检测。

### 顺带修的

- `speechQueue` 打断之后不再收句子。流式回调比打断晚一步到时，她会在被打断后接着念。
- `webSpeechOutput` 原来按第一个换行截断朗读文本，多行回复会被悄悄念掉一半。
- onnxruntime 默认把 27 MB 的 WebGPU wasm 内联进 bundle。改用
  `onnxruntime-web/wasm` + `onnxruntime-web-use-extern-wasm` 这个 resolve 条件，
  wasm 走 `public/ort/`（由 `npm run sync:ort` 从 node_modules 生成，不进仓库）。

### 诚实的边界

**Whisper 的语言检测是整段的。** 一句话里中英混说时它多半会统一按主语言转写。
比 Web Speech「一次只能给一个语言码」强得多，但**不是完美的混说识别**。
真机要实测到什么程度还认得准。

## M3 回合边界 ✅ 已实现，待真机验收（2026-09-03）

M3 拆成了两半：**回合怎么走**和**识别用什么引擎**互不依赖，先做了前者——
换 Whisper 之后这套逻辑一行不用改，而 P0 的抢话今天就能停。

- `domain/turnEnd.ts`：识别结果先攒进缓冲区，尾静音够长、且这段话语义上像收尾了才提交。
  基准 1.35 秒；句末标点或终助词收尾缩到 1.15 秒；填充词、连接词、读点收尾拉到 2.4 秒；
  兜底 4 秒一律提交。**纯判断，不持有计时器**——所以「20 轮不因一次停顿拆成两次请求」
  是单元测试，不用真等 1.35 秒。
- 缓冲区在字幕区可见，配「现在就发」和「听错了，清掉」。停顿不再等于提交，
  误判也不必被迫发出去。
- `domain/sentences.ts` + `services/voice/speechQueue.ts`：回复按句切分，第一句先出声，
  **逐句判断朗读音色**。她一句日语一句中文时，整段用一个音色念就换了个人。
- `services/voice/micActivity.ts`：播放期间保持监听，用户开口立刻停播交回这一轮。
  getUserMedia 打开 echoCancellation 挡回声，否则她会被自己的声音打断。
- 顺手修掉的：`webSpeechOutput` 原来按第一个换行截断朗读文本，多行回复会被悄悄念掉一半。

真机要验的三件事见 DEVELOPMENT_PLAN 的「需要真机验证的」。

## M3 流式输出 ✅ 已实现（2026-09-03）

## M3 逐句字幕高亮 ✅ 已实现（2026-09-03）

字幕本来就逐句长出来了，但整条一起亮着，看不出她读到哪儿。
`domain/captionHighlight.ts` 把正在念的那一句定位回字幕原文：送去合成的句子被
`sentences.ts` 清洗过（去 Markdown 记号、裁空白、并短句时补空格），直接 indexOf 找不到，
所以两边都按「忽略空白与 Markdown 记号」归一化后再找，再把下标映射回原文。
**找不到就不亮**——亮错位置比不亮更糟。搜索起点只往前走，一段回复里出现两句
一模一样的话时，第二句不会亮回第一处。

FIELD_TEST_NOTES 修复顺序第 4 条至此只剩 Live2D 口型，等 M4。
