# Aika 情感与人格研究路线

日期：2026-09-05。状态：研究建议，未修改运行时代码，未运行在线模型评测。

## 目标与研究问题

目标是可观察、可控制的角色行为：理解用户情境、保持人格、合理地改变情绪，并让台词与表现一致。本路线不把生成的自述或内部数值当作主观情感体验的证据。

核心问题：相对于当前单轮 mood 提示词，显式用户状态、人格配置和跨轮角色状态是否改善中日混合陪伴对话？改善是否值得额外的首句延迟与成本？

## 当前代码依据

- src/domain/character.ts：基础身份与固定 systemPrompt。
- src/domain/prompt.ts：身份、历史、记忆、关系与通用表达规则拼接；没有独立用户情绪契约。
- src/domain/companion.ts：回复包含 mood 和双语文本；mood 是角色表达。
- src/domain/mood.ts：七个表现标签及 Web Speech rate/pitch 映射；不能充当完整人格或用户状态。
- src/domain/streamingReply.ts：流式解析，当前缺失/未完整的 mood 回退 neutral。
- src/hooks/useCompanionSession.ts：聊天请求、消息保存和后台记忆任务。
- src/domain/relationship.ts：以相识时间、连续互动天数、消息数计算熟悉阶段；代码明确不因离线时间降低关系。
- src/hooks/useVoiceConversation.ts：流式正文按句朗读。
- src/services/voice/contracts.ts：输入上交转写文字，输出接口只有文本、语言、rate、pitch。

## 按顺序阅读

1. EmoBench，ACL 2024：https://aclanthology.org/2024.acl-long.326/
   - 分开评估 Emotional Understanding 和 Emotional Application；包含中英文题目。
   - 项目用途：借鉴情境题与评估拆分，不直接把选择题分数等同陪伴质量。
2. PersonaLLM，NAACL Findings 2024：https://aclanthology.org/2024.findings-naacl.229/
   - 通过 Big Five 设定角色，并用问卷、生成任务与人工评价检查人格表达。
   - 项目用途：人格应有行为指标；病娇、三无是创作预设，不能宣称与心理量表一一对应。
3. A psychometric framework for evaluating and shaping personality traits in large language models，2025：https://www.nature.com/articles/s42256-025-01115-6
   - 研究人格模拟的测量可靠性、效度与提示塑形。
   - 项目用途：问卷之外仍需真实对话盲评，检查跨语言、跨轮稳定性。
4. An Appraisal Theoretic Approach to Modelling Affect Flow in Conversation Corpora，CoNLL 2025：https://aclanthology.org/2025.conll-1.16/
   - 用评价维度研究对话中的情感变化。
   - 项目用途：事件、相关性和可控性比孤立的情绪标签更便于解释变化；无需照搬论文全部 21 个维度。
5. From Triggers to Emotions，2026-07 arXiv 预印本：https://arxiv.org/abs/2607.07824
   - 提出基于 CPM 的触发提取、评价和角色情绪状态更新框架。
   - 项目用途：借鉴模块分工，先实验单请求版本；该预印本不能证明多代理在 Aika 中一定更好。
6. LoCoMo，ACL 2024：https://aclanthology.org/2024.acl-long.747/
   - 评估长时间跨度的对话记忆，包括问答、事件摘要等任务。
   - 项目用途：测量跨会话事实、时间与事件状态，另行设计情绪连续性测试。
7. MELD，ACL 2019：https://aclanthology.org/P19-1050/
   - 包含文本、音频、视频的对话情绪数据。
   - 项目用途：后续音频实验的参考；英语电视剧数据不能直接代表中日混合私人聊天。

## 建议架构（工程假设，需实验验证）

分开五种信息：

1. 用户状态：有证据支持的情绪候选、针对对象、诉求与不确定性；证据使用消息 ID 和短原文片段。
2. 人格：稳定的表达习惯、主动性、情绪外露、依恋表达及对话示例。
3. 角色短期状态：Aika 当前情绪、强度、触发来源和更新时间。
4. 关系及事件记忆：熟悉阶段与具体互动事实；暂时生气不能直接修改长期关系。
5. 表现：现有 mood、台词，后续的语音风格与 Live2D 表情。

同一输入和用户状态下，不同性格可产生不同表达。三无低外露不等于不能理解情绪；病娇风格的吃醋不等于用户真的背叛。用户未出现不能被自动解释为拒绝。

第一版人格使用自然语言规则和少量示例。数值化维度如外露程度仅是工程控制量，只有验证单调可控后才考虑暴露滑块。

角色状态只在有关事件出现时变化；明确道歉、解释等可以引发较快变化。时间平滑只能是辅助，避免一律渐变导致该释怀时无法释怀。短期状态可回落，沿用现有长期关系不因离线下降的设计。

## 分阶段实现

### A：评测基线与人格（先实施）

- 保留现有实现为 A0。
- 新增人格预设文件，通过 buildInstructions 注入，保留通用约束，移动冲突的表达规则到预设中。
- 新增 user_state 和 response_intent，明确 unknown，不把模型自报 certainty 当成校准概率。
- 同步修改 schema、完整解析、流式解析和解析测试；旧回复仍可读取。
- 同一请求输出紧凑元数据与正文。只要求短结构化判断，不要求长篇思维过程。
- 保持线上默认版本可切回；先在评测入口对比。

### B：跨轮情绪状态（A 有效后）

- 新增角色状态类型及独立更新函数；人格保持稳定。
- 给模型上一轮状态与相关事件，让其提出本轮候选状态和表达意图。
- 单请求方案只能由本地代码做范围、来源和契约校验；若语义修改了候选状态，已生成文本未必匹配，不能假装严格同步。
- 如需要本地规则先决定本轮状态，再由模型按状态生成正文，单独评测两阶段请求，并记录额外延迟。
- 仅完整有效回复提交持久状态；失败、取消及过时请求不更新。流式表现可暂用本轮候选，但不得提前污染下一轮。
- 重试按轮次去重，防止同一事件重复加深情绪。

### C：事件记忆与输出（B 有效后）

- 扩展现有记忆链路为有来源、有时间的事件，如争执、解释、修复，不保存无依据的用户人格判断。
- 区分事实、用户明确自述和模型猜测；一次心情不成为永久偏好。
- 检索与当前输入相关事件，避免每轮复述全部历史。
- mood 保留为表现层；确需新表情时扩展素材和映射，不能让三无预设破坏现有标签兼容。
- 情感 TTS 与音频识别单独做增量实验；检测与声音表现分别评分。

### D：训练或复杂架构（有数据后）

- 当提示词版本稳定、人工偏好数据足够且错误集中在表达时，才考虑 SFT/偏好训练。
- 事实检索错误修记忆；状态重复提交修代码；不能统一交给微调。
- 多代理作为实验变量，不作为默认前提。

## 实验设计

先做探索性小样本，建议 30 个多轮场景 × 3 种性格 × 每条件 3 次生成；此规模用于发现失败模式，不保证统计显著。

场景包括：反讽、引用别人情绪、工作烦躁、明确求建议、只想倾诉、被夸、短暂离开、对 Aika 不满、道歉修复、中日混说、转写噪声。另做若干跨会话及较长对话测试，检查第 20/50 轮人格与记忆。

对照：A0 当前版本；A1 只加人格；A2 加用户状态与回应意图；A3 再加角色状态；A4 再加事件记忆。逐项增量，固定模型版本及生成设置，不同时换模型。

先固定对话历史做成对比较，再做自由延展测试。按完整场景拆开发/保留集，近似改写不要跨集合。开发集可用于提示示例，保留集不得用于调参。

评价：

- 用户理解：情绪对象/诉求是否正确；模糊输入是否承认不确定；用允许答案集合，避免强迫唯一情绪。
- 人格：盲评能否区分预设，且不依赖重复口头禅；三种性格都要检查回应是否适切。
- 连续性：变化是否有触发，解释/道歉后是否能更新，是否出现无缘由跳变。
- 记忆：依据是否存在，事实与时间是否正确，冲突是否已经解决。
- 表现：mood 是否符合台词，语音与表情是否匹配。
- 工程：schema 失败率、状态提交正确性、首个可播放句子延迟、每轮 token 与成本。

优先随机顺序的人工成对盲评，可用另一个模型辅助筛查。模型裁判需抽样核对，不能由被测模型自评分代替独立评价。多人标注记录分歧；一人评价则报告为个人偏好实验。

每篇论文记录：研究问题、状态表示、输入输出、公开代码数据、对照与消融、适用语言、迁移限制。每轮实验记录模型版本、提示版本、场景 ID、输出、评分与首句延迟。选择是否进入下一阶段以保留场景中的收益与代价为依据，不预先承诺准确率。

## 期刊选题收敛（2026-09-05 补充）

建议题目：面向人格化对话代理的证据驱动情绪修正：事件记忆、状态控制与多轮评估。

主问题：当情绪的事实依据被澄清、否定或更新时，显式事件关联状态能否比充分历史和结构化记忆更可靠地修正角色回应，同时保留人格？这是待验证选题，不宣称已证明首创。

新增相近工作：

- Beyond Static Persona Consistency: Dynamic Persona Coherence in LLM Role-Playing，ACL 2026：https://aclanthology.org/2026.acl-long.1336/ 。已研究稳定身份与动态心理层的分离，不能把分层本身作为新贡献。
- Controlling Long-Horizon Behavior in Language Model Agents with Explicit State Dynamics，2026 预印本：https://arxiv.org/abs/2601.16087 。已研究外部 VAD 状态、平滑和惯性，简单增加衰减公式不是充分创新。
- ZifaMem，2026-07 预印本：https://arxiv.org/abs/2607.17564 。摘要报告结构化记忆有收益，而额外情绪状态机在其五项指标上无可测增益；仅为该实验范围的发现，不等同所有状态机无效。必须纳入记忆强基线。

最小实验原型：

1. 在独立评测入口复用 providerClient，不改变默认聊天行为。
2. 事件记录包含 event_id、source_message_ids、interpretation、status(active/superseded/resolved)、superseded_by。事实与解释分开；新输入不自动具有更高可信度。
3. 状态更新依赖事件：同一澄清重复出现不重复更新；修正一个事件不清空其他事件产生的状态。先用结构化候选判断与确定性事件更新规则，避免声称仅靠 schema 保证语义正确。
4. 研究阶段可用“事件解析与状态更新→正文生成”两阶段便于检查。基线应包含等调用数的反思版本，控制 token 与模型预算；在线单请求优化是后续工程工作。
5. 完整回复成功后原子地提交消息及候选状态；失败、取消、过时回复不提交。

配对场景：共享误会前缀，分别接入明确事实纠正、只有安慰但无新证据、与事件无关的新话题、相互冲突且不充分的信息。另加入部分纠正、重复纠正和后续旧事重提。若是人际伤害后的道歉，允许残余情绪；不要把立即原谅设为唯一金标准。

候选指标：生成回复继续引用失效依据的比例（建议主指标）；有效修正后的错误持续轮数；无关输入导致不当状态重置的比例；人格盲评与回应适切性；首句延迟和成本。内部状态日志只用于定位错误，不能单独证明生成回复改善。

基线至少包括同一模型的静态人格＋充分原始历史、结构化记忆、平滑状态、近期相关方法的可复现实现，以及预算相近的自我反思方法。复现不足须明确标为简化基线。消融事件来源关联、失效机制和人格条件；不能仅比较自身逐步加模块的版本。

先以 20–30 个人工审阅的场景族试验，随后按先导效应与预算确定正式规模。建议覆盖至少三个可负担的模型骨干；以场景族而非单条生成输出作为独立抽样/划分单位，防止伪重复。报告置信区间，保留未参与调参的场景族。人工评分说明规则并检查一致性。三无/病娇用于产品示例，正式评测应覆盖多个独立角色和明确的行为维度。

期刊定位：若贡献是通用情感建模方法与严谨实验，IEEE Transactions on Affective Computing 的主题范围匹配，参见官方范围：https://www.computer.org/digital-library/journals/ta/tac-general-call-for-papers 。主题匹配不是录用或分区承诺。若转为用户体验研究，应重新按研究设计选择 HCI 期刊，并在招募前完成适用的伦理审查及知情同意安排。论文主张限于行为可控性与一致性。
