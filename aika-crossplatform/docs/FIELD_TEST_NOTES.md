# 实机测试记录

## 2026-08-31 — 实时语音第一轮反馈

### P0：用户发言会被过早截断 —— 已实现修复（2026-09-03），待真机验收

现象：用户在一句话中正常停顿、犹豫或换气时，当前 Web Speech 可能直接结束识别并发送，造成“愛花抢话”的感觉。

修法：把“识别出一段文字”和“这一轮说完了”拆成两件事。识别结果先攒进缓冲区
（`domain/turnEnd.ts`），尾静音够长、且这段话语义上像收尾了，才真的发给模型。
基准 1.35 秒；句末标点或终助词收尾时缩到 1.15 秒；填充词、连接词、读点收尾时拉到
2.4 秒；兜底 4 秒一律提交。缓冲区在字幕区可见，配“现在就发”和“听错了，清掉”。

判定是纯函数，不持有计时器，下面那条 20 轮验收已经写成单元测试
（`domain/turnEnd.test.ts`）。真机还要看 1.35 秒的基准在实际语速下嫌长还是嫌短。

目标行为：

- 短暂停顿不能立即提交，继续说话时应合并到同一轮。
- 界面先保留临时字幕，确认用户结束后才形成最终字幕并请求模型。
- 用户可以取消误判的提交，也可以用明确按钮立即发送。
- 后续本地 VAD 应提供可调的结束静音时间，默认先采用偏自然对话的 1.2～1.5 秒，再根据实测调整。

验收：包含句中停顿、犹豫词、中文与日语混说的 20 轮测试中，不得因为一次短停顿拆成两次模型请求。

### P0：输入语言不应由用户手动切换 —— 本地识别已接通（2026-09-03），待接服务端验收

语言按钮已经删掉，支持的语言也从中日两种扩到**中文、日语、英语**三种。
当前折中：识别语言跟着用户最近实际说的语言走（`domain/language.ts`），
默认日语，用户不需要点任何东西。
**但 Web Speech 一次只能给一个语言码，一句话里的混说仍然识别不准。**

2026-09-03：本地识别链路已经接通（麦克风 → Silero VAD → whisper.cpp），
送给 Whisper 的 language 固定是 auto，用户不需要在说话前声明语言。
代码这一侧完成并有测试，缺的是把 whisper-server 跑起来，见 NEXT_STEPS。

**仍然要诚实：Whisper 的语言检测是整段的**，一句话里中英混说时它多半会统一按主语言
转写。比「一次只能给一个语言码」强得多，但不等于完美的混说识别。

正式模式应是单一的“自动识别”模式：

- 用户说日语、中文、英语或混合内容，系统都应自动识别并理解完整语义。
- 不能要求用户在每句话前切换识别语言。
- 用户说中文时，中文是输入意图；愛花按自己的语感回答，可能是日语、中文或混着说
  （见 DEVELOPMENT_PLAN 的语言设计：她不分两种语言模式）。
- 语言选择可以保留为识别纠错设置，但不能作为日常对话的必需步骤。

### P1：回复字幕需要日中对照

实时语音界面应采用固定的双语字幕结构：

```text
愛花
今日は何をしてたの？
今天做了什么？
```

- 日语原文是主要字幕，也是语音合成的文本。
- 中文翻译紧跟在日语下面，视觉上弱一级。
- 翻译不能依靠“按换行猜测”，模型回复应返回明确的 `spokenJapanese` 与 `chineseTranslation` 字段。
- 用户字幕显示实际识别内容；如用户说中文，不需要伪装成日语识别结果。
